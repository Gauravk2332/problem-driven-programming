Start with a problem

A teacher has the marks 12, 7, 19, 4, 19, 8 and wants the highest. You can see one mark at a time. Before reading on, decide what you would keep in your head as you go.

Think first

Describe your method in one sentence. Would a friend following your sentence always get the right answer?

One precise method
Remember only the largest mark seen so far. Start with the first mark; for each later mark, replace the remembered value if the new mark is larger. After the last mark, the remembered value is the answer: 19.

That sentence is already an algorithm. Compare it with a recipe instruction such as “cook until ready”: a person can follow it, but two people may stop at different times. An algorithm must be precise enough that anyone, or any machine, following it gets the same result and finishes.

Chapter 02 / 13

What an algorithm is

An algorithm is a finite sequence of well-defined steps that takes zero or more inputs and produces the required output, finishing after a finite number of steps for every valid input.

CharacteristicMeaningIn the maximum algorithm
InputZero or more quantities supplied from outsideThe list of marks
OutputAt least one result, related to the input as specifiedThe largest mark
DefinitenessEach step is precise and unambiguous“If A[i] > best, set best = A[i]”
FinitenessStops after finitely many steps for every valid inputOne pass, n − 1 comparisons
EffectivenessEach step is basic enough to be carried out exactlyComparison and assignment

An algorithm is not a program. A program is an implementation of an algorithm in a particular language for a particular machine. The same algorithm can be written in C++, Java or Python, and it can be described without any programming language at all.

Chapter 03 / 13

Specifying the problem precisely

Before designing an algorithm, write down exactly what it must do. A specification has two parts:

  • Precondition: what is guaranteed about the input. A is a non-empty array of integers.
  • Postcondition: what must be true of the output. The result equals some A[i] and is ≥ every A[j].

An algorithm is correct if, for every input satisfying the precondition, it terminates and the output satisfies the postcondition. Inputs outside the precondition (here, an empty array) are not the algorithm’s responsibility, but the program should still handle them deliberately.

Algorithms can be described in several ways:

FormStrengthWeakness
Natural languageEasy to readEasily ambiguous
PseudocodePrecise, language-independentNot executable

Program codeExecutable and testableTied to one language’s details

    if A[i] > best then best ← A[i]

Chapter 05 / 13

Proving it correct: the loop invariant

Testing shows the algorithm works on the inputs we tried. A proof shows it works on every valid input. For loops, the standard tool is a loop invariant: a statement that is true before every iteration.

Invariant: at the start of the iteration with index i, best = max(A[0..i−1])

  1. Initialisation. Before the first iteration i = 1 and best = A[0] = max(A[0..0]). True.
  2. Maintenance. Suppose best = max(A[0..i−1]). If A[i] > best the algorithm sets best = A[i]; otherwise best stays. Either way best = max(A[0..i]), which is the invariant for i + 1.
  3. Termination. The loop ends with i = n, so best = max(A[0..n−1]): the postcondition. The loop runs exactly n − 1 times, so it terminates.

Chapter 06 / 13

Testing, edge cases and why proof matters

The buggy version (start at 0) passes every test with at least one non-negative value. It fails only when all values are negative. This is why a proof is stronger than tests: tests sample inputs, a proof covers all of them.

Good tests still matter, especially at the boundaries of the precondition:

Chapter 07 / 13

Different algorithms for the same problem

Problems usually have more than one correct algorithm, and they can differ hugely in cost. To add 1 + 2 + … + n you can loop n times, or use the formula n(n + 1)/2 with three operations. Both give 5050 for n = 100; for n = 109 one is instant and the other takes a noticeable time.

ProblemAlgorithm AAlgorithm B
Sum 1..nLoop: n additionsFormula n(n+1)/2: constant work
Is key in an unsorted list?Linear search: up to n comparisons—
Is key in a sorted list?Linear search: up to nBinary search: about log₂ n (Lecture 5)

We judge algorithms by correctness first, then efficiency (time and memory, Lectures 2–4), and also by simplicity and generality. Measuring efficiency independently of the machine is the subject of the next lecture.

Chapter 08 / 13

Algorithm design paradigms

A design paradigm is a general strategy that solves many different problems. This course is organised around them:

ParadigmIdeaExample in this course
Brute forceTry every candidateChecking all coin combinations; trial division (Lecture 6)
Divide and conquerSplit into independent subproblems, solve, combineMerge sort, binary search (Lecture 5)
GreedyMake the best-looking choice and never undo itActivity selection (Lectures 12–18)
Dynamic programmingSolve overlapping subproblems once and store themKnapsack, LIS, edit distance (Lectures 19–27)
BacktrackingBuild candidates step by step, abandon dead endsGenerating balanced brackets (Lecture 9)
Transform and conquerChange representation firstHashing (Lectures 10–11), sorting first

Recognising which paradigm fits a problem is a skill you will practise all semester. Lecture 5 compares divide and conquer, greedy and DP side by side.

Chapter 09 / 13

From pseudocode to code

The program implements Max with its comparison count, the buggy version, linear search and both ways of summing 1..n. Notice how the precondition (non-empty array) appears as a comment, and how the invariant is recorded next to the loop.

Python · algo_basics.py

"""Lecture 1: an algorithm as a precise, terminating procedure."""


def find_max(a):
    """Precondition: a is non-empty. Returns (largest value, comparisons made)."""
    best, comparisons = a[0], 0
    for i in range(1, len(a)):
        comparisons += 1          # invariant: best = max(a[0..i-1])
        if a[i] > best:
            best = a[i]
    return best, comparisons


def buggy_max(a):
    best = 0                      # wrong: assumes some value is >= 0
    for x in a:
        if x > best:
            best = x
    return best


def linear_search(a, key):
    for i, x in enumerate(a):
        if x == key:
            return i
    return -1


def sum_loop(n):
    total = 0
    for i in range(1, n + 1):
        total += i
    return total


def sum_formula(n):
    return n * (n + 1) // 2


marks = [12, 7, 19, 4, 19, 8]
best, comps = find_max(marks)
print("marks =", marks)
print(f"max = {best} after {comps} comparisons")
print("search 4  ->", linear_search(marks, 4))
print("search 10 ->", linear_search(marks, 10))
neg = [-5, -2, -9]
print(f"all-negative {neg}: correct max = {find_max(neg)[0]}, buggy max = {buggy_max(neg)}")
print(f"sum 1..100: loop = {sum_loop(100)}, formula = {sum_formula(100)}")

C++ · algo_basics.cpp

// Lecture 1: an algorithm as a precise, terminating procedure.
#include <iostream>
#include <string>
#include <utility>
#include <vector>
using namespace std;

string show(const vector<int>& a) {
    string s = "[";
    for (size_t i = 0; i < a.size(); i++) s += (i ? ", " : "") + to_string(a[i]);
    return s + "]";
}

// Precondition: a is non-empty. Returns {largest value, comparisons made}.
pair<int, int> findMax(const vector<int>& a) {
    int best = a[0], comparisons = 0;
    for (size_t i = 1; i < a.size(); i++) {
        comparisons++;                    // invariant: best = max(a[0..i-1])
        if (a[i] > best) best = a[i];
    }
    return {best, comparisons};
}

int buggyMax(const vector<int>& a) {
    int best = 0;                         // wrong: assumes some value is >= 0
    for (int x : a) if (x > best) best = x;
    return best;
}

int linearSearch(const vector<int>& a, int key) {
    for (size_t i = 0; i < a.size(); i++) if (a[i] == key) return (int)i;
    return -1;
}

long long sumLoop(int n) { long long t = 0; for (int i = 1; i <= n; i++) t += i; return t; }
long long sumFormula(long long n) { return n * (n + 1) / 2; }

int main() {
    vector<int> marks = {12, 7, 19, 4, 19, 8};
    auto [best, comps] = findMax(marks);
    cout << "marks = " << show(marks) << "\n";
    cout << "max = " << best << " after " << comps << " comparisons\n";
    cout << "search 4  -> " << linearSearch(marks, 4) << "\n";
    cout << "search 10 -> " << linearSearch(marks, 10) << "\n";
    vector<int> neg = {-5, -2, -9};
    cout << "all-negative " << show(neg) << ": correct max = " << findMax(neg).first << ", buggy max = " << buggyMax(neg) << "\n";
    cout << "sum 1..100: loop = " << sumLoop(100) << ", formula = " << sumFormula(100) << "\n";
}

Java · AlgoBasics.java

// Lecture 1: an algorithm as a precise, terminating procedure.
import java.util.Arrays;

public class AlgoBasics {
    // Precondition: a is non-empty. Returns {largest value, comparisons made}.
    static int[] findMax(int[] a) {
        int best = a[0], comparisons = 0;
        for (int i = 1; i < a.length; i++) {
            comparisons++;                    // invariant: best = max(a[0..i-1])
            if (a[i] > best) best = a[i];
        }
        return new int[]{best, comparisons};
    }

    static int buggyMax(int[] a) {
        int best = 0;                         // wrong: assumes some value is >= 0
        for (int x : a) if (x > best) best = x;
        return best;
    }

    static int linearSearch(int[] a, int key) {
        for (int i = 0; i < a.length; i++) if (a[i] == key) return i;
        return -1;
    }

    static long sumLoop(int n) { long t = 0; for (int i = 1; i <= n; i++) t += i; return t; }
    static long sumFormula(long n) { return n * (n + 1) / 2; }

    public static void main(String[] args) {
        int[] marks = {12, 7, 19, 4, 19, 8};
        int[] r = findMax(marks);
        System.out.println("marks = " + Arrays.toString(marks));
        System.out.println("max = " + r[0] + " after " + r[1] + " comparisons");
        System.out.println("search 4  -> " + linearSearch(marks, 4));
        System.out.println("search 10 -> " + linearSearch(marks, 10));
        int[] neg = {-5, -2, -9};
        System.out.println("all-negative " + Arrays.toString(neg) + ": correct max = " + findMax(neg)[0] + ", buggy max = " + buggyMax(neg));
        System.out.println("sum 1..100: loop = " + sumLoop(100) + ", formula = " + sumFormula(100));
    }
}

Output (identical in all three languages):

marks = [12, 7, 19, 4, 19, 8]
max = 19 after 5 comparisons
search 4  -> 3
search 10 -> -1
all-negative [-5, -2, -9]: correct max = -2, buggy max = 0
sum 1..100: loop = 5050, formula = 5050

Max and linear search are O(n) time and O(1) extra space; the formula is O(1). Copy and run it locally; this website shows code but does not execute it.

  • Overflow: n(n + 1)/2 overflows a 32-bit int once n exceeds about 65,535; the C++ and Java versions use 64-bit long long/long.
  • Return value −1: linear search uses an impossible index to signal “not found”; document such conventions in the postcondition.

Common confusions

ConfusionCorrection
“An algorithm is a program.”A program implements an algorithm; the algorithm is language-independent.
“It worked on my tests, so it is correct.”Tests sample inputs; a proof (e.g. a loop invariant) covers all valid inputs.
“Finiteness means fast.”Finiteness only means it stops. Speed is efficiency, analysed in Lectures 2–4.
“The invariant is true after the loop only.”It must be true before every iteration; at termination it gives the postcondition.
“Effectiveness means efficient.”Effectiveness means each step can actually be carried out exactly, e.g. by pencil and paper.

Practise

  1. Basic. Write a specification (pre/postcondition) for finding the smallest mark and adapt the invariant.
  2. Core. Write an algorithm that returns the largest and the second-largest distinct values in one pass. State its invariant.
    Hint
    Keep two variables, first and second. When a value beats first, the old first becomes second.
  3. Core. Is “keep dividing n by 2 until it is odd” an algorithm for every positive integer n? For n = 0?
    Answer
    For every positive n it terminates (n halves each time and odd numbers stop it). For n = 0 it never stops, so 0 must be excluded by the precondition.
  4. Challenge. Prove with an invariant that the loop total = 0; for i = 1..n: total += i returns n(n + 1)/2.

Reveal model answer

Reveal model answer
Counterexample [−5, −2, −9] returns 0, not −2. Tests with any non-negative value pass, so random tests on typical data can miss it; a proof would fail at initialisation (0 is not max(A[0..0])).

C1 · Prove the correctness of the maximum-finding algorithm using a loop invariant, and analyse its time and space. 10 marks

Reveal model answer
Invariant best = max(A[0..i−1]); initialisation, maintenance (two cases), termination at i = n gives postcondition; loop runs n − 1 times so it terminates. Time Θ(n) (n − 1 comparisons), extra space O(1).

Statement 2; initialisation 2; maintenance 3; termination 2; complexity 1.

C2 · Describe the major algorithm design paradigms with one example each, and explain how you would choose among them. 10 marks

Reveal model answer
Brute force, divide and conquer, greedy, DP, backtracking, transform and conquer, each with an example. Choice: independent subproblems → D&C; overlapping subproblems with optimal substructure → DP; provable safe local choice → greedy; small search space → brute force/backtracking.
