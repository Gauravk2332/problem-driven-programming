Terms

Key → hash function h → bucket 0…m−1. Collision: different keys, same h. Unavoidable when keys > slots (pigeonhole). Always compare keys after hashing.

Bucket 1: 15 → 8; bucket 6: 27 → 20. α = 6/7.

Cost

α = n/m. Chaining: expected O(1 + α) search (uniform hashing), worst O(n). Keep α bounded ⇒ expected O(1). No ordering.

Using maps and sets

Membership, counting, complement lookup (two-sum [2,7,11,15], 9 → (0,1)), grouping, prefix sums. C++ unordered_map/set; Java HashMap/HashSet; Python dict/set.

Common mistakes · full marks

  • Equal hash ≠ equal key.
  • k mod 10 or 2ᵏ with patterned keys.
  • Negative % in C++/Java.

Two-mark self-test

  1. Define hashing and a hash function.
    Hashing stores and finds keys by computing their position from the key. A hash function maps keys to indices 0 … m − 1.
  2. What is a collision? Why can it not be avoided?
    Two different keys with the same hash value. There are more possible keys than slots (pigeonhole).
  3. Define load factor.
    α = n/m, the number of stored keys divided by the number of buckets.
  4. Name four hash function methods.
    Division, multiplication, folding, mid-square (and polynomial for strings).
  5. What are the expected and worst-case search times with chaining?
    Expected O(1 + α) under simple uniform hashing; worst case O(n).
