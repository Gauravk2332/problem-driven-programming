Chapter 01 / 07

Start with a problem

A college has 10,000 student roll numbers. Each query asks whether a roll number is registered. A scan of an unsorted array may inspect every entry. A directly addressed array indexed by roll number is fast but wasteful if those numbers range up to a billion.

StructureLookupLimitation
Unsorted arrayO(n) worst caseInspect entries
Sorted arrayO(log n) binary searchMaintaining sorted order can be costly
Direct addressingO(1)Space proportional to key universe
Hash tableExpected O(1) with suitable hashingCollisions; worst case O(n)

Instead, send each key through a function that maps it into a smaller set of buckets. The actual keys are retained so equality can be checked.

Chapter 02 / 07

Understand hashing

Key: identifier used for lookup. Value: associated data. Hash function: maps a key to a hash value; a table converts that value to a bucket index. In introductory examples one function can do both. Hash index: a bucket position, not the key itself. Hash table: the storage and collision-resolution scheme.

h(k) = ((k mod m)+m) mod m
0 ≤ h(k) < m

For m=7, h(10)=3, h(17)=3, h(18)=4. Distinct keys can share a bucket. With more possible keys than buckets, collisions are unavoidable by the pigeonhole principle. A suitable function is deterministic within a table, inexpensive and distributes typical keys well. Equal keys must hash equally; equal hash values do not imply equal keys.

Division hashing uses modulo; multiplication hashing uses a fractional part scaled to m. Strings can be processed with a polynomial recurrence: h=0; for each character c, h=(31h+code(c)) mod m. With ASCII A=65, B=66 and m=101, AB gives 61 and BA gives 91. This illustrative function is not cryptographically secure; real hash tables may randomize hashing. For a string of length L, computing its hash from scratch takes O(L).

Chapter 03 / 07

Explore the worked example

Use the default input and step through entries. Bucket 3 holds 10,17,24,31; bucket 4 holds 18. Keys stay distinct even though their indices coincide. Lecture 11 explains how chaining and probing resolve such collisions.

Abstract structureStoresExample
Hash setUnique keysRegistered IDs, membership
Hash mapKey–value pairsID → name; word → frequency

Map insertion with an existing key updates the associated value; set insertion of an existing key has no effect. Library examples: C++ unordered_map/unordered_set; Java HashMap/HashSet; Python dict/set. Ordering is not the same as sorting; Python dict preserves insertion order, not sorted-key order. Hashable keys must have stable hash/equality while stored.

from collections import Counter
a=[4,2,4,7,2,4]
freq=Counter(a)
unique=set(a)
print(freq[4],len(unique))

def two_sum(a,target):
    seen={}
    for i,x in enumerate(a):
        if target-x in seen:
            return (seen[target-x],i)
        seen[x]=i
    return None
print(*two_sum([2,7,11,15],9))

int main(){
 vector<int> a={4,2,4,7,2,4};

 unordered_map<long long,int> seen;
 for(int i=0;i<(int)b.size();i++){
  auto it=seen.find(9LL-b[i]);
  if(it!=seen.end()){cout<<it->second<<" "<<i<<"\n";break;}
  seen[b[i]]=i;
 }
}
import java.util.*;
class Main{
 public static void main(String[] args){
  int[] a={4,2,4,7,2,4};
  Map<Integer,Integer> freq=new HashMap<>();
  Set<Integer> unique=new HashSet<>();
  for(int x:a){freq.merge(x,1,Integer::sum);unique.add(x);}
  System.out.println(freq.get(4)+" "+unique.size());
  int[] b={2,7,11,15};
  Map<Long,Integer> seen=new HashMap<>();
  for(int i=0;i<b.length;i++){
   long need=9L-b[i];
   if(seen.containsKey(need)){System.out.println(seen.get(need)+" "+i);break;}
   seen.put((long)b[i],i);
  }
 }
}

Expected output: 3 3, then 0 1. Run locally; the website displays and copies code.

Frequency counting and two-sum use expected O(n) time and O(n) auxiliary space for fixed-size keys under good hashing. Worst-case collision behavior can be slower (a simple chained table can take O(n²) across n operations). Lookup is performed before insertion in two-sum, so the same position is not used twice. For [3,3], target 6, the result is (0,1). For no pair, the Python function returns None; the two demonstration programs in C++ and Java print no pair line. On a judge follow its required output. Python dict.get and Java getOrDefault can avoid missing-key errors; in C++ unordered_map operator[] inserts a default value for a missing key, while find does not.

Chapter 07 / 07

Exam revision

Hashing translates a key into an index; the actual key is retained for equality. h(k)=((k mod m)+m) mod m handles negative integer keys. Equal keys must have equal hashes. Set: unique keys. Map: key/value association. With well-distributed hash values and controlled load, expected O(1) fixed-size-key operations; worst case O(n) in a simple chained table. Frequency and pair-complement problems often use expected O(n) time, O(n) space. Hashing does not automatically sort data.

For full marks: define the terms, show the mapping/probes, trace the table, explain the design assumptions and analyse expected and worst-case costs.
