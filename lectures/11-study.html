Chapter 02 / 07

Understand collision resolution

Separate chaining: each bucket stores a collection of entries. Hash to the bucket, then compare keys in its chain. Insert/update after checking for equality. Expected lookup O(1+α) under simple uniform hashing, α=n/m; worst O(n). Chains can store more keys than buckets.

Open addressing: store entries in the table itself; every probe uses the same deterministic sequence during insertion and search. For probe number i=0,1,… use:

Linear: (h₁(k)+i) mod m
Quadratic: (h₁(k)+c₁i+c₂i²) mod m
Double hashing: (h₁(k)+i·h₂(k)) mod m

For the lab use c₁=0,c₂=1. Linear covers every slot but has primary clustering (long occupied runs). Quadratic disperses adjacent runs but keys with the same home index follow the same sequence (secondary clustering); the sequence may repeat before reaching every slot. For double hashing use prime m and h₂(k)=1+normalized_mod(k,m−1); the step lies in 1..m−1 and is coprime to m, so all m slots are reachable. No rule removes all collisions.

A quadratic failure example: size 7 and keys 10,17,24,31,38; probes from home 3 visit only {3,4,0,5}, so 38 cannot be inserted although other slots are free. With i² probing and odd prime size, insertion is guaranteed while fewer than half the slots are occupied, but not at every load.

Search and deletion

Search follows the insertion probe sequence, compares actual keys, and may stop at a never-used empty slot; cap at m probes. Deleting by simply making a slot empty breaks a probe chain. Example: linear insert 10,17 at indices 3,4; erase 10 by marking empty and lookup of 17 stops at 3 incorrectly. Use a tombstone (deleted marker), which lookup passes. Insertion can reuse the first tombstone only after ruling out duplicates further in the sequence. Track tombstones separately; periodic rebuild removes them. Chaining deletion removes the key from its chain.

Load factor and rehashing

α = number of live entries / number of buckets

For this example α=5/7≈0.714. Open addressing requires α≤1, and performance degrades near full occupancy; with tombstones, effective occupancy is (live+deleted)/m. Chaining permits α>1. A resize threshold such as 0.7 or 0.75 is an implementation choice, not a universal law. Resize to a larger suitable size and reinsert every live key using the new function; copying entries to their old indices is incorrect. With linear probing and m=11 the keys 10,17,24,31,18 go to indices 10,6,2,9,7. Change the lab's size to 11 and apply to compare. If a probe scheme fails to insert during rebuild, enlarge again or change strategy; never silently drop keys. A rebuild usually costs expected O(n+m_new) with controlled load; geometric growth gives amortized expected O(1) insertion for fixed-size keys with constant-load assumptions. A single insertion may trigger a rebuild.

# Linear probing set; None = unused, DEAD = deleted
DEAD=object()
class Table:
    def __init__(self,m):
        self.a=[None]*m
    def find(self,k):
        for i in range(len(self.a)):
            j=(k+i)%len(self.a)
            v=self.a[j]
            if v is None:return -1
            if v is not DEAD and v==k:return j
        return -1
    def insert(self,k):
        first=-1
        for i in range(len(self.a)):
            j=(k+i)%len(self.a);v=self.a[j]
            if v is DEAD and first<0:first=j
            elif v is None:
                self.a[first if first>=0 else j]=k
                return True
            elif v is not DEAD and v==k:return True
        if first>=0:self.a[first]=k;return True
        return False
    def erase(self,k):
        j=self.find(k)
        if j>=0:self.a[j]=DEAD

Chapter 07 / 07

Exam revision

Collision resolution: chaining uses a collection per bucket; open addressing follows linear, quadratic or double-hash probe sequences. Linear: primary clustering. Quadratic: secondary clustering and restricted coverage. Double hashing: coprime step gives full coverage. Load α=n/m, chaining may exceed 1; open addressing slows near full occupancy. Search stops at unused slot or bounded exhaustion, not a tombstone. Resize by recomputing indices and reinserting every live entry. Expected constant operations require suitable assumptions; worst case can be linear. Rehashing has a one-time rebuild cost, geometric growth controls amortized cost.

For full marks: define the terms, show the mapping/probes, trace the table, explain the design assumptions and analyse expected and worst-case costs.
