Chapter 01 / 13

Recall: what an optimisation problem asks

Many problems in this course have the same shape. There is a set of feasible solutions (those that obey the rules) and an objective to maximise or minimise. Paying an exact amount with the fewest coins is one: a feasible solution is any collection of coins that adds up to the amount, and the objective is the number of coins.

Brute force tries every feasible solution. Dynamic programming (Module 5) organises that search so that no subproblem is solved twice. A greedy algorithm does something much bolder: it builds one solution, a piece at a time, always taking the piece that looks best right now, and it never goes back.

ApproachHow many solutions it examinesRisk
Brute forceAll of themToo slow
Dynamic programmingAll, but each subproblem onceNeeds a correct state and recurrence
GreedyExactly oneMay be wrong unless proved

That habit — take the largest piece that fits, then repeat on what is left — is a greedy algorithm. The question for this lecture is: is the obvious choice always right, and how would we know?

Chapter 03 / 13

The greedy idea in plain language

A greedy algorithm repeats three questions until the solution is complete:

  1. Select: which remaining candidate looks best by some rule (largest coin, earliest finish, highest profit…)?
  2. Feasible: can it be added without breaking the rules?
  3. Commit: if yes, keep it for good; if no, discard it for good.

Textbooks (for example Horowitz, Sahni and Rajasekaran) write this as a control abstraction that every greedy algorithm fills in:

Greedy(a[1..n]):
  solution = ∅
  for i = 1 to n:
    x = Select(a)    // best remaining candidate
    if Feasible(solution ∪ {x}): solution = solution ∪ {x}
  return solution
ComponentMeaningChange-making
Candidate setPieces we may choose fromCoins of each denomination
Selection functionRule that picks the next candidateLargest coin ≤ remaining amount
Feasibility checkCan the partial solution still be completed legally?Coin must not exceed the remaining amount
ObjectiveWhat we optimiseNumber of coins (minimise)
Solution checkIs the solution complete?Remaining amount is 0

Because the algorithm never undoes a choice, it is usually fast: often just a sort followed by one pass. Speed is the attraction; correctness is the thing we must earn.

Chapter 06 / 13

Two properties that make greedy correct

Why does largest-first work for rupees but not for {1, 3, 4}? Two properties explain it.

Greedy-choice property

There is an optimal solution that contains the first greedy choice. In other words, committing to the greedy choice never rules out reaching an optimum.

Optimal substructure

After the greedy choice is made, what remains is a smaller instance of the same problem, and an optimal solution to the whole consists of the greedy choice plus an optimal solution to that smaller instance.

If both hold, induction finishes the argument: the first choice is safe, the rest is the same problem again, so every choice is safe.

Coins {1, 2, 5, 10, 20, 50, 100}Coins {1, 3, 4}
Optimal substructureYesYes — remove any coin from an optimal solution and the rest is optimal for the smaller amount
Greedy-choice propertyYes (proved in the next chapter)No — for 6, no optimal solution contains a 4
Greedy optimal?AlwaysNot always

Key point: optimal substructure alone is not enough. Dynamic programming also needs optimal substructure, but it tries every first choice. Greedy bets on one, so it additionally needs the greedy-choice property.

Chapter 07 / 13

Proving greedy correct for a real coin system

A correctness proof shows the greedy-choice property holds for every input. Here is one for coins {1, 2, 5, 10}, using an exchange argument: if an optimal solution looked different, we could swap some coins for fewer coins, which contradicts optimality.

Claim: in every optimal solution, the coins smaller than 10 add up to at most 9

  1. At most one 1: two 1s can be exchanged for one 2 (one coin fewer).
  2. At most two 2s: three 2s (6) can be exchanged for 5 + 1.
  3. Not a 1 together with two 2s: 1 + 2 + 2 = 5 can be exchanged for one 5.
  4. So the 1s and 2s add up to at most 4 (possible totals 0, 1, 2, 3, 4).
  5. At most one 5: two 5s can be exchanged for one 10.
  6. Therefore the coins below 10 add up to at most 5 + 4 = 9.

Consequence. For an amount A, any optimal solution must use exactly ⌊A/10⌋ tens: with fewer tens, the smaller coins would have to cover at least 10. That is precisely what greedy does first. The same reasoning applied to the remainder (below 10) shows the next greedy choices are forced too: if the remainder is at least 5, the 1s and 2s cover at most 4, so a 5 is required. Each greedy choice is therefore part of every optimal solution.

The rupee system adds 20, 50 and 100, and the same style of exchange argument works (for example, three 20s can become 50 + 10). Coin systems for which largest-first is always optimal are called canonical. {1, 3, 4} is not canonical, and our proof breaks exactly there: two 3s (6) cannot be exchanged for fewer coins that include a 4.

Greedy, dynamic programming and brute force

The same problem can be solved three ways. Knowing which to use is part of the skill.

MethodChange for amount A with k coin typesAlways optimal?When to use
Brute forceExponential in AYesTiny inputs, or as a checker
Dynamic programmingO(A·k) time, O(A) spaceYes, for any coin systemWhen greedy is not proved
GreedyO(k log k) to sort + O(k) with divisionOnly for canonical systemsWhen the greedy-choice property is proved

A practical habit from competitive programming: when you invent a greedy rule, write a tiny brute-force or DP checker and compare them on many small inputs. If they ever disagree, you have found a counterexample before the examiner (or the judge) does. The program in the next chapter does exactly that for coin systems.

Chapter 09 / 13

From the rule to code

The program implements largest-first, the exact DP optimum, and a checker that finds the smallest amount where greedy is not optimal. Read how each part maps to the control abstraction: sorted(…, reverse=True) is the selection order, amount >= c is the feasibility check, and amount == 0 is the solution check.

Python · coin_change.py

# Greedy change-making versus the true optimum (Lecture 12)
# coins: distinct positive integers; amount >= 0


def greedy_change(coins, amount):
    """Largest coin first. Returns the coins used, or None if greedy gets stuck."""
    used = []
    for c in sorted(coins, reverse=True):
        while amount >= c:
            used.append(c)
            amount -= c
    return used if amount == 0 else None


def min_coins(coins, amount):
    """Exact optimum by DP (Lecture 22). Returns None if amount is unreachable."""
    INF = float("inf")
    best = [0] + [INF] * amount
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a and best[a - c] + 1 < best[a]:
                best[a] = best[a - c] + 1
    return None if best[amount] == INF else best[amount]


def first_failure(coins, limit):
    """Smallest amount <= limit where greedy is not optimal, or None."""
    for a in range(1, limit + 1):
        g = greedy_change(coins, a)
        if (None if g is None else len(g)) != min_coins(coins, a):
            return a
    return None


def show(coins, amount):
    g = greedy_change(coins, amount)
    shown = "stuck" if g is None else f"{len(g)} coins " + "+".join(map(str, g))
    print(f"{amount} with {coins}: greedy {shown}, optimum {min_coins(coins, amount)}")


if __name__ == "__main__":
    show([1, 2, 5, 10, 20, 50, 100], 289)
    show([1, 3, 4], 6)
    show([3, 4], 6)
    for coins in ([1, 2, 5, 10, 20, 50, 100], [1, 3, 4], [1, 5, 6, 9]):
        f = first_failure(coins, 500)
        print(f"first failure for {coins} up to 500: {'none' if f is None else f}")

C++ · coin_change.cpp

// Greedy change-making versus the true optimum (Lecture 12)
#include <algorithm>
#include <climits>
#include <functional>
#include <iostream>
#include <string>
#include <vector>
using namespace std;

// Largest coin first. Returns false if greedy gets stuck.
bool greedyChange(vector<int> coins, int amount, vector<int>& used) {
    sort(coins.rbegin(), coins.rend());
    used.clear();
    for (int c : coins)
        while (amount >= c) { used.push_back(c); amount -= c; }
    return amount == 0;
}

// Exact optimum by DP (Lecture 22); -1 if unreachable.
int minCoins(const vector<int>& coins, int amount) {
    vector<int> best(amount + 1, INT_MAX);
    best[0] = 0;
    for (int a = 1; a <= amount; a++)
        for (int c : coins)
            if (c <= a && best[a - c] != INT_MAX && best[a - c] + 1 < best[a]) best[a] = best[a - c] + 1;
    return best[amount] == INT_MAX ? -1 : best[amount];
}

// Smallest amount <= limit where greedy is not optimal; 0 if none.
int firstFailure(const vector<int>& coins, int limit) {
    vector<int> used;
    for (int a = 1; a <= limit; a++) {
        int g = greedyChange(coins, a, used) ? (int)used.size() : -1;
        if (g != minCoins(coins, a)) return a;
    }
    return 0;
}

string list(const vector<int>& v) {
    string s = "[";
    for (size_t i = 0; i < v.size(); i++) s += (i ? ", " : "") + to_string(v[i]);
    return s + "]";
}

void show(const vector<int>& coins, int amount) {
    vector<int> used;
    string shown = "stuck";
    if (greedyChange(coins, amount, used)) {
        shown = to_string(used.size()) + " coins ";
        for (size_t i = 0; i < used.size(); i++) shown += (i ? "+" : "") + to_string(used[i]);
    }
    cout << amount << " with " << list(coins) << ": greedy " << shown
         << ", optimum " << minCoins(coins, amount) << "\n";
}

int main() {
    show({1, 2, 5, 10, 20, 50, 100}, 289);
    show({1, 3, 4}, 6);
    show({3, 4}, 6);
    for (auto coins : vector<vector<int>>{{1, 2, 5, 10, 20, 50, 100}, {1, 3, 4}, {1, 5, 6, 9}}) {
        int f = firstFailure(coins, 500);
        cout << "first failure for " << list(coins) << " up to 500: "
             << (f ? to_string(f) : "none") << "\n";
    }
}

Java · CoinChange.java

// Greedy change-making versus the true optimum (Lecture 12)
import java.util.*;

public class CoinChange {
    // Largest coin first. Returns null if greedy gets stuck.
    static List<Integer> greedyChange(int[] coins, int amount) {
        int[] c = coins.clone();
        Arrays.sort(c);
        List<Integer> used = new ArrayList<>();
        for (int i = c.length - 1; i >= 0; i--)
            while (amount >= c[i]) { used.add(c[i]); amount -= c[i]; }
        return amount == 0 ? used : null;
    }

    // Exact optimum by DP (Lecture 22); -1 if unreachable.
    static int minCoins(int[] coins, int amount) {
        int[] best = new int[amount + 1];
        Arrays.fill(best, Integer.MAX_VALUE);
        best[0] = 0;
        for (int a = 1; a <= amount; a++)
            for (int c : coins)
                if (c <= a && best[a - c] != Integer.MAX_VALUE && best[a - c] + 1 < best[a]) best[a] = best[a - c] + 1;
        return best[amount] == Integer.MAX_VALUE ? -1 : best[amount];
    }

    // Smallest amount <= limit where greedy is not optimal; 0 if none.
    static int firstFailure(int[] coins, int limit) {
        for (int a = 1; a <= limit; a++) {
            List<Integer> g = greedyChange(coins, a);
            if ((g == null ? -1 : g.size()) != minCoins(coins, a)) return a;
        }
        return 0;
    }

    static void show(int[] coins, int amount) {
        List<Integer> g = greedyChange(coins, amount);
        String shown = "stuck";
        if (g != null) {
            StringJoiner j = new StringJoiner("+");
            for (int x : g) j.add(String.valueOf(x));
            shown = g.size() + " coins " + j;
        }
        System.out.println(amount + " with " + Arrays.toString(coins) + ": greedy " + shown
                + ", optimum " + minCoins(coins, amount));
    }

    public static void main(String[] args) {
        show(new int[]{1, 2, 5, 10, 20, 50, 100}, 289);
        show(new int[]{1, 3, 4}, 6);
        show(new int[]{3, 4}, 6);
        for (int[] coins : new int[][]{{1, 2, 5, 10, 20, 50, 100}, {1, 3, 4}, {1, 5, 6, 9}}) {
            int f = firstFailure(coins, 500);
            System.out.println("first failure for " + Arrays.toString(coins) + " up to 500: "
                    + (f == 0 ? "none" : String.valueOf(f)));
        }
    }
}

6 with [1, 3, 4]: greedy 3 coins 4+1+1, optimum 2

Greedy: O(k log k + q), where q is the number of coins output. DP and the checker: O(A·k) per amount. Copy and run it locally; this website shows code but does not execute it.

  • Faster greedy: replace the while loop with division (q = amount // c), giving O(k) after sorting.
  • Stuck case: without a coin of value 1, greedy can end with a positive remainder even when an exact answer exists (coins 3, 4 for amount 6).
  • Large amounts: the greedy itself needs no table, so it handles huge amounts; the DP checker needs O(A) memory.

Chapter 10 / 13

Recognising greedy problems and common confusions

A problem is a good greedy candidate when:

  • a solution is built from a sequence of choices, and
  • there is a natural priority (largest, smallest, earliest, cheapest, highest ratio), and
  • making the top-priority choice leaves a smaller problem of the same kind.

It is only a candidate: you still need a proof or a counterexample search.

ConfusionCorrection
'Greedy means pick the largest number.'The rule depends on the problem: earliest finish, smallest ratio, highest profit…
'It worked on my examples, so it is correct.'Examples can only refute. Prove the greedy-choice property, or test against brute force.
'Optimal substructure means greedy works.'DP needs substructure too. Greedy additionally needs the greedy-choice property.
'Greedy fails, so the problem is hard.'Often DP solves it exactly (coin change with any coins).

B1 · Apply the greedy method to pay ₹289 with Indian denominations. Is it optimal? 5 marks

Reveal model answer
Take 100, 100 (89 left), 50 (39), 20 (19), 10 (9), 5 (4), 2 (2), 2 (0): 8 pieces. The rupee system is canonical, so largest-first is optimal; a DP or exchange argument confirms 8 is the minimum.

B2 · Show that largest-first fails for coins {1,5,6,9}. Find the smallest failing amount and explain why. 5 marks

Reveal model answer
Amounts 1–10 agree with the optimum. For 11, greedy takes 9 then 1+1: 3 coins; 5+6 uses 2. The first greedy choice (9) is not in any optimal solution for 11, so the greedy-choice property fails.

Smallest amount 1; greedy trace 1; optimum 1; property identified 2.

B3 · Compare greedy and dynamic programming for change-making. 5 marks

Reveal model answer
Greedy: sort and scan, O(k log k + k); correct only for canonical systems. DP: m[a] = min over coins c ≤ a of 1 + m[a−c], O(A·k) time, O(A) space; correct for any system. Both rely on optimal substructure; greedy also needs the greedy-choice property.

Greedy cost and condition 2; DP recurrence and cost 2; property distinction 1.
