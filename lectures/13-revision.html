Design process

  1. Model input, feasibility, objective
  2. Propose candidate rules
  3. Refute rules with small counterexamples
  4. Prove the survivor (exchange / stays ahead)
  5. Implement (sort + scan, heap)
  6. Analyse time, space, edge cases

Fractional knapsack

Maximise Σ vᵢxᵢ/wᵢ subject to Σxᵢ ≤ W, 0 ≤ xᵢ ≤ wᵢ.

sort by vᵢ/wᵢ descending
for each item: take = min(wᵢ, room)
  value += vᵢ·take/wᵢ; room −= take

At most one item is split.

Exchange proof

If an optimum uses weight of item j while item i (rᵢ ≥ rⱼ) is not full, move ε from j to i: weight same, value +ε(rᵢ − rⱼ) ≥ 0. Repeat ⇒ greedy is optimal.

0/1 contrast

W = 50; 10:60, 20:100, 30:120. Fractional greedy: 240. Whole items, ratio-greedy: 160; optimum 220 (items 2+3) ⇒ use DP (Lecture 21).

Complexity and implementation

O(n log n) sort + O(n) scan. Compare ratios exactly: v₁w₂ vs v₂w₁ (64-bit).

Common mistakes · full marks

  • Sorting by value or weight instead of ratio.
  • Applying the fractional rule to 0/1 items.
  • Floating-point ratio ties.

Full marks: model, rule, ratio table, trace, exchange proof, complexity, 0/1 contrast.

Two-mark self-test

  1. Define the fractional knapsack problem.
    Given capacity W and items with weight wᵢ > 0 and value vᵢ, choose 0 ≤ xᵢ ≤ wᵢ with Σxᵢ ≤ W to maximise Σ vᵢxᵢ/wᵢ; items may be split.
  2. State the greedy rule for the fractional knapsack.
    Take items in non-increasing order of vᵢ/wᵢ, each fully while it fits, then a fraction of the next until the bag is full.
  3. Why does ratio-greedy fail for the 0/1 knapsack?
    Items cannot be split, so the exchange of a small weight ε between items is impossible; e.g. W=50, items 10:60, 20:100, 30:120 gives 160 by greedy but 220 is optimal.
  4. List the steps for designing a greedy algorithm.
    Model; propose rules; test with counterexamples; prove the survivor; implement; analyse.
  5. What is the time complexity of the fractional knapsack algorithm?
    O(n log n): sorting by ratio; the scan is O(n).
