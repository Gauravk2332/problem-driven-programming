Chapter 01 / 12

Recall: what makes a greedy algorithm correct

In Lecture 12 a greedy algorithm built one solution by repeatedly taking the best feasible candidate and never undoing a choice. It is correct when two properties hold: the greedy-choice property (some optimal solution contains the greedy choice) and optimal substructure (what remains is a smaller instance of the same problem).

Today's question is practical: where does the rule come from? For coins the rule was obvious. For most problems there are several plausible rules and most of them are wrong.

All three are greedy. Only one is right, and we need a way to know which.

Chapter 03 / 12

A six-step design process

Designing a greedy algorithm is a disciplined process, not a lucky guess.

  1. Model. State the input, the feasible solutions and the objective precisely. (Here: choose amounts 0 ≤ xᵢ ≤ wᵢ with Σxᵢ ≤ W, maximise Σ vᵢ·xᵢ/wᵢ.)
  2. Propose rules. List natural priorities: largest value, smallest weight, largest ratio…
  3. Attack each rule. Hunt for a small counterexample, by hand or with a brute-force checker.
  4. Prove the survivor. Usually with an exchange argument (Chapter 6) or a "stays ahead" argument (Lecture 14).
  5. Implement. Most greedy algorithms are a sort followed by one scan, or a priority queue.
  6. Analyse. Time, extra space, and edge cases such as ties, empty input and overflow.

Chapter 06 / 12

Why the ratio rule is optimal

Exchange argument

Order items so that r₁ ≥ r₂ ≥ … ≥ rₙ, where rᵢ = vᵢ/wᵢ. Let O be any optimal filling. Suppose O takes less than all of some item i while using some weight of a later item j with rⱼ ≤ rᵢ.

Move ε kilograms from item j to item i, where ε is small enough to stay within both items. The total weight is unchanged, so O stays feasible, and the value changes by ε·rᵢ − ε·rⱼ ≥ 0. So the new filling is still optimal.

Repeating this exchange transforms O, without ever lowering its value, into the filling that takes items fully in ratio order until the bag is full, which is exactly the greedy solution. Therefore greedy is optimal.

Notice the shape of the proof: start from any optimal solution, show that a local swap toward the greedy choice never hurts, and conclude that greedy is one of the optima. You will reuse this template for job sequencing, scheduling and Huffman coding.

The same rule fails when items cannot be split

The exchange argument broke because it moved ε kilograms between items; with whole items, ε cannot be arbitrary. The 0/1 version needs dynamic programming (Lecture 21). This is a classic exam distinction: fractional → greedy by ratio; 0/1 → DP.

Chapter 08 / 12

From the rule to code

Sort by ratio, then scan. Two implementation details matter:

  • Exact comparison. Compare v₁/w₁ with v₂/w₂ as v₁·w₂ versus v₂·w₁, avoiding floating-point rounding in the sort. Use 64-bit integers so the products do not overflow.
  • Only the answer is fractional. The amounts taken are whole numbers here; only the value of the last item can be fractional.

Python · fractional_knapsack.py

# Fractional knapsack by value-per-weight ratio (Lecture 13)
# items: (weight > 0, value >= 0); capacity >= 0
from functools import cmp_to_key


def by_ratio(a, b):
    # compare v1/w1 with v2/w2 exactly, without floating point: v1*w2 vs v2*w1
    left, right = a[1] * b[0], b[1] * a[0]
    return -1 if left > right else (1 if left < right else 0)


def fractional_knapsack(items, capacity):
    total, plan = 0.0, []
    for w, v in sorted(items, key=cmp_to_key(by_ratio)):  # stable: ties keep input order
        if capacity == 0:
            break
        take = min(w, capacity)            # whole item, or the part that fits
        total += v * take / w
        capacity -= take
        plan.append(f"{take}/{w} of ({w},{v})")
    return total, plan


if __name__ == "__main__":
    for items, cap in (([(10, 60), (20, 100), (30, 120)], 50),
                       ([(18, 25), (15, 24), (10, 15)], 20),
                       ([(5, 10)], 0)):
        total, plan = fractional_knapsack(items, cap)
        print(f"capacity {cap}: take {', '.join(plan) if plan else 'nothing'} -> {total:.2f}")

C++ · fractional_knapsack.cpp

// Fractional knapsack by value-per-weight ratio (Lecture 13)
#include <algorithm>
#include <cstdio>
#include <string>
#include <vector>
using namespace std;

struct Item { long long w, v; };   // weight > 0, value >= 0

double fractionalKnapsack(vector<Item> items, long long capacity, string& plan) {
    // v1/w1 > v2/w2  <=>  v1*w2 > v2*w1  (exact, no floating point)
    stable_sort(items.begin(), items.end(),
                [](const Item& a, const Item& b) { return a.v * b.w > b.v * a.w; });
    double total = 0;
    plan.clear();
    for (const Item& it : items) {
        if (capacity == 0) break;
        long long take = min(it.w, capacity);   // whole item, or the part that fits
        total += (double)it.v * take / it.w;
        capacity -= take;
        if (!plan.empty()) plan += ", ";
        plan += to_string(take) + "/" + to_string(it.w) + " of (" + to_string(it.w) + "," + to_string(it.v) + ")";
    }
    return total;
}

int main() {
    vector<pair<vector<Item>, long long>> cases = {
        {{{10, 60}, {20, 100}, {30, 120}}, 50},
        {{{18, 25}, {15, 24}, {10, 15}}, 20},
        {{{5, 10}}, 0}};
    for (auto& [items, cap] : cases) {
        string plan;
        double total = fractionalKnapsack(items, cap, plan);
        printf("capacity %lld: take %s -> %.2f\n", cap, plan.empty() ? "nothing" : plan.c_str(), total);
    }
}

Java · FractionalKnapsack.java

// Fractional knapsack by value-per-weight ratio (Lecture 13)
import java.util.*;

public class FractionalKnapsack {
    // each item: {weight > 0, value >= 0}
    static double solve(long[][] items, long capacity, StringJoiner plan) {
        long[][] order = items.clone();
        // v1/w1 > v2/w2  <=>  v1*w2 > v2*w1  (exact; List.sort is stable)
        Arrays.sort(order, (a, b) -> Long.compare(b[1] * a[0], a[1] * b[0]));
        double total = 0;
        for (long[] it : order) {
            if (capacity == 0) break;
            long take = Math.min(it[0], capacity);   // whole item, or the part that fits
            total += (double) it[1] * take / it[0];
            capacity -= take;
            plan.add(take + "/" + it[0] + " of (" + it[0] + "," + it[1] + ")");
        }
        return total;
    }

    public static void main(String[] args) {
        long[][][] cases = {{{10, 60}, {20, 100}, {30, 120}}, {{18, 25}, {15, 24}, {10, 15}}, {{5, 10}}};
        long[] caps = {50, 20, 0};
        for (int i = 0; i < cases.length; i++) {
            StringJoiner plan = new StringJoiner(", ");
            double total = solve(cases[i], caps[i], plan);
            System.out.printf("capacity %d: take %s -> %.2f%n", caps[i],
                    plan.length() == 0 ? "nothing" : plan.toString(), total);
        }
    }
}

Chapter 09 / 12

Recognising and designing greedy problems

Ask these questions when a new problem looks greedy:

  1. Is the solution a set or sequence of choices with a clear objective?
  2. Is there a single number per candidate that should decide priority (ratio, deadline, finish time)?
  3. Can items be divided, or must they be taken whole? Divisibility often makes greedy work.
  4. After one choice, is the remaining problem the same kind?
ProblemGreedy ruleStatus
Fractional knapsackHighest value/weight firstOptimal
0/1 knapsackHighest value/weight firstNot optimal (DP)
Maximum units on a truck (boxes of unit weight)Most units per box firstOptimal: boxes are equal-sized pieces
Activity selectionEarliest finish firstOptimal (Lecture 14)
Job sequencingHighest profit first, latest free slotOptimal (Lecture 15)

Common confusions: "highest value first" sounds natural but ignores weight; "take whole items" silently changes the problem to 0/1; equal ratios can be taken in any order without changing the value.

A1 · Define the fractional knapsack problem. 2 marks

Reveal model answer
Given capacity W and items with weight wᵢ > 0 and value vᵢ, choose 0 ≤ xᵢ ≤ wᵢ with Σxᵢ ≤ W to maximise Σ vᵢxᵢ/wᵢ; items may be split.

Constraint 1; objective with fractions 1.

A2 · State the greedy rule for the fractional knapsack. 2 marks

Reveal model answer
Take items in non-increasing order of vᵢ/wᵢ, each fully while it fits, then a fraction of the next until the bag is full.

Ratio order 1; whole-then-fraction 1.

A3 · Why does ratio-greedy fail for the 0/1 knapsack? 2 marks

Reveal model answer
Items cannot be split, so the exchange of a small weight ε between items is impossible; e.g. W=50, items 10:60, 20:100, 30:120 gives 160 by greedy but 220 is optimal.

Reason 1; example 1.

B3 · Prove that ratio-greedy is optimal for the fractional knapsack. 5 marks

Reveal model answer
Take an optimal solution O. If it leaves part of a higher-ratio item i while using a lower-ratio item j, move ε weight from j to i: feasible, value change ε(rᵢ − rⱼ) ≥ 0. Repeat until O equals the greedy solution; value never drops, so greedy is optimal.

Setup 1; swap 2; conclusion 2.

C2 · Design a greedy algorithm to load a truck with at most k boxes, where box type i has cᵢ boxes of uᵢ units each, maximising units. Prove and analyse it. 10 marks

Reveal model answer
Sort types by uᵢ descending; take min(cᵢ, remaining) boxes of each. Proof by exchange: replacing a box of smaller units with an unused box of larger units never decreases the total. O(n log n) time. Edge cases: k larger than all boxes; ties.
