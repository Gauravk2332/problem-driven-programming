Problem Driven Programming · R1UC544B
Lecture 14

Problem

Activities [sᵢ, fᵢ) (half-open). Compatible ⇔ no overlap; touching ends are fine. Choose the maximum number of mutually compatible activities.

Algorithm

sort by finish
last = −∞
for each [s, f): if s ≥ last: take; last = f

O(n log n) time; O(1) extra besides sorting.

Take a1 (4), a4 (7), a8 (11), a11 (16): 4.

Proof (stays ahead)

Greedy g₁…gₖ, optimum o₁…oₘ by finish. Induction: f(gᵣ) ≤ f(oᵣ). If m > k, o_{k+1} starts after f(oₖ) ≥ f(gₖ), so greedy would not have stopped. ⇒ k = m.

Variants

  • Closed intervals: accept if s > last.
  • Fewest removals = n − max.
  • Fewest rooms for all: Lecture 17.
  • Weighted: greedy fails → DP (Lecture 27).

Full marks

Define compatibility, rule, sorted trace with last-finish column, proof, one counterexample, complexity.

Two-mark self-test

  1. Define the activity selection problem.
    Given activities with start and finish times, select a maximum-size subset of mutually compatible (non-overlapping) activities.
  2. State the greedy rule for activity selection.
    Sort by finish time; repeatedly take the next activity whose start is at least the finish of the last chosen one.
  3. Give a counterexample to 'shortest activity first'.
    [0,5), [4,7), [6,11): shortest [4,7) blocks both others, giving 1; optimum 2.
  4. What is the time complexity of activity selection?
    O(n log n) for sorting by finish time plus O(n) for the scan.
  5. How does the algorithm change for closed intervals?
    Touching endpoints conflict, so accept only if start > last finish.
