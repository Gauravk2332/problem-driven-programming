Problem Driven Programming · R1UC544B
Lecture 15

Problem

Unit-time jobs, deadline dᵢ ≥ 1, profit pᵢ ≥ 0, one machine. Profit counts only if the job finishes by dᵢ. Maximise total profit.

Algorithm

sort jobs by profit descending
slots = min(n, max d)
for each job: t = latest free slot ≤ min(d, slots)
  if t exists: slot[t] = job else reject

Example 1

p = (100, 10, 15, 27), d = (2, 1, 2, 1): J1 → 2, J4 → 1, J3 and J2 rejected. Order J4, J1; profit 127.

Feasibility

S feasible ⇔ ∀t: |{i ∈ S : dᵢ ≤ t}| ≤ t ⇔ sorted by deadline, i-th job has d ≥ i.

Proof idea

First disagreement j with an optimum O. j ∈ O∖G impossible (subset of O infeasible). j ∈ G∖O: swap in j for a later (cheaper) k ∈ O with dₖ ≤ first overloaded t ⇒ still feasible, profit ≥ ⇒ contradiction.

Complexity · mistakes

O(n log n + n·d), worst O(n²); DSU slot finder ≈ O(n log n).

  • Earliest free slot loses (5:2, 4:1).
  • Deadline order alone ignores profit.
  • Only valid for unit-time jobs.

Two-mark self-test

  1. State the job sequencing with deadlines problem.
    n unit-time jobs with deadlines dᵢ and profits pᵢ on one machine; choose and order jobs so each chosen job finishes by its deadline, maximising total profit.
  2. State the greedy rule.
    Sort by decreasing profit; place each job in the latest free slot ≤ its deadline; reject if none.
  3. When is a set of jobs feasible?
    When, ordered by deadline, the i-th job has deadline ≥ i (equivalently, for every t at most t jobs have deadline ≤ t).
  4. Why use the latest free slot?
    It keeps earlier slots free for jobs with smaller deadlines, so a feasible job is never blocked unnecessarily.
  5. Give the time complexity of the simple algorithm.
    O(n log n) sort + O(n·d) slot scans, d = min(n, max deadline): O(n²) worst case.
