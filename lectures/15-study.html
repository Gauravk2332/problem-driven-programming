Chapter 03 / 12

The greedy rule and why the latest slot

Rule. Consider jobs in order of decreasing profit. Put each job in the latest free slot on or before its deadline. If no such slot is free, reject it.

slots = min(n, max deadline)   // more slots are never useful
for each job in decreasing profit:
  for t = min(d, slots) down to 1:
    if slot t is free: put the job in slot t; stop
  (no free slot ⇒ reject the job)

Why the latest free slot? A job with deadline 3 can use slot 1, 2 or 3. If we put it in slot 1, a later job with deadline 1 has nowhere to go. Placing each job as late as possible keeps the early, scarce slots for jobs with tight deadlines.

Why at most min(n, max deadline) slots? With n jobs, at most n slots are ever filled, so deadlines larger than n can be treated as n.

Chapter 06 / 12

When is a set of jobs feasible?

A set S of jobs is feasible if all of them can be scheduled before their deadlines. There is a neat test:

Feasibility lemma

S is feasible if and only if, for every time t, the number of jobs in S with deadline ≤ t is at most t.

Equivalently: sort S by deadline; S is feasible exactly when the i-th job in that order has deadline ≥ i. (If too many jobs must finish by time t, there are not enough slots; conversely, running jobs in deadline order meets every deadline.)

Example: {J1, J3, J4} has deadlines 2, 2, 1. Sorted: 1, 2, 2. The third job needs deadline ≥ 3 but has 2, so the set is infeasible: three jobs cannot all finish by time 2.

The latest-free-slot placement is simply an efficient way to run this test incrementally: a new job fits into some free slot ≤ its deadline exactly when the enlarged set is still feasible.

Chapter 07 / 12

Why highest profit first is optimal

Two facts about feasible sets drive the proof: (1) any subset of a feasible set is feasible; (2) if S is feasible and S ∪ {j} is not, removing one suitable job of S with deadline ≤ t (for the first overloaded time t) restores feasibility.

Exchange proof (exam-level detail)

List jobs by profit p₁ ≥ p₂ ≥ …. Let G be the greedy set and O an optimal set that agrees with G on as many of the first jobs as possible. Let j be the first job on which they disagree.

  • j ∈ O, j ∉ G. Greedy rejected j because (agreed jobs before j) ∪ {j} was infeasible. That set is a subset of O, so O would be infeasible: impossible.
  • j ∈ G, j ∉ O. If O ∪ {j} is feasible it is at least as profitable and agrees longer: contradiction. Otherwise let t be the first overloaded time of O ∪ {j}. The agreed jobs plus j are feasible, so some job k ∈ O with deadline ≤ t is not among them, i.e. k comes after j in profit order, so pₖ ≤ pⱼ. Then O − {k} + {j} is feasible, has profit ≥ O's, and agrees longer: contradiction.

So no disagreement exists: G is optimal. (In advanced courses this is the statement that feasible job sets form a matroid, for which the greedy algorithm is always optimal.)

Plain-language version: a more profitable job never needs to give way to a less profitable one; whenever the optimum uses a cheaper job where greedy used a dearer one, swapping them keeps the schedule feasible and does not lose money.

Chapter 08 / 12

From the rule to code

Sort by profit, keep an array of slots, scan down from each deadline.

Python · job_sequencing.py

# Job sequencing with deadlines: unit-time jobs, one machine (Lecture 15)


def job_sequencing(jobs):
    """jobs: list of (name, profit, deadline >= 1). Returns (slots, total profit)."""
    if not jobs:
        return [], 0
    size = min(len(jobs), max(d for _, _, d in jobs))   # never need more slots than jobs
    slot = [None] * (size + 1)                          # slot[1..size]
    total = 0
    for name, p, d in sorted(jobs, key=lambda j: -j[1]):  # highest profit first (stable)
        for t in range(min(d, size), 0, -1):            # latest free slot on or before d
            if slot[t] is None:
                slot[t] = name
                total += p
                break                                   # no free slot: job rejected
    return slot[1:], total


def show(jobs):
    slots, total = job_sequencing(jobs)
    plan = ", ".join(f"slot {t}: {n}" for t, n in enumerate(slots, 1) if n)
    print(f"{plan} | profit {total}")


if __name__ == "__main__":
    show([("J1", 100, 2), ("J2", 10, 1), ("J3", 15, 2), ("J4", 27, 1)])
    show([("J1", 20, 2), ("J2", 15, 2), ("J3", 10, 1), ("J4", 5, 3), ("J5", 1, 3)])
    show([("A", 9, 5)])

C++ · job_sequencing.cpp

// Job sequencing with deadlines: unit-time jobs, one machine (Lecture 15)
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>
using namespace std;

struct Job { string name; long long profit; int deadline; };   // deadline >= 1

long long jobSequencing(vector<Job> jobs, vector<string>& slot) {
    slot.clear();
    if (jobs.empty()) return 0;
    int maxD = 0;
    for (auto& j : jobs) maxD = max(maxD, j.deadline);
    int size = min((int)jobs.size(), maxD);         // never need more slots than jobs
    slot.assign(size + 1, "");                      // slot[1..size], "" = free
    stable_sort(jobs.begin(), jobs.end(),
                [](const Job& a, const Job& b) { return a.profit > b.profit; });
    long long total = 0;
    for (auto& j : jobs)
        for (int t = min(j.deadline, size); t >= 1; t--)   // latest free slot <= deadline
            if (slot[t].empty()) { slot[t] = j.name; total += j.profit; break; }
    return total;                                   // a job with no free slot is rejected
}

void show(const vector<Job>& jobs) {
    vector<string> slot;
    long long total = jobSequencing(jobs, slot);
    string plan;
    for (size_t t = 1; t < slot.size(); t++)
        if (!slot[t].empty()) plan += (plan.empty() ? "" : ", ") + string("slot ") + to_string(t) + ": " + slot[t];
    cout << plan << " | profit " << total << "\n";
}

int main() {
    show({{"J1", 100, 2}, {"J2", 10, 1}, {"J3", 15, 2}, {"J4", 27, 1}});
    show({{"J1", 20, 2}, {"J2", 15, 2}, {"J3", 10, 1}, {"J4", 5, 3}, {"J5", 1, 3}});
    show({{"A", 9, 5}});
}

Java · JobSequencing.java

// Job sequencing with deadlines: unit-time jobs, one machine (Lecture 15)
import java.util.*;

public class JobSequencing {
    record Job(String name, long profit, int deadline) {}   // deadline >= 1

    static long solve(List<Job> jobs, String[][] out) {
        if (jobs.isEmpty()) { out[0] = new String[1]; return 0; }
        int maxD = 0;
        for (Job j : jobs) maxD = Math.max(maxD, j.deadline());
        int size = Math.min(jobs.size(), maxD);          // never need more slots than jobs
        String[] slot = new String[size + 1];            // slot[1..size], null = free
        List<Job> order = new ArrayList<>(jobs);
        order.sort((a, b) -> Long.compare(b.profit(), a.profit()));   // stable
        long total = 0;
        for (Job j : order)
            for (int t = Math.min(j.deadline(), size); t >= 1; t--)  // latest free slot <= deadline
                if (slot[t] == null) { slot[t] = j.name(); total += j.profit(); break; }
        out[0] = slot;
        return total;                                    // a job with no free slot is rejected
    }

    static void show(List<Job> jobs) {
        String[][] out = new String[1][];
        long total = solve(jobs, out);
        StringJoiner plan = new StringJoiner(", ");
        for (int t = 1; t < out[0].length; t++)
            if (out[0][t] != null) plan.add("slot " + t + ": " + out[0][t]);
        System.out.println(plan + " | profit " + total);
    }

    public static void main(String[] args) {
        show(List.of(new Job("J1", 100, 2), new Job("J2", 10, 1), new Job("J3", 15, 2), new Job("J4", 27, 1)));
        show(List.of(new Job("J1", 20, 2), new Job("J2", 15, 2), new Job("J3", 10, 1),
                new Job("J4", 5, 3), new Job("J5", 1, 3)));
        show(List.of(new Job("A", 9, 5)));
    }
}

Output (identical in all three languages):

slot 1: J4, slot 2: J1 | profit 127
slot 1: J2, slot 2: J1, slot 3: J4 | profit 40
slot 1: A | profit 9

Time O(n log n) for the sort plus O(n·d) for slot scanning, where d = min(n, max deadline), so O(n²) in the worst case; extra space O(d). Copy and run it locally; this website shows code but does not execute it.

  • Faster slot search: a disjoint-set structure where find(t) returns the latest free slot ≤ t reduces scanning to almost O(1) per job, giving O(n log n) overall (optional).
  • Large deadlines: cap them at n, as the code does.
  • Zero-profit jobs may be scheduled or skipped; the total is unchanged.

ProblemRuleNotes
Unit jobs, deadlines, maximise profitHighest profit first, latest free slotThis lecture
Unit events with a start day and end day, maximise countEach day, attend the open event that ends soonest (min-heap)LeetCode 1353

  • Sorting by deadline alone is not this algorithm. Deadline order tests feasibility; profit order decides what to keep.
  • Earliest free slot is wrong. Jobs 5:2 then 4:1: putting the first in slot 1 rejects the second (profit 5); latest-slot placement keeps both (profit 9).
  • Different durations break the slot model. The proof assumed unit-time jobs.
