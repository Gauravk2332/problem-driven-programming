Optimal merge pattern

heap = sizes; cost = 0
while |heap| ≥ 2:
  a = pop; b = pop; cost += a+b; push a+b

20, 30, 10, 5, 30: 5+10, 15+20, 30+30, 35+60 ⇒ 205 (left-to-right 270).

Cost = Σ size × depth

A merge order is a full binary tree; each file moves once per merge above it.

Proof

Deepest sibling leaves in an optimum: swap the two smallest there (cost cannot rise) ⇒ some optimum merges them first; contract and induct.

Complexity · mistakes

n − 1 rounds × O(log n) ⇒ O(n log n); O(n) space.

  • Sorting once and merging left to right is not optimal.
  • Use 64-bit sums.
  • One symbol ⇒ code “0”.

Two-mark self-test

  1. What is a priority queue? Give min-heap operation costs.
    A collection supporting insert and remove-min (or max). Binary heap: peek O(1), push/pop O(log n), build O(n).
  2. State the greedy rule for the optimal merge pattern.
    Repeatedly merge the two smallest files and put the result back, until one file remains.
  3. Why does the optimal merge pattern need a heap?
    Each merge creates a new file size that competes with the remaining ones; a heap gives the two smallest in O(log n).
  4. Define a prefix code.
    A code in which no codeword is a prefix of another, so any bit string decodes uniquely.
  5. Write the cost formula of a merge tree / code tree.
    Σ wᵢ · depth(i) over leaves i.
