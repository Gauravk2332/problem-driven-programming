Chapter 01 / 11

Recall: sort once, or keep choosing?

In Lectures 13–15 the greedy order was fixed in advance: sort by ratio, finish time or profit, then scan. Some problems are different: each choice creates a new candidate that must compete with the rest. Re-sorting after every step would cost O(n log n) each time.

A priority queue solves this. A binary min-heap stores items so that the smallest is always at the root.

OperationBinary heap cost
Look at the minimumO(1)
Remove the minimum (pop)O(log n)
Insert (push)O(log n)
Build from n itemsO(n)

In Python use heapq; in C++ priority_queue with greater<> for a min-heap; in Java PriorityQueue (a min-heap by default).

A min-heap holds 1,000 numbers. Roughly how many steps does removing the minimum take?

Chapter 02 / 11

Merging five sorted files

Five sorted files have 20, 30, 10, 5 and 30 records. Merging two sorted files of sizes a and b costs a + b record moves and produces one file of size a + b. Merge pairs until one file remains.

Think first

Does the order of merging matter? Try merging in the given order (20+30, then +10, …) and compute the total cost.

Two orders compared
Left to right: 20+30=50, 50+10=60, 60+5=65, 65+30=95; total 50+60+65+95 = 270.
Always merging the two smallest: 5+10=15, 15+20=35, 30+30=60, 35+60=95; total 15+35+60+95 = 205.

The order matters a lot. The greedy rule "merge the two smallest files" needs the two smallest after every merge, and the merged file is a new candidate: a job for a min-heap.

Cost as a tree. Draw each merge as a node with the two merged files as children. A file's records are moved once for every merge above it, so total cost = Σ (size × depth). For this example: 5 and 10 at depth 3, 20 at depth 2, both 30s at depth 2: 5·3 + 10·3 + 20·2 + 30·2 + 30·2 = 205.

Chapter 05 / 11

Why merging the two smallest is optimal

Exchange argument on the merge tree

Any merge order is a full binary tree whose leaves are the files; cost = Σ size × depth.

  1. In an optimal tree, take a deepest internal node; its two children are leaves at maximum depth.
  2. Swap the two smallest files into those two deepest positions. Moving a smaller size deeper and a larger size shallower never increases Σ size × depth.
  3. So some optimal tree merges the two smallest files first (greedy-choice property).
  4. Replace those two leaves by one leaf of their combined size: the remaining problem is the same kind with n − 1 files, and its optimum plus the first merge is optimal (optimal substructure).

By induction, always merging the two smallest is optimal.

Chapter 06 / 11

Huffman coding: the same idea for compression

A text file uses six letters with these frequencies (in thousands): a 45, b 13, c 12, d 16, e 9, f 5. A fixed-length code needs 3 bits per letter: 300 thousand bits. Can a variable-length code do better?

A prefix code gives each letter a bit string such that no code is a prefix of another, so a bit stream decodes in exactly one way. Prefix codes correspond to binary trees: left edge = 0, right edge = 1, letters at the leaves. The encoded length is Σ frequency × depth: exactly the merge-cost formula.

Huffman's algorithm therefore merges the two least frequent subtrees, again and again, with a min-heap.

Chapter 07 / 11

From the rule to code

Both algorithms are the same loop: pop two, push their sum. Huffman additionally keeps the subtree so it can read the codes from the final tree. A counter breaks ties so the output is reproducible in all three languages.

Python · heap_greedy.py

# Priority-queue greedy: optimal merge pattern and Huffman coding (Lecture 16)
import heapq


def optimal_merge(sizes):
    """Repeatedly merge the two smallest files. Returns (total cost, merge log)."""
    heap = list(sizes)
    heapq.heapify(heap)
    total, log = 0, []
    while len(heap) > 1:
        a, b = heapq.heappop(heap), heapq.heappop(heap)
        total += a + b
        log.append(f"{a}+{b}={a + b}")
        heapq.heappush(heap, a + b)
    return total, log


def huffman(freq):
    """freq: dict symbol -> positive count. Returns dict symbol -> bit string."""
    heap, counter = [], 0
    for sym in sorted(freq):                      # fixed order makes ties reproducible
        heap.append((freq[sym], counter, sym))
        counter += 1
    heapq.heapify(heap)
    if len(heap) == 1:                             # one symbol still needs one bit
        return {heap[0][2]: "0"}
    while len(heap) > 1:
        f1, _, left = heapq.heappop(heap)          # smaller subtree gets bit 0
        f2, _, right = heapq.heappop(heap)
        heapq.heappush(heap, (f1 + f2, counter, (left, right)))
        counter += 1
    codes = {}

    def walk(node, prefix):
        if isinstance(node, tuple):
            walk(node[0], prefix + "0")
            walk(node[1], prefix + "1")
        else:
            codes[node] = prefix

    walk(heap[0][2], "")
    return codes


if __name__ == "__main__":
    total, log = optimal_merge([20, 30, 10, 5, 30])
    print(", ".join(log), f"| total {total}")
    freq = {"a": 45, "b": 13, "c": 12, "d": 16, "e": 9, "f": 5}
    codes = huffman(freq)
    print(" ".join(f"{s}:{codes[s]}" for s in sorted(codes)),
          f"| bits {sum(freq[s] * len(codes[s]) for s in freq)}")

C++ · heap_greedy.cpp

// Priority-queue greedy: optimal merge pattern and Huffman coding (Lecture 16)
#include <functional>
#include <iostream>
#include <map>
#include <memory>
#include <queue>
#include <string>
#include <tuple>
#include <vector>
using namespace std;

// Repeatedly merge the two smallest files.
long long optimalMerge(const vector<long long>& sizes, string& log) {
    priority_queue<long long, vector<long long>, greater<long long>> heap(sizes.begin(), sizes.end());
    long long total = 0;
    log.clear();
    while (heap.size() > 1) {
        long long a = heap.top(); heap.pop();
        long long b = heap.top(); heap.pop();
        total += a + b;
        log += (log.empty() ? "" : ", ") + to_string(a) + "+" + to_string(b) + "=" + to_string(a + b);
        heap.push(a + b);
    }
    return total;
}

struct Node { char sym; shared_ptr<Node> left, right; };

void walk(const shared_ptr<Node>& n, const string& prefix, map<char, string>& codes) {
    if (!n->left) { codes[n->sym] = prefix; return; }
    walk(n->left, prefix + "0", codes);
    walk(n->right, prefix + "1", codes);
}

map<char, string> huffman(const map<char, long long>& freq) {
    using Entry = tuple<long long, int, shared_ptr<Node>>;   // (frequency, tie-break order, subtree)
    auto cmp = [](const Entry& a, const Entry& b) {
        return tie(get<0>(a), get<1>(a)) > tie(get<0>(b), get<1>(b));
    };
    priority_queue<Entry, vector<Entry>, decltype(cmp)> heap(cmp);
    int counter = 0;
    for (auto& [s, f] : freq) heap.push({f, counter++, make_shared<Node>(Node{s, nullptr, nullptr})});
    map<char, string> codes;
    if (heap.size() == 1) { codes[get<2>(heap.top())->sym] = "0"; return codes; }  // one symbol: one bit
    while (heap.size() > 1) {
        auto [f1, c1, left] = heap.top(); heap.pop();         // smaller subtree gets bit 0
        auto [f2, c2, right] = heap.top(); heap.pop();
        heap.push({f1 + f2, counter++, make_shared<Node>(Node{0, left, right})});
    }
    walk(get<2>(heap.top()), "", codes);
    return codes;
}

int main() {
    string log;
    long long total = optimalMerge({20, 30, 10, 5, 30}, log);
    cout << log << " | total " << total << "\n";
    map<char, long long> freq = {{'a', 45}, {'b', 13}, {'c', 12}, {'d', 16}, {'e', 9}, {'f', 5}};
    auto codes = huffman(freq);
    long long bits = 0;
    string out;
    for (auto& [s, c] : codes) { out += (out.empty() ? "" : " ") + string(1, s) + ":" + c; bits += freq[s] * (long long)c.size(); }
    cout << out << " | bits " << bits << "\n";
}

Java · HeapGreedy.java

// Priority-queue greedy: optimal merge pattern and Huffman coding (Lecture 16)
import java.util.*;

public class HeapGreedy {
    // Repeatedly merge the two smallest files.
    static long optimalMerge(long[] sizes, StringJoiner log) {
        PriorityQueue<Long> heap = new PriorityQueue<>();
        for (long s : sizes) heap.add(s);
        long total = 0;
        while (heap.size() > 1) {
            long a = heap.poll(), b = heap.poll();
            total += a + b;
            log.add(a + "+" + b + "=" + (a + b));
            heap.add(a + b);
        }
        return total;
    }

    record Node(long freq, int order, char sym, Node left, Node right) {}

    static void walk(Node n, String prefix, Map<Character, String> codes) {
        if (n.left() == null) { codes.put(n.sym(), prefix); return; }
        walk(n.left(), prefix + "0", codes);
        walk(n.right(), prefix + "1", codes);
    }

    static Map<Character, String> huffman(TreeMap<Character, Long> freq) {
        // ordered by frequency, then creation order, so ties are reproducible
        PriorityQueue<Node> heap = new PriorityQueue<>(
                Comparator.comparingLong(Node::freq).thenComparingInt(Node::order));
        int counter = 0;
        for (var e : freq.entrySet()) heap.add(new Node(e.getValue(), counter++, e.getKey(), null, null));
        Map<Character, String> codes = new TreeMap<>();
        if (heap.size() == 1) { codes.put(heap.peek().sym(), "0"); return codes; }  // one symbol: one bit
        while (heap.size() > 1) {
            Node left = heap.poll(), right = heap.poll();      // smaller subtree gets bit 0
            heap.add(new Node(left.freq() + right.freq(), counter++, '\0', left, right));
        }
        walk(heap.poll(), "", codes);
        return codes;
    }

    public static void main(String[] args) {
        StringJoiner log = new StringJoiner(", ");
        long total = optimalMerge(new long[]{20, 30, 10, 5, 30}, log);
        System.out.println(log + " | total " + total);
        TreeMap<Character, Long> freq = new TreeMap<>(Map.of('a', 45L, 'b', 13L, 'c', 12L, 'd', 16L, 'e', 9L, 'f', 5L));
        Map<Character, String> codes = huffman(freq);
        StringJoiner out = new StringJoiner(" ");
        long bits = 0;
        for (var e : codes.entrySet()) {
            out.add(e.getKey() + ":" + e.getValue());
            bits += freq.get(e.getKey()) * e.getValue().length();
        }
        System.out.println(out + " | bits " + bits);
    }
}

Output (identical in all three languages):

5+10=15, 15+20=35, 30+30=60, 35+60=95 | total 205
a:0 b:101 c:100 d:111 e:1101 f:1100 | bits 224

Each of the n − 1 rounds does two pops and one push: O(n log n) time, O(n) heap space. Copy and run it locally; this website shows code but does not execute it.

  • One symbol: the tree is a single leaf; give it the code "0" so it still uses one bit.
  • Overflow: sums of sizes can exceed 32 bits; use 64-bit integers.
  • Sorting once is not enough: merged sizes must re-enter the competition, which is why a heap (or two queues, if the input is pre-sorted) is needed.

Chapter 08 / 11

Recognising priority-queue greedy problems

Reach for a heap when the greedy rule is "take the smallest (or largest) currently available", and the set of available items changes as you go.

ProblemHeap holdsGreedy step
Optimal merge / connect ropesFile or rope sizesCombine the two smallest
Huffman codingSubtrees by frequencyCombine the two least frequent
Room allocation (Lecture 17)Finish times of roomsReuse the room that frees earliest
Dijkstra / Prim (Lecture 18)Tentative distances / edge costsSettle the closest vertex
Halve the largest number to reduce a sumCurrent values (max-heap)Halve the largest

Common confusions: sorting the input once and merging left to right (cost 270 in our example) is a different, worse algorithm; Huffman codes are not unique, but their total length is; a max-heap is needed when the rule picks the largest.
