SPT (one machine, all ready at 0)

Minimise Σ Cᵢ (≡ average completion / waiting). Rule: shortest processing time first.

Σ Cᵢ = n·t₁ + (n−1)·t₂ + … + 1·tₙ

SPT example

JobP2P4P1P3
t1234
start0136
C13610

Σ C = 20; average waiting 2.5. (A6 B2 C4 → B, C, A: 20.)

SPT proof

Adjacent x, y with tₓ > tᵧ: swapping saves tₓ − tᵧ, others unchanged ⇒ optimum has no inversions ⇒ SPT. Weighted: sort by tᵢ/wᵢ (Smith).

Interval partitioning

sort by start; heap of (finish, room)
for [s, f): if heap.min ≤ s: reuse
  else open new room; push (f, room)

Example

A[9,11) B[9,13) C[9,11) D[11,14) E[11,13) F[13,15) G[14,16) H[14,16): R1 = A, D, H; R2 = B, F; R3 = C, E, G ⇒ 3 rooms = depth.

Proof · complexity

New room k opened at s ⇒ k − 1 rooms busy at s ⇒ k intervals overlap ⇒ depth ≥ k ⇒ optimal. Both algorithms O(n log n).

Mistakes · full marks

  • Makespan is order-independent; Σ C is not.
  • Rooms: sort by start, not finish.
  • Half-open: reuse if finish ≤ start.

Two-mark self-test

  1. State the SPT rule and its objective.
    Run jobs in non-decreasing processing time; it minimises the sum (and average) of completion and waiting times when all jobs are ready at time 0.
  2. Why does job order not affect the makespan on one machine?
    The last job always finishes at the sum of all lengths, whatever the order.
  3. Define the depth of a set of intervals.
    The maximum number of intervals that contain a common point (alive at the same moment).
  4. State the interval partitioning rule.
    Sort by start; assign each interval to a room that is free by its start (earliest-free via a min-heap); open a new room only if none is free.
  5. Give the complexity of interval partitioning.
    O(n log n): sorting plus n heap operations of O(log n).
