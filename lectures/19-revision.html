Key definitions

DP
Write the answer in terms of smaller subproblems (a recurrence) and store each subproblem's answer so it is solved once.
State
The information that fixes one subproblem, e.g. n in F(n), or (vertex, fuel left).
Base case
An answer known without smaller states, e.g. F(0) = 0.
Transition
The rule linking a state to smaller states (the recurrence).
Overlap
The same subproblem is needed more than once.
Optimal substructure
An optimal solution is built from optimal solutions of subproblems.

Bellman's principle of optimality

In an optimal sequence of decisions, whatever the first decision is, the remaining decisions are optimal for the state it leads to.

Replacement argument: if any remaining part could be improved, swapping it in would improve the whole solution, which contradicts “optimal”.

Top-down vs bottom-up

Top-down: start at the answer, recurse, store each result in a memo; solves only the states needed, but deep recursion can overflow the stack. Bottom-up: start at the base cases and fill the table with loops in dependency order; no recursion. Same states, same recurrence, same answer.

Is it a DP problem? Ask four questions

  1. Is there a smaller version of the same problem?
  2. Do smaller answers combine into this one?
  3. Do different choices reach the same states?
  4. Are there few enough states to store?

Common mistakes

  • “DP means a 2-D table.” No: Fibonacci needs only two variables.
  • “Minimum/maximum, so DP.” Keywords are clues; justify with states and a recurrence.
  • “Optimal substructure proves greedy works.” Greedy also needs its choice to be safe.
  • State too small: a route with a fuel limit needs (place, fuel), not just place.
  • Calls vs states: F(5) makes 15 calls but has 6 states.

Writing a full-marks answer

Define the state in words → base cases and recurrence → table filled in order → final answer → time and space.
