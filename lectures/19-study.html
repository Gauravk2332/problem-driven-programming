Chapter 01 / 12

Before learning DP

You do not need to know memoization or tabulation yet: this lecture introduces both briefly, and Lecture 20 develops them. You do need to recognize three ideas: recursion, greedy choice and the amount of work an algorithm performs.

Recursion in ordinary language

A recursive function asks a smaller version of itself for an answer. It must eventually reach a question that it can answer directly. For example, to find the sum of integers from 1 to 4, ask for the sum up to 3 and add 4; the sum up to 0 is 0.

S(4) = 4 + S(3)
S(0) = 0

The base case stops recursion. The recurrence specifies how the larger answer depends on smaller answers. In this example each state is visited once, so there is no duplicated work to save.

Greedy and complexity

A greedy algorithm commits to a locally attractive choice. It needs a correctness proof: a locally attractive choice may not give the best final result. Time complexity describes how the amount of computation grows as input size increases; it is not a stopwatch reading.

Chapter 02 / 12

Why do we need DP?

Suppose your friend asks you for 17 × 23. You work it out: 391. Another friend asks the identical question. Would you multiply again, or remember your previous answer?

A computer can make exactly this kind of mistake. It may solve a small problem, forget its answer and later solve the identical problem again.

Start with a staircase

You stand at step 0 and want to reach step 4. You can move one or two steps at a time. Count distinct ordered move sequences.

Think first

Try listing the possibilities before reading the solution.

See the five possibilities

1+1+1+1; 1+1+2; 1+2+1; 2+1+1; 2+2. Notice that 1+2+1 and 2+1+1 are different sequences.

Instead of listing sequences for every new staircase, consider the last move. A route to step 4 ends with either a move from step 3 or a move from step 2. These cases are disjoint, so the counts add. Store each smaller count and use it again.

W(0)=1; W(1)=1
W(n)=W(n−1)+W(n−2)

W(0)=1 counts the empty sequence: there is one way to stay where you already are.

Find W(3) and W(4), then add them.

Chapter 03 / 12

Discover repeated work in Fibonacci

Fibonacci is the smallest clear example of repeated computation. It computes a value; nothing is being minimized. Its rule is simple: add the previous two values.

F(0)=0, F(1)=1
F(n)=F(n−1)+F(n−2)

To compute F(5), a direct recursive function asks for F(4) and F(3). But the F(4) branch also asks for F(3). Those are the same mathematical question.

Think first

Predict how many times F(3) will occur before viewing the whole tree.

Chapter 04 / 12

Remember answers instead of recomputing

Storing a result is useful only if we know which question that result answers. In Fibonacci, the single integer n uniquely identifies the question F(n). We call that integer the state.

In a table, the index denotes the state and the contents store its answer. Begin with answers that are already known: F(0)=0 and F(1)=1. Now every next value can be built from two saved answers.

Think first

Before pressing Next in the lab, predict the next number and identify the two cells it uses.

Why is this faster?

Naive Fibonacci recursion performs the same additions many times. A bottom-up calculation performs one addition for each n from 2 to the target. Use the slider to see how the two work counts grow.

For n = 10, naive recursion does 88 additions; the table does 9. Naive recursion takes exponential time. The table takes O(n) time and O(n) storage.

Top-down and bottom-up

Every DP can be computed in two ways. Both use the same states and the same recurrence and give the same answer; they differ only in the order in which states are solved.

Top-down (memoization)Bottom-up (tabulation)
Starts fromThe question you want: F(n)The base cases: F(0) and F(1)
Stored byA memo keyed by nA table dp[0…n], filled in increasing n
How it runsRecursion. A state is solved the first time it is asked for, then read from the cacheLoops. Every state is filled once, after the states it depends on
Which statesOnly the states the final answer actually needsUsually every state in the table
Extra costA call stack as deep as the longest chain of calls; very deep inputs can overflow itNo recursion; the table can often be shrunk to one or two rows
Choose it whenThe fill order is awkward, or many states are never neededThe fill order is clear and most states are needed; this is the safer default for large inputs

Top-down is ordinary recursion plus a memo: before computing F(n), check whether it is already stored. Bottom-up is the loop you have already seen. For Fibonacci both take O(n) time; top-down also uses O(n) stack space. Lecture 20 develops both methods properly, including how to design the state and save memory.

Python · fib_two_ways.py

memo = {}


def fib_top_down(n):
    # Top-down: start from n, recurse, store each answer the first time
    if n <= 1:
        return n
    if n not in memo:
        memo[n] = fib_top_down(n - 1) + fib_top_down(n - 2)
    return memo[n]


def fib_bottom_up(n):
    # Bottom-up: fill answers from the base cases upward
    if n <= 1:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]


print(fib_top_down(10), fib_bottom_up(10))   # 55 55
print(fib_top_down(90) == fib_bottom_up(90))  # True

C++ · fib_two_ways.cpp

#include <iostream>
#include <vector>
using namespace std;

vector<long long> memo;  // memo[i] = -1 means "not computed yet"

// Top-down: start from n, recurse, store each answer the first time
long long fibTopDown(int n) {
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];
    return memo[n] = fibTopDown(n - 1) + fibTopDown(n - 2);
}

// Bottom-up: fill answers from the base cases upward
long long fibBottomUp(int n) {
    if (n <= 1) return n;
    vector<long long> dp(n + 1);
    dp[0] = 0;
    dp[1] = 1;
    for (int i = 2; i <= n; i++) dp[i] = dp[i - 1] + dp[i - 2];
    return dp[n];
}

int main() {
    memo.assign(91, -1);
    cout << fibTopDown(10) << " " << fibBottomUp(10) << "\n";  // 55 55
    cout << (fibTopDown(90) == fibBottomUp(90)) << "\n";       // 1
}

        return n

Chapter 05 / 12

The two fundamental properties

1. Overlapping subproblems: will saving help?

Two different branches of a solution reach an identical state. If we save its answer, we need not solve it again. Fibonacci has overlap. In ordinary merge sort, the two recursive halves are different ranges, so this kind of caching usually adds no benefit.

2. Optimal substructure: can smaller optimal answers build a bigger optimum?

Suppose a journey from A to C must pass B, and you are minimizing distance with no additional constraints. A shortest A–C journey via B cannot contain an unnecessarily long A–B segment; replacing it with a shorter feasible segment would improve the journey.

In optimization problems this is called optimal substructure. In counting problems, such as the staircase, the corresponding requirement is a correct decomposition of the count, not a minimum or maximum.

PropertyQuestion to ask
OverlapDo we solve the same question repeatedly?
Optimal substructureCan a global optimum be built using optimal answers to correctly defined smaller questions?

These are related but different. Overlap explains a possible efficiency gain; optimal substructure explains how a valid optimization recurrence can work. A fast algorithm still needs a manageable number of states and a cheap way to combine them.

Chapter 06 / 12

Understand Bellman's principle

Think of being halfway through a trip. If reaching your current location has already cost 20, and the journey rules from here onward are unchanged, that 20 is already spent. To minimize total cost, choose the least-cost remaining route.

Formal statement: given the state reached after an initial decision, the remaining decisions in an optimal policy must be optimal for that state. (A policy is just the rule that says which decision to take in each state.) The state must include all information that affects future choices.

Test the idea on a small graph

All edges below are undirected with positive weights. Choose each simple A-to-D route in the explorer.

Route A→B→D has cost 2+3=5. The other three simple routes cost 9 each. If there were a cheaper feasible continuation from B, replacing the B→D part would improve the allegedly best route. That contradiction explains the principle.

When is location not enough?

If a car has a remaining fuel budget, arriving at B with 2 litres and arriving at B with 10 litres are not necessarily the same subproblem. The state might need both position and fuel. Caching just by location could return an infeasible answer.

Chapter 07 / 12

Why greedy can fail

Imagine paying exactly 6 using unlimited coins of denominations 1, 3 and 4. The intuitive rule is to use the largest coin that fits. Try it on paper first.

Think first

If your first coin is 4, what remains? Can you do better by starting with 3?

Compare both choices

Largest-first: 4+1+1 uses three coins. Choosing 3+3 uses two coins. One locally attractive choice caused an inferior global result.

Instead of committing to the largest coin, define M(a) as the minimum number of coins that make amount a exactly. Removing one coin c leaves amount a−c. Therefore compare every feasible final coin and take the smallest total count.

M(0)=0
M(a)=1+min M(a−c) over c≤a

Impossible amounts are represented by ∞. Every denomination is a positive integer, and coins are unlimited.

Try these experiments: choose {1,3,4}, amount 6; then choose {3,4}, amount 6, where greedy gets stuck; finally choose {1,3,4}, amount 4, where greedy is optimal. A failure on one input disproves a universal greedy claim, but success on one input does not prove it.

Code it

Both strategies side by side. dp[a] stores the fewest coins for amount a; amounts that cannot be made stay at infinity.

Python · coins.py

INF = float("inf")


def greedy_coins(coins, target):
    # Largest coin first. Fast, but not always optimal.
    count = 0
    for c in sorted(coins, reverse=True):
        count += target // c
        target %= c
    return count if target == 0 else -1


def min_coins(coins, target):
    # dp[a] = fewest coins that make exactly a (INF if impossible)
    dp = [0] + [INF] * target
    for a in range(1, target + 1):
        for c in coins:
            if c <= a and dp[a - c] + 1 < dp[a]:
                dp[a] = dp[a - c] + 1
    return dp[target] if dp[target] != INF else -1


print(greedy_coins([1, 3, 4], 6), min_coins([1, 3, 4], 6))  # 3 2
print(greedy_coins([3, 4], 6), min_coins([3, 4], 6))        # -1 2
print(min_coins([3, 4], 1))                                 # -1 (unreachable)

C++ · coins.cpp

#include <algorithm>
#include <functional>
#include <iostream>
#include <vector>
using namespace std;

const int INF = 1e9;

// Largest coin first. Fast, but not always optimal.
int greedyCoins(vector<int> coins, int target) {
    sort(coins.begin(), coins.end(), greater<int>());
    int count = 0;
    for (int c : coins) {
        count += target / c;
        target %= c;
    }
    return target == 0 ? count : -1;
}

// dp[a] = fewest coins that make exactly a (INF if impossible)
int minCoins(const vector<int>& coins, int target) {
    vector<int> dp(target + 1, INF);
    dp[0] = 0;
    for (int a = 1; a <= target; a++)
        for (int c : coins)
            if (c <= a && dp[a - c] != INF)
                dp[a] = min(dp[a], dp[a - c] + 1);
    return dp[target] == INF ? -1 : dp[target];
}

int main() {
    cout << greedyCoins({1, 3, 4}, 6) << " " << minCoins({1, 3, 4}, 6) << "\n";  // 3 2
    cout << greedyCoins({3, 4}, 6) << " " << minCoins({3, 4}, 6) << "\n";        // -1 2
    cout << minCoins({3, 4}, 1) << "\n";                                         // -1
}

Java · Coins.java

import java.util.Arrays;

public class Coins {
    static final int INF = Integer.MAX_VALUE;

    // Largest coin first. Fast, but not always optimal.
    static int greedyCoins(int[] coins, int target) {
        int[] sorted = coins.clone();
        Arrays.sort(sorted);
        int count = 0;
        for (int i = sorted.length - 1; i >= 0; i--) {
            count += target / sorted[i];
            target %= sorted[i];
        }
        return target == 0 ? count : -1;
    }

    // dp[a] = fewest coins that make exactly a (INF if impossible)
    static int minCoins(int[] coins, int target) {
        int[] dp = new int[target + 1];
        Arrays.fill(dp, INF);
        dp[0] = 0;
        for (int a = 1; a <= target; a++)
            for (int c : coins)
                if (c <= a && dp[a - c] != INF)
                    dp[a] = Math.min(dp[a], dp[a - c] + 1);
        return dp[target] == INF ? -1 : dp[target];
    }

    public static void main(String[] args) {
        System.out.println(greedyCoins(new int[]{1, 3, 4}, 6) + " " + minCoins(new int[]{1, 3, 4}, 6)); // 3 2
        System.out.println(greedyCoins(new int[]{3, 4}, 6) + " " + minCoins(new int[]{3, 4}, 6));       // -1 2
        System.out.println(minCoins(new int[]{3, 4}, 1));                                               // -1
    }
}

The output shows greedy using 3 coins where DP uses 2, and greedy failing outright for {3, 4}. Change the coin set to {1, 2, 5, 10} (Indian coins): greedy and DP now agree. Coin systems where greedy is always optimal are called canonical.

Chapter 08 / 12

Recognize when DP is a good idea

Do not memorize a list of keywords and automatically select DP. Instead, ask what the smaller problem means, how answers combine, whether states repeat and whether the number of distinct states is manageable.

A practical four-question test

  1. Can I describe a smaller version of the same problem?
  2. Can I combine correct smaller answers to solve the current state?
  3. Will different choices often reach identical states?
  4. Can I evaluate the necessary states efficiently?
ProblemReasoning
Binary searchOne smaller interval per step; no repeated states in the standard algorithm.
Merge sortIndependent smaller ranges; divide and conquer.
Unweighted activity selectionEarliest-finish greedy can be proved correct.
Climbing stairsCounts for smaller step numbers are reused.
0/1 KnapsackInclude/exclude alternatives can revisit identical remaining item/capacity states.

Chapter 09 / 12

Common confusions

Check these statements against your understanding before opening their explanations.

“DP means using a two-dimensional array.”

No. An array is a storage representation. Fibonacci needs one dimension, and even two variables can suffice. What matters is a valid recurrence and reuse of state answers.

“Any recursive program becomes faster with DP.”

No. A chain of calls or disjoint subproblems may have no repeat work to eliminate. Saving every answer could add overhead.

“Optimal substructure proves greedy is correct.”

No. Greedy additionally needs the chosen local decision to be safe. The coin counterexample has optimal substructure but largest-first greedy fails.

“Fibonacci is an optimization problem.”

No. It computes a defined sequence value. DP can also count, decide feasibility and compute exact values.

“DP always gives polynomial time.”

No. The number of states or work per state may be exponential. A knapsack table has one column per unit of capacity, so its size grows with the value of the capacity, not with how many digits it has. A capacity of 10⁹ makes the table far too large. This is called pseudo-polynomial time; Lecture 21 returns to it.

Definitions worth remembering

Dynamic Programming
An algorithm design technique that relates smaller states through a recurrence and reuses computed answers.
State
Information sufficient to determine a subproblem and its answer.
Overlapping subproblems
Identical states occur in different branches of a decomposition.
Optimal substructure
An optimal solution can be constructed from optimal answers to appropriately defined subproblems.
Bellman's principle of optimality
In an optimal sequence of decisions, whatever the first decision is, the remaining decisions are optimal for the state it leads to.
Base case
A known answer that requires no smaller states.

Exam questions with model answers

For full marks: define the state in words, write the base cases and recurrence, show the table in order, state the final answer, and give the time and space complexity.

Short answers 2 marks each

A1 · Define DP2 marks

Define dynamic programming.

Model answer

Dynamic programming solves a problem by writing its answer in terms of answers to smaller subproblems (a recurrence) and storing each subproblem’s answer so that it is computed only once.

Marks: 1 for smaller subproblems with a recurrence, 1 for storing and reusing answers.

A2 · Overlapping subproblems2 marks

What are overlapping subproblems? Give an example.

Model answer

The same subproblem is needed more than once while solving a problem. Example: computing F(5) recursively computes F(3) twice and F(2) three times.

Marks: 1 for the definition, 1 for a correct example.

A3 · Principle of optimality2 marks

State Bellman’s principle of optimality.

Model answer

In an optimal sequence of decisions, whatever the first decision is, the remaining decisions must be optimal for the state that the first decision leads to.

Marks: 2 for a complete statement; 1 if the idea of “the state reached” is missing.

A4 · Greedy counterexample2 marks

Coins {1, 3, 4} are available in unlimited supply. Show that “take the largest coin that fits” does not give the fewest coins for amount 6.

Model answer

Greedy takes 4, then 1, then 1: three coins. But 3 + 3 uses only two coins. So the greedy choice is not optimal for this coin set.

Marks: 1 for the greedy result, 1 for the better solution.

A5 · D&C versus DP2 marks

Give one difference between divide and conquer and dynamic programming, with an example of each.

Model answer

Divide and conquer splits a problem into separate subproblems that do not repeat, such as the two halves in merge sort. DP is used when subproblems repeat, so their answers are stored and reused, as in Fibonacci.

Marks: 1 for the difference, 1 for the two examples.

Medium answers 5 marks each

B1 · Recursion tree5 marks

Draw the recursion tree for F(5) computed by the naive recursive function. Count the total calls and the distinct subproblems, and explain how DP reduces the work.

Model answer

F(5) calls F(4) and F(3); every node F(k) with k ≥ 2 has children F(k−1) and F(k−2), and F(1), F(0) are leaves.

StateF(5)F(4)F(3)F(2)F(1)F(0)

B2 · Coin change table5 marks

Coins {1, 4, 6} are available in unlimited supply. Using DP, find the fewest coins needed to make 8. Show the table and compare with greedy.

Model answer

Let dp[a] be the fewest coins that make amount a. Then dp[0] = 0 and dp[a] = 1 + min(dp[a − c]) over coins c ≤ a.

a012345678
dp[a]012312122

dp[8] = 1 + min(dp[7], dp[4], dp[2]) = 1 + min(2, 1, 2) = 2, using 4 + 4. Greedy takes 6 + 1 + 1 = 3 coins, so greedy is not optimal here.

Marks: 1 for the recurrence, 3 for the correct table, 1 for the answer and the greedy comparison.

C1 · Properties and Bellman’s principle10 marks

Explain the two properties a problem needs for dynamic programming. For the undirected graph with edges A–B = 2, A–C = 4, B–C = 2, B–D = 3 and C–D = 5, find the shortest path from A to D and use it to explain Bellman’s principle with a replacement argument.

Model answer
  1. Overlapping subproblems: the same subproblem is needed many times, so storing its answer saves time (Fibonacci).
  2. Optimal substructure: an optimal solution is built from optimal solutions of its subproblems (shortest paths).
  3. Paths from A to D: A–B–D = 2 + 3 = 5; A–C–D = 4 + 5 = 9; A–B–C–D = 2 + 2 + 5 = 9; A–C–B–D = 4 + 2 + 3 = 9. Shortest: A–B–D, cost 5.
  4. Principle: after the first decision (go to B), the rest of the route must be the best route from B to D.
  5. Check: from B the options are B–D = 3 and B–C–D = 7, so B–D is best. From A to B the options are 2 and A–C–B = 6, so A–B is best.
  6. Replacement argument: if the part B–D could be replaced by something cheaper, the whole A–D route would cost less than 5, contradicting that it is the shortest. So every part of a shortest path is itself shortest.

Marks: 2 + 2 for the two properties, 2 for listing paths and costs, 1 for the statement, 2 for the replacement argument, 1 for the conclusion.

C2 · Climbing stairs end to end10 marks

A staircase has n steps. You may climb 1 or 2 steps at a time. (a) Define a DP state, base cases and recurrence. (b) Find the number of ways for n = 6. (c) Compare the time of naive recursion with the table method. (d) Write bottom-up pseudocode.

Model answer
  1. (a) W(i) = number of ordered ways to reach step i. W(0) = 1 (the empty sequence) and W(1) = 1. The last move is either 1 step (from i − 1) or 2 steps (from i − 2); these cases do not overlap and cover everything, so W(i) = W(i − 1) + W(i − 2).
  2. (b) W(0…6) = 1, 1, 2, 3, 5, 8, 13. So there are 13 ways.
  3. (c) Naive recursion recomputes the same W(i) many times, giving exponential time, O(2n). The table computes each W(i) once: O(n) time and O(n) space, or O(1) space if only the last two values are kept.
  4. (d)
W[0] = 1; W[1] = 1
for i = 2 to n:
  W[i] = W[i − 1] + W[i − 2]
return W[n]

Marks: 3 for (a), 2 for (b), 2 for (c), 3 for (d).
