Section 01

Why Dynamic Programming?

Start with a problem, not a definition

Classroom challenge · Climbing stairs

You are at the bottom of a staircase with four steps. Each move climbs exactly one or two steps. How many different ordered sequences of moves take you to the top?

Reveal solution

1+1+1+1, 1+1+2, 1+2+1, 2+1+1, 2+2.

Listing all possible paths works for four steps, but for a much larger staircase the number of sequences grows rapidly. What if we count ways to reach each smaller step once, then reuse those counts?

W(0) = 1, W(1) = 1
W(n) = W(n−1) + W(n−2), n ≥ 2

Look at the last move: it is either one step (from step n − 1) or two steps (from step n − 2). The two cases never overlap and together cover every way, so we add them. That is the central DP idea: answer a problem using answers to smaller versions of it.

From brute force to reuse

A greedy algorithm makes the choice that looks best right now and never reconsiders it. That is fast when the choice is safe, but some problems need several choices compared. A plain recursive solution can also end up solving the same smaller problem again and again.

Definition

Dynamic Programming (DP) is an algorithm design technique that expresses a problem in terms of subproblems, evaluates their answers through a recurrence, and reuses those answers instead of solving the same state repeatedly.

DP is used to find a minimum or maximum, to count ways, and to answer yes/no questions. Its speed comes from never solving the same subproblem twice.

Describe a smaller instance with a state.

02

Solve

Use the base cases and the recurrence.

03

Store results when the same state is needed again.

Important: a state is the information that pins down one subproblem, such as “step i” or “amount a”. Its answer can be a number, a yes/no value or a best cost. A table is only where answers are stored; filling a table does not by itself make an algorithm DP.
Learning objectives: recognize repeated subproblems; explain optimal substructure and Bellman's principle of optimality; distinguish greedy, divide and conquer and DP; identify suitable problems.

Section 02

Fibonacci: the cost of repetition

The Fibonacci sequence begins 0, 1, 1, 2, 3, 5, 8, … . A recursive function directly follows this definition:

F(0) = 0, F(1) = 1
F(n) = F(n−1) + F(n−2), n ≥ 2
Recursive pseudocode
fib(n):
  if n ≤ 1: return n
  return fib(n−1) + fib(n−2)
For F(5), naive recursion makes 15 calls but there are only 6 different questions, F(0) to F(5). The number of calls grows roughly like 1.6n, so the time is exponential; we write O(2n).

Worked example: F(5)

StateF(5)F(4)F(3)F(2)F(1)F(0)
Calls112353

So 9 of the 15 calls (15 − 6) repeat work already done. Repeating F(3) is worse than repeating F(1), because F(3) brings its whole subtree with it.

Go deeper: exactly how many calls? (proof)

Let C(n) count every call, including the first one and the base cases. Each call with n ≥ 2 makes exactly two more calls.

C(0) = C(1) = 1
C(n) = 1 + C(n−1) + C(n−2)
C(n) = 2F(n+1) − 1

The last line follows by induction using the Fibonacci recurrence. Each call does a constant amount of work, so the running time grows like C(n). More precisely it is Θ(φn), where φ ≈ 1.618 is the golden ratio. At most n calls are waiting on the stack at once, so the extra space is only O(n).

Section 03

Fundamental properties of DP

Overlapping subproblems

Subproblems overlap when the same state must be solved more than once during a decomposition. Storing a result allows later requests for that state to reuse it.

One call tree, many shared states

The recursion tree draws one box per call. Merge all boxes with the same label and you get one box per state. This picture is a dependency graph (a DAG); an arrow means “needs the answer of”.

Each state is computed once, so the time is O(n) and the table uses O(n) space. Keeping only the last two values cuts the extra space to O(1).

Fibonacci approachTimeAuxiliary space
Naive recursionO(2n)O(n) for the call stack
Store all valuesO(n)O(n)
Keep only two valuesO(n)O(1)
Complexity rule of thumb

DP time ≈ (number of states) × (work per state). Fibonacci has n + 1 states and each needs one addition, so it takes O(n) time. The table stores one answer per state, so the space is O(number of states).

Go deeper: the precise statement

For a DP whose states form no cycle and whose stored answers can be read in constant time, the total work is the sum of the work done for each distinct state. If there are S states and each needs at most K steps, the time is O(SK), and storing one answer per state takes O(S) space.

One subtlety: Fibonacci numbers grow quickly, so for very large n the additions themselves stop being constant-time. For normal exam and programming sizes this is ignored.

Optimal substructure

An optimization problem has optimal substructure when an optimal solution can be built from optimal solutions of appropriately defined smaller subproblems.

Overlapping subproblemsOptimal substructure
Repeated statesOptimal solutions of smaller states
Explains why reuse can save timeExplains why a recurrence can construct an optimum
Example: FibonacciExample: shortest path

Fibonacci just computes a value; nothing is minimized or maximized, so “optimal” does not apply to it. For counting problems like the staircase, what we need instead is a correct way to split the count into smaller counts.

Remember: optimal substructure is why the recurrence gives the correct best answer; overlapping subproblems are why storing answers saves time. DP pays off when both hold.

Section 04

Bellman's Principle of Optimality

An optimal sequence of decisions has the property that, after the first decision, the remaining decisions must form an optimal policy for the state reached by that decision.

In plain words: if a route is the best route, then from any point on it, the rest of the route is also the best route from that point. (A policy is just the rule for which decision to take in each state.)

Think of this as a road map: roads work in both directions and every road has a positive length. Pick each route from A to D and compare the totals.

Candidate pathCost
A → B → D2 + 3 = 5 (minimum)
A → C → D4 + 5 = 9
A → B → C → D2 + 2 + 5 = 9
A → C → B → D4 + 2 + 3 = 9

The best route is A → B → D, cost 5. Its pieces are also best: A → B costs 2 (the other way, A → C → B, costs 6), and B → D costs 3 (B → C → D costs 7). If either piece could be made cheaper, the whole route would cost less than 5, which is impossible because 5 is the minimum.

Why must the remainder be optimal?

Replacement argument: suppose a best solution reaches some state v, but the rest of it is not the best possible from v. Swap in the better rest. The whole solution gets better, but it was already the best, which is a contradiction. So the rest must be the best from v. (This needs the state to capture everything that limits the future, which is why the fuel example below matters.)

Go deeper: solve a multistage route by working backwards

This directed graph has four stages. A delivery starts at A and must reach T using the shown edges. Edge costs add; all future options depend only on the current vertex. The objective is minimum total cost.

Define J(v) as the minimum remaining cost from vertex v to T. If we choose an outgoing edge v→u, we pay w(v,u), then still need an optimal solution from u.

J(T) = 0
J(v) = min over outgoing edges (v,u) of [w(v,u) + J(u)]
StateCompare alternativesBest costNext vertex
TAlready at destination0—
D3 + 03T
E5 + 05T
Bmin(9+3, 4+5)9E
Cmin(1+3, 2+5)4D
Amin(2+9, 5+4)9C

Answer: A→C→D→T, cost 5+1+3=9. Greedy choosing the cheapest outgoing edge would take A→B→E→T, cost 2+4+5=11. This demonstrates optimal substructure and shared costs J(D), J(E); it also demonstrates why a safe local choice requires a separate argument. The recurrence works in reverse topological order on this DAG, not blindly on arbitrary cyclic graphs.

The state must hold everything that affects future choices. If a car has a fuel limit, “I am at B” is not enough: arriving at B with 2 litres and with 10 litres are different situations, so the state must be (place, fuel left). Also note: optimal substructure does not make greedy safe. The multistage example above has optimal substructure, yet the cheapest-next-road rule fails.

Section 05

When a greedy choice fails

Given unlimited coins with denominations 1, 3 and 4, make amount 6 using the fewest coins. Greedy selects the largest coin that fits; DP compares the alternatives for each amount.

Worked example: denominations 1, 3, 4; target 6

Derivation: Let dp[a] mean the fewest coins needed to form exactly a. In any valid optimal solution, remove one of its coins c. The remaining amount is a−c and must be formed optimally; otherwise replacing it with a better solution reduces the total coin count. Therefore try all feasible c and choose the minimum.

Greedy choice

411

3 coins · choose the largest that fits.

Optimal choice

33

2 coins · compare possible first choices.

DP finds the optimum by comparing candidates. With these denominations, every non-negative integer amount is reachable.

Amount a0123456
dp[a]0121122
dp[0] = 0
dp[a] = 1 + min(dp[a−c]) over c ∈ {1, 3, 4}, c ≤ a
dp[6] = 1 + min(dp[5], dp[3], dp[2]) = 1 + min(2, 1, 2) = 2

If some amount cannot be made (with coins {3, 4}, amount 1 is impossible), store ∞ for it and never build on it. With m coin types and target A, the table has A + 1 cells and each cell tries m coins, so the time is O(mA) and the space is O(A). Lecture 22 develops the full Coin Change algorithm.

Go deeper: why O(mA) can still be slow

O(mA) depends on the value of A, not on how many digits it has. A target of 109 needs a billion cells. Running times like this are called pseudo-polynomial; Lecture 21 returns to the idea with knapsack.

Section 06

How to identify a DP problem

When you see a problem involving choices, look for these three signals: a valid decomposition, recurring states and a way to construct the required solution from smaller states. For optimization problems, check optimal substructure.

Problem patternExample
Maximum value with constraints0/1 Knapsack
Minimum steps or costCoin Change; Edit Distance
Number of waysClimbing Stairs
Possibility of a targetSubset Sum
Longest valid sequenceLongest Increasing Subsequence
01

Decomposition

Can the original problem be expressed using smaller states?

02

Reuse

Do different choices lead to the same states?

03

Validity

Can correct smaller answers determine the required answer?

Three decisions before choosing DP

Can greedy be proved?

If committing to a local choice is safe, greedy may be simpler.

Do subproblems repeat?

If they are essentially disjoint, divide and conquer may already avoid repeated work.

Can we keep states small?

If each state needs huge history, storing every state may still be impractical.

Optional extension: what changes when activity selection has profits?

Three jobs: A runs from time 0 to 2 and earns 2; B runs from 2 to 4 and earns 2; C runs from 0 to 4 and earns 10. “Earliest finish first” picks A and then B, earning 4. Doing only C earns 10. A greedy rule that was correct for counting jobs fails once jobs have different profits, so a small change to the goal can change which algorithm works.

These are clues, not guarantees: some minimum, maximum or counting problems have simpler greedy, mathematical or other solutions. Always justify the approach.

Section 07

From recurrence to code

A correct recurrence becomes a bottom-up loop with three direct translations, plus one decision about order.

01

State → index

dp[i] holds the answer for state i.

02

Base cases → first cells

Fill the answers that need no smaller state.

03

Recurrence → loop body

Visit states so every dependency is already filled.

Top-down and bottom-up

Every DP can be computed in two ways. Both use the same states and the same recurrence and give the same answer; they differ only in the order in which states are solved.

Top-down (memoization)Bottom-up (tabulation)
Starts fromThe question you want: F(n)The base cases: F(0) and F(1)
Stored byA memo keyed by nA table dp[0…n], filled in increasing n
How it runsRecursion. A state is solved the first time it is asked for, then read from the cacheLoops. Every state is filled once, after the states it depends on
Which statesOnly the states the final answer actually needsUsually every state in the table
Extra costA call stack as deep as the longest chain of calls; very deep inputs can overflow itNo recursion; the table can often be shrunk to one or two rows
Choose it whenThe fill order is awkward, or many states are never neededThe fill order is clear and most states are needed; this is the safer default for large inputs

Top-down is ordinary recursion plus a memo: before computing F(n), check whether it is already stored. Bottom-up is the loop you have already seen. For Fibonacci both take O(n) time; top-down also uses O(n) stack space. Lecture 20 develops both methods properly, including how to design the state and save memory.

Python · fib_two_ways.py

memo = {}


def fib_top_down(n):
    # Top-down: start from n, recurse, store each answer the first time
    if n <= 1:
        return n
    if n not in memo:
        memo[n] = fib_top_down(n - 1) + fib_top_down(n - 2)
    return memo[n]


def fib_bottom_up(n):
    # Bottom-up: fill answers from the base cases upward
    if n <= 1:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]


print(fib_top_down(10), fib_bottom_up(10))   # 55 55
print(fib_top_down(90) == fib_bottom_up(90))  # True

C++ · fib_two_ways.cpp

#include <iostream>
#include <vector>
using namespace std;

vector<long long> memo;  // memo[i] = -1 means "not computed yet"

// Top-down: start from n, recurse, store each answer the first time
long long fibTopDown(int n) {
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];
    return memo[n] = fibTopDown(n - 1) + fibTopDown(n - 2);
}

// Bottom-up: fill answers from the base cases upward
long long fibBottomUp(int n) {
    if (n <= 1) return n;
    vector<long long> dp(n + 1);
    dp[0] = 0;
    dp[1] = 1;
    for (int i = 2; i <= n; i++) dp[i] = dp[i - 1] + dp[i - 2];
    return dp[n];
}

int main() {
    memo.assign(91, -1);
    cout << fibTopDown(10) << " " << fibBottomUp(10) << "\n";  // 55 55
    cout << (fibTopDown(90) == fibBottomUp(90)) << "\n";       // 1
}

Java · FibTwoWays.java

import java.util.Arrays;

public class FibTwoWays {
    static long[] memo = new long[91];  // -1 means "not computed yet"

    // Top-down: start from n, recurse, store each answer the first time
    static long fibTopDown(int n) {
        if (n <= 1) return n;
        if (memo[n] != -1) return memo[n];
        return memo[n] = fibTopDown(n - 1) + fibTopDown(n - 2);
    }

    // Bottom-up: fill answers from the base cases upward
    static long fibBottomUp(int n) {
        if (n <= 1) return n;
        long[] dp = new long[n + 1];
        dp[1] = 1;
        for (int i = 2; i <= n; i++) dp[i] = dp[i - 1] + dp[i - 2];
        return dp[n];
    }

    public static void main(String[] args) {
        Arrays.fill(memo, -1);
        System.out.println(fibTopDown(10) + " " + fibBottomUp(10));  // 55 55

    }
}

Both functions print the same values. Notice that the top-down function is the naive recursion with three extra lines: check the memo, store the answer, return it.

Fibonacci: naive and table

Python · fib.py

def fib_naive(n):
    # Direct translation of the recurrence: exponential time
    if n <= 1:
        return n
    return fib_naive(n - 1) + fib_naive(n - 2)


def fib_table(n):
    # Each state 0..n is solved once, in dependency order: O(n) time
    if n <= 1:
        return n
    dp = [0] * (n + 1)          # dp[i] stores F(i)
    dp[1] = 1                   # base cases: dp[0] = 0, dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]


print(fib_naive(10), fib_table(10))   # 55 55
print(fib_table(90))                  # try fib_naive(35) and compare the wait

Coin change: greedy and DP

Python · coins.py

INF = float("inf")


def greedy_coins(coins, target):
    # Largest coin first. Fast, but not always optimal.
    count = 0
    for c in sorted(coins, reverse=True):
        count += target // c
        target %= c
    return count if target == 0 else -1


def min_coins(coins, target):
    # dp[a] = fewest coins that make exactly a (INF if impossible)
    dp = [0] + [INF] * target
    for a in range(1, target + 1):
        for c in coins:
            if c <= a and dp[a - c] + 1 < dp[a]:
                dp[a] = dp[a - c] + 1
    return dp[target] if dp[target] != INF else -1


print(greedy_coins([1, 3, 4], 6), min_coins([1, 3, 4], 6))  # 3 2
print(greedy_coins([3, 4], 6), min_coins([3, 4], 6))        # -1 2
print(min_coins([3, 4], 1))                                 # -1 (unreachable)

C++ · coins.cpp

#include <algorithm>
#include <functional>
#include <iostream>
#include <vector>
using namespace std;

const int INF = 1e9;

// Largest coin first. Fast, but not always optimal.
int greedyCoins(vector<int> coins, int target) {
    sort(coins.begin(), coins.end(), greater<int>());
    int count = 0;
    for (int c : coins) {
        count += target / c;
        target %= c;
    }
    return target == 0 ? count : -1;
}

// dp[a] = fewest coins that make exactly a (INF if impossible)
int minCoins(const vector<int>& coins, int target) {
    vector<int> dp(target + 1, INF);
    dp[0] = 0;
    for (int a = 1; a <= target; a++)
        for (int c : coins)
            if (c <= a && dp[a - c] != INF)
                dp[a] = min(dp[a], dp[a - c] + 1);
    return dp[target] == INF ? -1 : dp[target];
}

int main() {
    cout << greedyCoins({1, 3, 4}, 6) << " " << minCoins({1, 3, 4}, 6) << "\n";  // 3 2
    cout << greedyCoins({3, 4}, 6) << " " << minCoins({3, 4}, 6) << "\n";        // -1 2
    cout << minCoins({3, 4}, 1) << "\n";                                         // -1
}

Java · Coins.java

import java.util.Arrays;

public class Coins {
    static final int INF = Integer.MAX_VALUE;

    // Largest coin first. Fast, but not always optimal.
    static int greedyCoins(int[] coins, int target) {
        int[] sorted = coins.clone();
        Arrays.sort(sorted);
        int count = 0;
        for (int i = sorted.length - 1; i >= 0; i--) {
            count += target / sorted[i];
            target %= sorted[i];
        }
        return target == 0 ? count : -1;
    }

    // dp[a] = fewest coins that make exactly a (INF if impossible)
    static int minCoins(int[] coins, int target) {
        int[] dp = new int[target + 1];
        Arrays.fill(dp, INF);
        dp[0] = 0;
        for (int a = 1; a <= target; a++)
            for (int c : coins)
                if (c <= a && dp[a - c] != INF)
                    dp[a] = Math.min(dp[a], dp[a - c] + 1);
        return dp[target] == INF ? -1 : dp[target];
    }

    public static void main(String[] args) {
        System.out.println(greedyCoins(new int[]{1, 3, 4}, 6) + " " + minCoins(new int[]{1, 3, 4}, 6)); // 3 2
        System.out.println(greedyCoins(new int[]{3, 4}, 6) + " " + minCoins(new int[]{3, 4}, 6));       // -1 2
        System.out.println(minCoins(new int[]{3, 4}, 1));                                               // -1
    }
}

The output shows greedy using 3 coins where DP uses 2, and greedy failing outright for {3, 4}. Change the coin set to {1, 2, 5, 10} (Indian coins): greedy and DP now agree. Coin systems where greedy is always optimal are called canonical.

Section 08

Practice set

Attempt questions 1–3 on paper before revealing answers. Questions 4–7 and the interactive exercises are available for independent revision.

Q1 · Recursion tree

Draw the complete recursion tree of F(6). Count all calls, distinct states and occurrences of F(3).

Reveal solution

F(6)=8; 25 calls; 7 distinct states; 18 repeated calls beyond the first visits; F(3) occurs 3 times. Call frequencies from F(6) down to F(0) are 1, 1, 2, 3, 5, 8, 5.

Q2 · Greedy failure

Given unlimited coins {1, 4, 6}, make amount 8. Compare greedy and optimal solutions and explain the failure.

Reveal solution

Greedy: 6+1+1 (3 coins). Optimal: 4+4 (2 coins). A locally largest coin is not always the best first choice.

Q3 · Principle of optimality

In this undirected graph find a shortest A–D path, and justify the optimality of its subpaths.

Reveal solution

ABCD costs 3+1+2=6; ABD costs 9, ACD costs 7 and ACBD costs 12. The optimal path is A→B→C→D. A→B→C costs 4 and B→C→D costs 3; both are shortest between those endpoints.

Q4 · Choose the approach

Which are natural DP candidates: Fibonacci, binary search, minimum coin change, merge sort, climbing stairs, 0/1 Knapsack? Justify.

Reveal solution

Fibonacci, minimum coin change, climbing stairs and 0/1 Knapsack naturally admit DP. Binary search follows one smaller interval, and merge sort divides into independent subarrays; neither standard algorithm benefits from caching overlapping states.

Q5 · Exam theory

Differentiate overlapping subproblems from optimal substructure, state Bellman's principle and compare greedy with DP.

Reveal solution

Overlapping subproblems concern recurring states; optimal substructure concerns constructing an optimum from smaller optima. Bellman's principle says the remaining decisions of an optimal policy are optimal for the state reached. Greedy makes justified local choices; DP compares relevant recurrence alternatives.

Q6 · Count paths

A staircase has five steps. Each move climbs one or two steps. Define the smaller problem, write its base cases and recurrence, and count the number of ways to reach the top.

Reveal solution

W(i) is the number of ordered ways to reach step i. W(0)=1 (empty sequence), W(1)=1; W(i)=W(i−1)+W(i−2). Values for steps 0…5 are 1,1,2,3,5,8. Last-move cases are disjoint and exhaustive.

Q7 · Greedy versus optimal substructure

Coins are {3,4}, each unlimited. Form exactly 6. What happens to largest-first greedy? What is the optimum? Why is amount 1 unreachable?

Reveal solution

Greedy chooses 4, leaving 2, which cannot be formed. The optimal exact solution is 3+3 (two coins). Amount 1 cannot be reached by any nonnegative sum of denominations 3 and 4; dp[1]=∞.

For full marks: define the state in words, write the base cases and recurrence, show the table in order, state the final answer, and give the time and space complexity.

Short answers 2 marks each

A1 · Define DP2 marks

Define dynamic programming.

Model answer

Dynamic programming solves a problem by writing its answer in terms of answers to smaller subproblems (a recurrence) and storing each subproblem’s answer so that it is computed only once.

Marks: 1 for smaller subproblems with a recurrence, 1 for storing and reusing answers.

A2 · Overlapping subproblems2 marks

What are overlapping subproblems? Give an example.

Model answer

The same subproblem is needed more than once while solving a problem. Example: computing F(5) recursively computes F(3) twice and F(2) three times.

Marks: 1 for the definition, 1 for a correct example.

A3 · Principle of optimality2 marks

State Bellman’s principle of optimality.

Model answer

In an optimal sequence of decisions, whatever the first decision is, the remaining decisions must be optimal for the state that the first decision leads to.

Marks: 2 for a complete statement; 1 if the idea of “the state reached” is missing.

A4 · Greedy counterexample2 marks

Coins {1, 3, 4} are available in unlimited supply. Show that “take the largest coin that fits” does not give the fewest coins for amount 6.

Model answer

Greedy takes 4, then 1, then 1: three coins. But 3 + 3 uses only two coins. So the greedy choice is not optimal for this coin set.

Marks: 1 for the greedy result, 1 for the better solution.

A5 · D&C versus DP2 marks

Give one difference between divide and conquer and dynamic programming, with an example of each.

Model answer

Divide and conquer splits a problem into separate subproblems that do not repeat, such as the two halves in merge sort. DP is used when subproblems repeat, so their answers are stored and reused, as in Fibonacci.

Marks: 1 for the difference, 1 for the two examples.

Medium answers 5 marks each

B1 · Recursion tree5 marks

Draw the recursion tree for F(5) computed by the naive recursive function. Count the total calls and the distinct subproblems, and explain how DP reduces the work.

Model answer

F(5) calls F(4) and F(3); every node F(k) with k ≥ 2 has children F(k−1) and F(k−2), and F(1), F(0) are leaves.

StateF(5)F(4)F(3)F(2)F(1)F(0)
Calls112353

Total calls = 15, but only 6 distinct subproblems, F(0) to F(5). DP stores each F(i) the first time it is computed, so each value is calculated once: n − 1 additions and O(n) time instead of exponential time.

Marks: 2 for the tree, 1 for the counts (15 and 6), 2 for explaining reuse and the O(n) result.

B2 · Coin change table5 marks

Coins {1, 4, 6} are available in unlimited supply. Using DP, find the fewest coins needed to make 8. Show the table and compare with greedy.

Model answer

Let dp[a] be the fewest coins that make amount a. Then dp[0] = 0 and dp[a] = 1 + min(dp[a − c]) over coins c ≤ a.

a012345678
dp[a]012312122

dp[8] = 1 + min(dp[7], dp[4], dp[2]) = 1 + min(2, 1, 2) = 2, using 4 + 4. Greedy takes 6 + 1 + 1 = 3 coins, so greedy is not optimal here.

Marks: 1 for the recurrence, 3 for the correct table, 1 for the answer and the greedy comparison.

Long answers 10 marks each

C1 · Properties and Bellman’s principle10 marks

Explain the two properties a problem needs for dynamic programming. For the undirected graph with edges A–B = 2, A–C = 4, B–C = 2, B–D = 3 and C–D = 5, find the shortest path from A to D and use it to explain Bellman’s principle with a replacement argument.

Model answer
  1. Overlapping subproblems: the same subproblem is needed many times, so storing its answer saves time (Fibonacci).
  2. Optimal substructure: an optimal solution is built from optimal solutions of its subproblems (shortest paths).
  3. Paths from A to D: A–B–D = 2 + 3 = 5; A–C–D = 4 + 5 = 9; A–B–C–D = 2 + 2 + 5 = 9; A–C–B–D = 4 + 2 + 3 = 9. Shortest: A–B–D, cost 5.
  4. Principle: after the first decision (go to B), the rest of the route must be the best route from B to D.
  5. Check: from B the options are B–D = 3 and B–C–D = 7, so B–D is best. From A to B the options are 2 and A–C–B = 6, so A–B is best.
  6. Replacement argument: if the part B–D could be replaced by something cheaper, the whole A–D route would cost less than 5, contradicting that it is the shortest. So every part of a shortest path is itself shortest.

Marks: 2 + 2 for the two properties, 2 for listing paths and costs, 1 for the statement, 2 for the replacement argument, 1 for the conclusion.

C2 · Climbing stairs end to end10 marks

A staircase has n steps. You may climb 1 or 2 steps at a time. (a) Define a DP state, base cases and recurrence. (b) Find the number of ways for n = 6. (c) Compare the time of naive recursion with the table method. (d) Write bottom-up pseudocode.

Model answer
  1. (a) W(i) = number of ordered ways to reach step i. W(0) = 1 (the empty sequence) and W(1) = 1. The last move is either 1 step (from i − 1) or 2 steps (from i − 2); these cases do not overlap and cover everything, so W(i) = W(i − 1) + W(i − 2).
  2. (b) W(0…6) = 1, 1, 2, 3, 5, 8, 13. So there are 13 ways.
  3. (c) Naive recursion recomputes the same W(i) many times, giving exponential time, O(2n). The table computes each W(i) once: O(n) time and O(n) space, or O(1) space if only the last two values are kept.
  4. (d)
W[0] = 1; W[1] = 1
for i = 2 to n:
  W[i] = W[i − 1] + W[i − 2]
return W[n]

Marks: 3 for (a), 2 for (b), 2 for (c), 3 for (d).

Section 10

Lecture summary

  • Dynamic Programming solves related subproblems and avoids repeated work where possible.
  • Overlapping subproblems make storing results useful.
  • Optimal substructure supports recurrence-based optimization.
  • Bellman's principle concerns the optimal continuation from the reached state.
  • Greedy choices need a separate correctness justification.
  • A valid state, transition and base case are crucial to a DP solution.
