Measuring cost

Count basic operations as a function of input size n (RAM model: each takes constant time). A priori = from the algorithm; a posteriori = timing a program.

Space

S = fixed part + variable part. Report auxiliary space. Recursion depth d costs Θ(d) stack. Iterative sum O(1); recursive sum O(n); merge sort O(n).

Common mistakes · full marks

  • Worst case ≠ largest input.
  • Average ≠ (best+worst)/2; state the distribution.
  • Forgetting the recursion stack in space.

Full marks: state n and the basic operation, count step by step, name the inputs for each case, give space.

Two-mark self-test

  1. Define time complexity.
    The number of basic operations an algorithm performs, expressed as a function of the input size n.
  2. Differentiate a priori analysis and a posteriori testing.
    A priori: estimated from the algorithm before execution, machine-independent. A posteriori: measured by running a program on a machine, machine-dependent.
  3. What are the best and worst cases of linear search?
    Best: key at the first position, 1 comparison. Worst: key at the last position or absent, n comparisons.
  4. What is auxiliary space?
    Extra memory used by the algorithm apart from the input, e.g. temporary arrays and the recursion stack.
  5. How many times does a loop that doubles i from 1 up to n run?
    ⌊log₂ n⌋ + 1 times, i.e. Θ(log n).
