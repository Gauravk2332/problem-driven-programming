Chapter 01 / 13

Start with a problem

Two students write programs to check whether a list of roll numbers contains a duplicate. Asha compares every pair. Ravi sorts the list first and then compares neighbours. On 1,000 roll numbers both finish instantly. On 10 million, Asha’s program runs for hours.

Think first

Why is timing the two programs with a stopwatch not a fair way to decide which algorithm is better?

Why stopwatches mislead
Running time depends on the machine, the language, the compiler, other programs running, and above all the particular input. We want a measure that depends only on the algorithm and the size of the input.

The answer is to count basic operations as a function of the input size n. Comparing every pair of n items takes n(n − 1)/2 comparisons: about 50 trillion for n = 10 million. This lecture teaches that counting.

Chapter 02 / 13

What we count, and why

A priori analysis estimates cost from the algorithm itself, before running it; a posteriori testing measures a program on a machine. A priori analysis is machine-independent, so we use it to compare algorithms.

  • Input size n: the quantity that drives the cost (number of elements, number of digits, vertices…).
  • Basic operation: the operation that dominates the work, usually the one in the innermost loop (a comparison, an addition).
  • Cost model: each basic operation takes constant time. This is the RAM model used in textbooks.
ProblemInput size nBasic operation
Search a listnumber of elementskey comparison
Sort a listnumber of elementscomparison (or swap)
Multiply n × n matricesmatrix dimensionmultiplication
Test if N is primenumber of digits of N (or N itself)division

Time complexity T(n) is the number of basic operations; space complexity S(n) is the memory used. Both are functions of n, so they let us predict how cost grows when the input grows.

Chapter 03 / 13

The frequency-count method

Count how many times each statement runs, then add. For summing an array of n elements:

StatementTimes executed
total = 01
for i = 0 to n − 1 (test)n + 1
  total = total + A[i]n
return total1
Total2n + 3

The exact count 2n + 3 depends on what we decide to count, but its growth does not: doubling n roughly doubles the work. Lecture 3 makes “roughly” precise with Big-O; for now notice that the leading term (2n) dominates for large n.

For nested loops multiply, or add up the inner counts. In for i = 0..n−1: for j = i+1..n−1 the inner loop runs n − 1, n − 2, …, 1, 0 times: a total of n(n − 1)/2.

Chapter 04 / 13

Explore: count comparisons in insertion sort

Insertion sort inserts each element into the sorted prefix on its left. Count the comparisons for different inputs: already sorted, reversed, and mixed.

Think first

Predict the counts for 4 9 15 16 23 31 42 (sorted) and 42 31 23 16 15 9 8 4 (reversed) before running them.

What you should see
Sorted: n − 1 comparisons and no shifts (each key stops after one comparison). Reversed: n(n − 1)/2 comparisons, because each key moves all the way to the front. The same algorithm, the same n, very different costs.

Worked analysis: insertion sort

The lab’s counts follow from the code. Inserting the element at index i takes between 1 and i comparisons.

So insertion sort is fast on nearly sorted data and quadratic in the worst case: worst-case time is proportional to n², best-case to n. It sorts in place, using only a constant amount of extra memory.

Loop patterns you should recognise

Most running times come from a few loop shapes. Take n = 16 and count iterations; then name the growth.

LoopIterations for n = 16Grows like

for i = 1; i ≤ n; i = 2i
for i = 1; i·i ≤ n; i++
for i = 1 to n: for j = 1 to n
for i = 1 to n: for j = i+1 to n

  • A loop that halves or doubles its variable runs about log₂ n times.
  • Sequential loops add: n + n² grows like n².
  • Nested loops multiply when the bounds are independent.

Chapter 08 / 13

Space complexity

Space complexity counts memory as a function of n. It has a fixed part (code, simple variables, constants) and a variable part that depends on the input (arrays, recursion stack). We usually report auxiliary space: extra memory beyond the input itself.

AlgorithmAuxiliary spaceWhy
Sum with a loopO(1)one accumulator
Insertion sortO(1)sorts in place
Copy the array, then sort the copyO(n)a second array
Recursive sum(A, n) = A[n−1] + sum(A, n−1)O(n)n stack frames are alive at the deepest point
Merge sort (Lecture 5)O(n)temporary arrays for merging

Recursion is not free: every pending call keeps a stack frame. A recursive algorithm with depth n uses Θ(n) stack space even if each call uses only a few variables; very deep recursion can cause a stack overflow.

Chapter 09 / 13

Counting operations in code

The program instruments linear search and insertion sort with counters and checks the pair-count formula. Counters like these are a quick way to check an analysis experimentally.

Python · op_count.py

"""Lecture 2: counting basic operations for best, worst and average cases."""


def linear_search_cmp(a, key):
    comparisons = 0
    for x in a:
        comparisons += 1
        if x == key:
            return comparisons
    return comparisons


def insertion_sort_cmp(a):
    a, comparisons = list(a), 0
    for i in range(1, len(a)):
        key, j = a[i], i - 1
        while j >= 0:
            comparisons += 1
            if a[j] <= key:
                break
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key
    return a, comparisons


def pair_count(n):
    count = 0
    for i in range(n):
        for j in range(i + 1, n):
            count += 1
    return count


a = [31, 8, 42, 15, 4, 23, 16, 9]
n = len(a)
print("linear search in", a)
print("  best  (key 31, first):", linear_search_cmp(a, 31), "comparison")
print("  worst (key 9, last)  :", linear_search_cmp(a, 9), "comparisons")
print("  worst (key 50, absent):", linear_search_cmp(a, 50), "comparisons")
total = sum(linear_search_cmp(a, k) for k in a)
print(f"  average over present keys: {total}/{n} = {total / n}")
for name, data in [("sorted", sorted(a)), ("reversed", sorted(a, reverse=True)), ("given", a)]:
    out, c = insertion_sort_cmp(data)
    print(f"insertion sort, {name:8}: {c} comparisons")
for k in [4, 8, 16]:
    print(f"pairs i<j for n={k}: {pair_count(k)} = n(n-1)/2 = {k * (k - 1) // 2}")

C++ · op_count.cpp

// Lecture 2: counting basic operations for best, worst and average cases.
#include <algorithm>
#include <cstdio>
#include <functional>
#include <string>
#include <vector>
using namespace std;

int linearSearchCmp(const vector<int>& a, int key) {
    int comparisons = 0;
    for (int x : a) { comparisons++; if (x == key) return comparisons; }
    return comparisons;
}

int insertionSortCmp(vector<int> a) {      // works on a copy
    int comparisons = 0;
    for (size_t i = 1; i < a.size(); i++) {
        int key = a[i], j = (int)i - 1;
        while (j >= 0) {
            comparisons++;
            if (a[j] <= key) break;
            a[j + 1] = a[j];
            j--;
        }
        a[j + 1] = key;
    }
    return comparisons;
}

long long pairCount(int n) {
    long long count = 0;
    for (int i = 0; i < n; i++) for (int j = i + 1; j < n; j++) count++;
    return count;
}

int main() {
    vector<int> a = {31, 8, 42, 15, 4, 23, 16, 9};
    int n = a.size();
    printf("linear search in [31, 8, 42, 15, 4, 23, 16, 9]\n");
    printf("  best  (key 31, first): %d comparison\n", linearSearchCmp(a, 31));
    printf("  worst (key 9, last)  : %d comparisons\n", linearSearchCmp(a, 9));
    printf("  worst (key 50, absent): %d comparisons\n", linearSearchCmp(a, 50));
    int total = 0;
    for (int k : a) total += linearSearchCmp(a, k);
    printf("  average over present keys: %d/%d = %.1f\n", total, n, (double)total / n);
    vector<int> s = a, r = a;
    sort(s.begin(), s.end());
    sort(r.begin(), r.end(), greater<int>());
    printf("insertion sort, %-8s: %d comparisons\n", "sorted", insertionSortCmp(s));
    printf("insertion sort, %-8s: %d comparisons\n", "reversed", insertionSortCmp(r));
    printf("insertion sort, %-8s: %d comparisons\n", "given", insertionSortCmp(a));
    for (int k : {4, 8, 16})
        printf("pairs i<j for n=%d: %lld = n(n-1)/2 = %d\n", k, pairCount(k), k * (k - 1) / 2);
}

Java · OpCount.java

// Lecture 2: counting basic operations for best, worst and average cases.
import java.util.Arrays;

public class OpCount {
    static int linearSearchCmp(int[] a, int key) {
        int comparisons = 0;
        for (int x : a) { comparisons++; if (x == key) return comparisons; }
        return comparisons;
    }

    static int insertionSortCmp(int[] input) {
        int[] a = input.clone();
        int comparisons = 0;
        for (int i = 1; i < a.length; i++) {
            int key = a[i], j = i - 1;
            while (j >= 0) {
                comparisons++;
                if (a[j] <= key) break;
                a[j + 1] = a[j];
                j--;
            }
            a[j + 1] = key;
        }
        return comparisons;
    }

    static long pairCount(int n) {
        long count = 0;
        for (int i = 0; i < n; i++) for (int j = i + 1; j < n; j++) count++;
        return count;
    }

    public static void main(String[] args) {
        int[] a = {31, 8, 42, 15, 4, 23, 16, 9};
        int n = a.length;
        System.out.println("linear search in " + Arrays.toString(a));
        System.out.println("  best  (key 31, first): " + linearSearchCmp(a, 31) + " comparison");
        System.out.println("  worst (key 9, last)  : " + linearSearchCmp(a, 9) + " comparisons");
        System.out.println("  worst (key 50, absent): " + linearSearchCmp(a, 50) + " comparisons");
        int total = 0;
        for (int k : a) total += linearSearchCmp(a, k);
        System.out.println("  average over present keys: " + total + "/" + n + " = " + (double) total / n);
        int[] s = a.clone(); Arrays.sort(s);
        int[] r = new int[n]; for (int i = 0; i < n; i++) r[i] = s[n - 1 - i];
        System.out.printf("insertion sort, %-8s: %d comparisons%n", "sorted", insertionSortCmp(s));
        System.out.printf("insertion sort, %-8s: %d comparisons%n", "reversed", insertionSortCmp(r));
        System.out.printf("insertion sort, %-8s: %d comparisons%n", "given", insertionSortCmp(a));
        for (int k : new int[]{4, 8, 16})
            System.out.println("pairs i<j for n=" + k + ": " + pairCount(k) + " = n(n-1)/2 = " + k * (k - 1) / 2);
    }
}

Chapter 10 / 13

Common confusions

ConfusionCorrection
“Worst case means the largest input.”Cases compare inputs of the same size n; worst case is the most expensive input of that size.
“Average case is the average of best and worst.”It is the expected cost under a stated probability distribution of inputs.
“Time complexity is measured in seconds.”It counts basic operations as a function of n.
“Recursion uses no extra memory.”Each pending call occupies a stack frame.
“Two nested loops always mean n².”Only if both run about n times; for i: for j = 1 to 5 is 5n.
for i = 1 to n: for j = 1 to 10 runs the inner body how many times?

Short answers 2 marks each

A1 · Define time complexity. 2 marks

Reveal model answer
The number of basic operations an algorithm performs, expressed as a function of the input size n.

Basic operations 1; function of n 1.

A2 · Differentiate a priori analysis and a posteriori testing. 2 marks

Reveal model answer
A priori: estimated from the algorithm before execution, machine-independent. A posteriori: measured by running a program on a machine, machine-dependent.

1 each.

A3 · What are the best and worst cases of linear search? 2 marks

Reveal model answer
Best: key at the first position, 1 comparison. Worst: key at the last position or absent, n comparisons.

1 each.

A4 · What is auxiliary space? 2 marks

Reveal model answer
Extra memory used by the algorithm apart from the input, e.g. temporary arrays and the recursion stack.

Reveal model answer
⌊log₂ n⌋ + 1 times, i.e. Θ(log n).

Medium answers 5 marks each

B1 · Use the frequency-count method to find the time of matrix addition for n × n matrices. 5 marks

Reveal model answer
Outer test n + 1; inner test n(n + 1); assignment n². Total 2n² + 2n + 1, which grows like n².

Counts 3; total 1; growth 1.

B2 · Explain best, worst and average case with insertion sort. 5 marks

Reveal model answer
Best: sorted input, n − 1 comparisons. Worst: reversed, n(n − 1)/2. Average: random order, about n²/4. Example n = 8: 7, 28, 22 for [31,8,42,15,4,23,16,9].

Each case with input and count 1½; example ½.

B3 · Explain the components of space complexity with examples. 5 marks

Reveal model answer
S(P) = fixed part c (instructions, simple variables, constants) + variable part S_P(n) (input-dependent arrays, recursion stack). Examples: iterative sum O(1), copy of array O(n), recursive sum O(n) stack.

Components 2; examples 3.

Long answers 10 marks each

C1 · Analyse linear search completely: time in all three cases (with assumptions) and space. 10 marks

Reveal model answer
Basic operation: comparison. Best 1, worst n (last/absent), average (n + 1)/2 assuming the key is present and uniformly located; if absent with probability 1 − p, average p(n + 1)/2 + (1 − p)n. Space O(1) auxiliary. Example on an 8-element list.

Model 2; best/worst 2; average with assumption 4; space 1; example 1.

C2 · Compare two algorithms for detecting duplicates (all pairs; sort then scan) in time and space, and explain which to choose. 10 marks

Reveal model answer
All pairs: n(n − 1)/2 comparisons, O(1) space. Sort + scan: O(n log n) time with merge sort (O(n) space) or heap sort (O(1)). For n = 10⁶: about 5 × 10¹¹ vs 2 × 10⁷ comparisons. Choose sort + scan (or hashing, Lecture 10) for large n; all pairs only for tiny n.
