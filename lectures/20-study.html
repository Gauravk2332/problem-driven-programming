Recall the DP idea

In Lecture 19, we learned that recursive solutions may repeat identical questions. Today the task is to turn a problem into a precise DP solution. You need basic arrays, recursion, and the idea of a minimum or maximum. Review Lecture 19 if any terms are unfamiliar.

Imagine a friend asking the same calculation several times. Saving the result helps only if the inputs really identify the same question. DP begins by identifying those inputs; the array or recursion comes later.

Chapter 02 / 13

Solve a jumping problem

You are controlling a robot across stones with heights [10,30,40,20,25,15]. It starts on index 0, pays the absolute change in height for a jump and can advance one or two indices. Your goal is the smallest possible total energy, not the smallest number of jumps.

Think first

On stone 1, both stone 2 and stone 3 cost 10 to reach. Which should you choose?

Try the two complete routes

Route 0→1→2→4→5 costs 55. Route 0→1→3→5 costs 35. Equal immediate costs can lead to different final results. Even without ties, heights [2,3,0,1,0] make cheapest-next greedy choose 0→1→3→4 (4 energy), while 0→2→4 (2 energy) is optimal. We want a rule based on optimal subproblem answers, not intuition about only the next jump.

Need a hint?

Downward jumps also consume positive energy.

Chapter 03 / 13

What exactly should a state mean?

Imagine writing small questions on index cards. One card asks: “What minimum energy does the robot need to arrive at stone 3?” Another asks about stone 2. Those questions differ only in one integer: the stone index.

Write dp[i] = the minimum energy to reach i from 0. Notice we did not define it as the cost of the last jump, or as the height at i. Updating the meaning halfway through would make the formula wrong.

Why is the whole route unnecessary? If two routes reach the same stone, the cheaper prefix is at least as good for every possible future route. That is the optimal substructure you met last lecture. If a jump-count limit is introduced, two arrivals with different counts may no longer be equivalent; then add that count to the state.

Chapter 04 / 13

Derive the transition by the last jump

Work backwards from your destination. If the final stone is i, the last legal jump must start one or two positions earlier. There are no other cases. Ask the smaller questions, add the last jump cost, and choose the cheaper complete candidate.

dp[0] = 0
dp[1] = |h[1] − h[0]| (if n ≥ 2)
dp[i] = min(dp[i−1] + |h[i] − h[i−1]|, dp[i−2] + |h[i] − h[i−2]|), i ≥ 2
Answer = dp[n−1]

At stone 3, dp[2]=30 and dp[1]=20. Height differences: from stone 2 is |20−40|=20; from stone 1 is |20−30|=10. Compare 50 versus 30. The second candidate wins, so dp[3]=30.

Need a hint?

Add the jump cost to each complete predecessor cost.

The recurrence is correct because any feasible last jump has one of these two predecessors, and a cheaper feasible prefix would make the entire route cheaper.

Base cases and dependency order

Imagine asking the energy needed to arrive at the starting stone. You have already arrived, so it costs zero. Stone 1 has just one legal predecessor. If you tried to use dp[−1], you would be asking for a stone outside the problem.

We can either write both bases explicitly or define dp[0]=0 and guard the second predecessor inside the loop. Notice that a valid zero result must not be confused with an uncomputed answer.

Chapter 06 / 13

Ask questions on demand: memoization

Imagine someone asks for the final stone's answer, but you do not know it yet. Ask for the previous two answers. Write down each answer as soon as you finish it. When a later branch asks for one already written, read it and return immediately.

Think first

Watch a cache hit. Does it call its own smaller questions again?

For six stones, six distinct states are computed; four additional requests are cache hits. The cache eliminates repeated expansion, not the call overhead. Recursive frames still occupy memory until their dependencies return.

Chapter 07 / 13

Work from known answers: tabulation

Instead of letting recursive calls decide the order, start at the first known answer, then build the next. A table is simply a notebook of already answered questions. Each current cell should consult two previously filled cells.

Chapter 08 / 13

Remember only the answers you still need

Suppose you solved a long series of questions. Each new question needs only the previous two answers. Would you keep the entire notebook if you only need the final answer? Use two sticky notes instead.

Before calculating stone i, prev2 means dp[i−2] and prev1 means dp[i−1]. Compute curr using both old values. Only after computing curr move prev1 into prev2 and curr into prev1.

For n=1, simply return zero. If you need every intermediate value or an optimal path, rolling values alone lose the required history. Space reduction is a trade-off, not automatically an improvement in every application.

Chapter 09 / 13

Code the same recurrence three ways

Read the state meaning first, then the code. In the top-down method the function input is the index. In the iterative method the loop variable is the index. Both store or represent exactly the same answer.

Top-down and bottom-up

This lecture is about exactly this choice, so here is the summary in one place.

Top-down (memoization)Bottom-up (tabulation)
Starts fromThe final stone: dp[n−1]The first stone: dp[0] = 0
Stored byA memo keyed by stone index iA table dp[0…n−1], filled in increasing i
How it runsRecursion. A state is solved the first time it is asked for, then read from the cacheLoops. Every state is filled once, after the states it depends on
Which statesOnly the states the final answer actually needsUsually every state in the table
Extra costA call stack as deep as the longest chain of calls; very deep inputs can overflow itNo recursion; the table can often be shrunk to one or two rows
Choose it whenThe fill order is awkward, or many states are never neededThe fill order is clear and most states are needed; this is the safer default for large inputs

In the programs below, memoized is top-down, tabulated is bottom-up, and rolling is bottom-up with only two saved values.

Full program

Python · frog_dp.py

# h is a nonempty sequence of nonnegative integer heights.
def memoized(h):
    memo = [None] * len(h)
    def solve(i):
        if memo[i] is not None:
            return memo[i]
        if i == 0:
            memo[i] = 0
        else:
            a = solve(i-1) + abs(h[i]-h[i-1])
            b = solve(i-2) + abs(h[i]-h[i-2]) if i >= 2 else float("inf")
            memo[i] = min(a,b)
        return memo[i]
    return solve(len(h)-1)

def tabulated(h):
    dp = [0] * len(h)
    for i in range(1,len(h)):
        a = dp[i-1] + abs(h[i]-h[i-1])
        b = dp[i-2] + abs(h[i]-h[i-2]) if i >= 2 else float("inf")
        dp[i] = min(a,b)
    return dp[-1]

def rolling(h):
    if len(h) == 1:
        return 0
    prev2, prev1 = 0, abs(h[1]-h[0])
    for i in range(2,len(h)):
        curr = min(prev1 + abs(h[i]-h[i-1]),
                   prev2 + abs(h[i]-h[i-2]))
        prev2, prev1 = prev1, curr
    return prev1

if __name__ == "__main__":
    h = [10,30,40,20,25,15]
    print(memoized(h), tabulated(h), rolling(h))  # 35 35 35

C++ · frog_dp.cpp

#include <iostream>
#include <vector>
#include <algorithm>
#include <cstdlib>
#include <functional>
#include <climits>
using namespace std;
using ll = long long;
// Nonempty input; assume heights 0..10^9, n <= 10^6.
ll memoized(const vector<ll>& h) {
    vector<ll> memo(h.size(), -1); // valid costs are nonnegative
    function<ll(int)> solve = [&](int i) -> ll {
        if (memo[i] != -1) return memo[i];
        if (i == 0) return memo[i] = 0;
        ll a = solve(i-1) + llabs(h[i]-h[i-1]);
        ll b = i >= 2 ? solve(i-2) + llabs(h[i]-h[i-2]) : LLONG_MAX;
        return memo[i] = min(a,b);
    };
    return solve(int(h.size())-1);
}
ll tabulated(const vector<ll>& h) {
    vector<ll> dp(h.size(), 0);
    for (int i=1; i<int(h.size()); ++i) {
        ll a = dp[i-1] + llabs(h[i]-h[i-1]);
        ll b = i>=2 ? dp[i-2] + llabs(h[i]-h[i-2]) : LLONG_MAX;
        dp[i] = min(a,b);
    }
    return dp.back();
}
ll rolling(const vector<ll>& h) {
    if (h.size()==1) return 0;
    ll prev2=0, prev1=llabs(h[1]-h[0]);
    for (int i=2; i<int(h.size()); ++i) {
        ll curr = min(prev1+llabs(h[i]-h[i-1]),
                      prev2+llabs(h[i]-h[i-2]));
        prev2=prev1; prev1=curr;
    }
    return prev1;
}
int main() {
    vector<ll> h={10,30,40,20,25,15};
    cout<<memoized(h)<<" "<<tabulated(h)<<" "<<rolling(h)<<"\n"; // 35 35 35
}

Java · FrogDP.java

import java.util.Arrays;
public class FrogDP {
    // Nonempty input; heights 0..10^9, n <= 10^6.
    static long solve(int i, long[] h, long[] memo) {
        if (memo[i] != -1) return memo[i];
        if (i == 0) return memo[i] = 0;
        long a = solve(i-1,h,memo)+Math.abs(h[i]-h[i-1]);
        long b = i>=2 ? solve(i-2,h,memo)+Math.abs(h[i]-h[i-2]) : Long.MAX_VALUE;
        return memo[i] = Math.min(a,b);
    }
    static long memoized(long[] h) {
        long[] memo = new long[h.length];
        Arrays.fill(memo,-1);
        return solve(h.length-1,h,memo);
    }
    static long tabulated(long[] h) {
        long[] dp = new long[h.length];
        for (int i=1;i<h.length;i++) {
            long a = dp[i-1]+Math.abs(h[i]-h[i-1]);
            long b = i>=2 ? dp[i-2]+Math.abs(h[i]-h[i-2]) : Long.MAX_VALUE;
            dp[i] = Math.min(a,b);
        }
        return dp[h.length-1];
    }
    static long rolling(long[] h) {
        if (h.length==1) return 0;
        long prev2=0, prev1=Math.abs(h[1]-h[0]);
        for (int i=2;i<h.length;i++) {
            long curr=Math.min(prev1+Math.abs(h[i]-h[i-1]),
                               prev2+Math.abs(h[i]-h[i-2]));
            prev2=prev1; prev1=curr;
        }
        return prev1;
    }
    public static void main(String[] args) {
        long[] h={10,30,40,20,25,15};
        System.out.println(memoized(h)+" "+tabulated(h)+" "+rolling(h)); // 35 35 35
    }
}

Run locally: all three methods return 35 for the same input. One stone returns 0; equal heights can also return 0. The examples assume a nonempty array. The bounded numeric inputs fit signed 64-bit costs; do not add to the impossible sentinel. Top-down recursion is appropriate for modest n only; recursion depth can exceed a language/runtime stack limit. Prefer iterative code for very large n. The site displays and copies code; it does not execute it.

Don't confuse the cost of finding a state with the number of states. Here n states each do at most two comparisons and additions, so O(n) time. Memoization also uses the call stack. Table and rolling approaches avoid recursive stack overflow.

Chapter 11 / 13

Common mistakes and debugging

Before running code on a large input, check these frequent mistakes.

Mistake 1 · dp[i] means different things in different lines

Write the state as a sentence first. If it means energy to reach i, every update must return a complete energy, not a height or last jump.

Mistake 2 · zero means unvisited

Equal heights can have zero energy, so a zero-filled cache is ambiguous. Use a separate marker such as None or −1 here.

Mistake 3 · use a future state before it is computed

Every dependency must be available. Draw arrows to prerequisites; use increasing i for the jump problem.

Mistake 4 · overwrite prev2 too soon

Compute curr from old prev1 and prev2. Then shift. Using a modified value changes the recurrence.

Mistake 5 · assume O(1) extra space means no memory

It still stores input and temporary registers; O(1) describes additional storage independent of input size. It doesn't retain route choices.

A2 · Differentiate memoization and tabulation. 2 marks

Reveal model answer

A3 · Why is a separate visited flag sometimes needed? 2 marks

Reveal model answer
A valid result may equal the chosen initial value. For example, zero energy is valid; using zero to mean not computed causes repeat work. Use a distinct sentinel or visited flag.

Medium answers 5 marks each

B1 · Trace memoized jumps on [10,30,40,20]. 5 marks

Reveal model answer
dp[0]=0, dp[1]=20, dp[2]=30, dp[3]=30. With recursive order i−1 then i−2, calls: 3,2,1,0,0(hit),1(hit). Four misses, two hits, six total calls; best route 0→1→3.

State/base 1; recurrence 1; values 2; call/hit count 1.

B2 · Fill a bottom-up table for [8,3,10,6,7]. 5 marks

Reveal model answer
dp=[0,5,2,6,5]. At 2 compare 5+7=12 and 0+2=2; at 3 compare 2+4=6 and 5+3=8; at 4 compare 6+1=7 and 2+3=5. Answer 5, path 0→2→4.

Base 1; comparisons 3; final answer 1.

B3 · Compare time and auxiliary space of four methods. 5 marks

Reveal model answer
Plain recursion O(2ⁿ) upper bound, O(n) stack. Memoization O(n) time and O(n) extra (cache + stack); table O(n) each; rolling O(n) time, O(1) extra. Counts are for constant-time transitions and fixed-size arithmetic.

Recursion 1; memo 1; tab 1; rolling 1; assumptions 1.
