Module 05 · Lecture 20

DP Solution Design

States · Transitions · Base cases · Memoization · Tabulation · Space reduction

Section 01

From identifying DP to designing it

Today's problem · Minimum-energy jumps

A robot stands on stone 0. There are n ≥ 1 stones with integer heights. It can advance one or two positions; a jump from j to i costs |h[i]−h[j]|. Find minimum total energy needed to reach the last stone. Heights: [10,30,40,20,25,15].

Think first

Can you guarantee a globally cheapest route by picking the cheapest immediate jump? Try tracing first.

Reveal why a local choice is not a proof

At stone 1, the jump to 2 and the jump to 3 both cost 10. Choosing 2, then the cheapest available jumps 2→4→5, gives total 20+10+15+10=55. The route 0→1→3→5 costs 20+10+5=35. An arbitrary local tie rule is not guaranteed safe. Even without ties, heights [2,3,0,1,0] make cheapest-next greedy choose 0→1→3→4 at cost 1+2+1=4, while 0→2→4 costs 2+0=2 (optimal). DP compares complete prefix costs.

Lecture 19 established why DP can work. Today we design a state, derive its recurrence, then implement exactly the same computation three ways.

Learning outcomes: state, transition, base case, evaluation order, memoization, tabulation and safe reduction of storage.

Section 02

Design the state and recurrence

State: dp[i] = minimum total energy needed to reach stone i from stone 0. At stone i, future legal jumps and costs depend on current index, not the previous route.

Last decision: the last jump to i is either i−1→i or i−2→i. Each candidate is the optimal energy of its predecessor plus the new jump cost.

dp[0] = 0
dp[1] = |h[1] − h[0]| (if n ≥ 2)
dp[i] = min(dp[i−1] + |h[i] − h[i−1]|, dp[i−2] + |h[i] − h[i−2]|), i ≥ 2
Answer = dp[n−1]

Correctness (induction): dp[0]=0. Assume all smaller states are correct. Every feasible route ending at i uses one legal predecessor; its prefix has cost at least that predecessor's optimum. Conversely each candidate corresponds to a feasible optimal prefix plus a legal jump. The minimum of the candidates is exactly optimal.

1 · StateWhat exact question does dp[i] answer?
2 · TransitionWhich legal last decisions lead here?
3 · Base casesWhich states are already known?
4 · OrderAre prerequisites available before use?
5 · AnswerWhich state is the requested output?
6 · CostCount states × local work; include stack and storage.

State sufficiency: if there is a limit on the number of jumps or an external fuel constraint, i alone may not encode the remaining options. Add the relevant parameter. Do not store the entire route unless future decisions truly need it.

Section 03

Memoization · top-down DP

Start with the query dp[n−1]. Recursively request only states needed by the recurrence. On a first visit compute the answer; save it under its state key. On later visits return the saved result.

if memo[i] exists: return memo[i]
if i = 0: answer = 0
else: answer = min(valid predecessor costs)
memo[i] = answer; return answer

For our six-stone instance (order i−1 first), there are 10 invocations, 6 first visits and 4 cache hits; maximum recursive depth is 6. All six states are needed in this particular recurrence. The cache prevents re-expansion, not all function calls. Valid cost 0 cannot also mean uncomputed.

Time: O(n), since each state is expanded once with at most two constant-time transitions. Auxiliary space: O(n) memo + O(n) recursive stack = O(n).

Section 04

Tabulation · bottom-up DP

Instead of requesting the final state recursively, evaluate the dependency DAG in increasing stone order. Every prerequisite has a smaller index. The table is an explicit representation of answers already solved.

1300+20=20—20
24020+10=300+30=3030
32030+20=5020+10=3030

At i=3, the table compares 30+20=50 against 20+10=30. At i=5, compare 35+10=45 against 30+5=35. Each candidate has a feasible predecessor; return dp[5]=35, not the sum of all cells.

Reconstruction: store the chosen predecessor p[i] along with each new answer. Starting at i=5, follow p[i] until 0, then reverse: 0→1→3→5. Ties may store either valid choice. O(n) time and O(n) extra for table/parent; a path may require O(n) output.

Section 05

Space reduction · rolling state

For any i≥2, future transitions read only the last two answers. Older cells are no longer live for the value computation. Keep prev2=dp[i−2], prev1=dp[i−1], calculate curr, then shift.

prev2 = dp[0] = 0
prev1 = dp[1] = |h[1]−h[0]|
curr = min(prev1 + |h[i]−h[i−1]|, prev2 + |h[i]−h[i−2]|)
prev2 ← prev1; prev1 ← curr

Invariant: before iteration i, the registers contain exactly the two needed answers. Computing curr before updating either register preserves the invariant. Handle n=1 separately. O(n) time, O(1) auxiliary storage for the optimum value, excluding original input. Full route retrieval needs additional history or recomputation.

Section 06

Compare approaches and design choices

MethodOrderTimeAuxiliary spaceTrade-off
Plain recursionDemand-drivenO(2ⁿ) upper boundO(n) stackRepeats states
Memoization (array)Demand-drivenO(n)O(n) cache + O(n) stack = O(n)Computes needed states
TabulationIncreasing iO(n)O(n) tableNo recursive stack; full history
Rolling valuesIncreasing iO(n)O(1) extraValue only; input array excluded

All three optimized methods solve the same recurrence. Memoization is useful when demand-driven states are sparse or evaluation order is awkward. Tabulation is useful when a dependency order is clear and most states are needed. Rolling values apply only if old states become unnecessary. None of these choices repairs an incorrect recurrence.

Generalizing evaluation order

For dp[r][c] = paths from top-left of an obstacle-free grid, dependencies are (r−1,c) and (r,c−1); row-major order is valid. If obstacles exist, blocked states count zero. A row-sized buffer often works, but loop direction must preserve the intended previous/current row values.

Transfer the design: maximum non-adjacent reward

Choose numbers from [2,7,9,3,1] without choosing adjacent positions. Values are nonnegative; choosing nothing is allowed. Let R(k) be the maximum from the first k elements, not the maximum ending at k.

R(0)=0; R(1)=2
R(k)=max(R(k−1), R(k−2)+a[k−1]), k ≥ 2
Answer = R(n)
k012345
R(k)027111112

Skip the new element or choose it and combine with the best prefix excluding its neighbor. The optimal reward is 12 (2+9+1). The prefix state has the same two-value dependency pattern, but a different meaning and a max rather than min.

Section 07

From recurrence to executable code

Use exactly the same state meaning and transitions in each method. A sentinel is safe only if no valid answer equals it. For this energy problem all costs are nonnegative, so −1 is safe; Python uses None.

Top-down and bottom-up

This lecture is about exactly this choice, so here is the summary in one place.

Top-down (memoization)Bottom-up (tabulation)
Starts fromThe final stone: dp[n−1]The first stone: dp[0] = 0
Stored byA memo keyed by stone index iA table dp[0…n−1], filled in increasing i
How it runsRecursion. A state is solved the first time it is asked for, then read from the cacheLoops. Every state is filled once, after the states it depends on
Which statesOnly the states the final answer actually needsUsually every state in the table
Extra costA call stack as deep as the longest chain of calls; very deep inputs can overflow itNo recursion; the table can often be shrunk to one or two rows
Choose it whenThe fill order is awkward, or many states are never neededThe fill order is clear and most states are needed; this is the safer default for large inputs

In the programs below, memoized is top-down, tabulated is bottom-up, and rolling is bottom-up with only two saved values.

Full program

Python · frog_dp.py

# h is a nonempty sequence of nonnegative integer heights.
def memoized(h):
    memo = [None] * len(h)
    def solve(i):
        if memo[i] is not None:
            return memo[i]
        if i == 0:
            memo[i] = 0
        else:
            a = solve(i-1) + abs(h[i]-h[i-1])
            b = solve(i-2) + abs(h[i]-h[i-2]) if i >= 2 else float("inf")
            memo[i] = min(a,b)
        return memo[i]
    return solve(len(h)-1)

def tabulated(h):
    dp = [0] * len(h)
    for i in range(1,len(h)):
        a = dp[i-1] + abs(h[i]-h[i-1])
        b = dp[i-2] + abs(h[i]-h[i-2]) if i >= 2 else float("inf")
        dp[i] = min(a,b)
    return dp[-1]

def rolling(h):
    if len(h) == 1:
        return 0
    prev2, prev1 = 0, abs(h[1]-h[0])
    for i in range(2,len(h)):
        curr = min(prev1 + abs(h[i]-h[i-1]),
                   prev2 + abs(h[i]-h[i-2]))
        prev2, prev1 = prev1, curr
    return prev1

if __name__ == "__main__":
    h = [10,30,40,20,25,15]
    print(memoized(h), tabulated(h), rolling(h))  # 35 35 35

C++ · frog_dp.cpp

#include <iostream>
#include <vector>
#include <algorithm>
#include <cstdlib>
#include <functional>
#include <climits>
using namespace std;
using ll = long long;
// Nonempty input; assume heights 0..10^9, n <= 10^6.
ll memoized(const vector<ll>& h) {
    vector<ll> memo(h.size(), -1); // valid costs are nonnegative
    function<ll(int)> solve = [&](int i) -> ll {
        if (memo[i] != -1) return memo[i];
        if (i == 0) return memo[i] = 0;
        ll a = solve(i-1) + llabs(h[i]-h[i-1]);
        ll b = i >= 2 ? solve(i-2) + llabs(h[i]-h[i-2]) : LLONG_MAX;
        return memo[i] = min(a,b);
    };
    return solve(int(h.size())-1);
}
ll tabulated(const vector<ll>& h) {
    vector<ll> dp(h.size(), 0);
    for (int i=1; i<int(h.size()); ++i) {
        ll a = dp[i-1] + llabs(h[i]-h[i-1]);
        ll b = i>=2 ? dp[i-2] + llabs(h[i]-h[i-2]) : LLONG_MAX;
        dp[i] = min(a,b);
    }
    return dp.back();
}
ll rolling(const vector<ll>& h) {
    if (h.size()==1) return 0;
    ll prev2=0, prev1=llabs(h[1]-h[0]);
    for (int i=2; i<int(h.size()); ++i) {
        ll curr = min(prev1+llabs(h[i]-h[i-1]),
                      prev2+llabs(h[i]-h[i-2]));
        prev2=prev1; prev1=curr;
    }
    return prev1;
}
int main() {
    vector<ll> h={10,30,40,20,25,15};
    cout<<memoized(h)<<" "<<tabulated(h)<<" "<<rolling(h)<<"\n"; // 35 35 35
}

Java · FrogDP.java

import java.util.Arrays;
public class FrogDP {
    // Nonempty input; heights 0..10^9, n <= 10^6.
    static long solve(int i, long[] h, long[] memo) {
        if (memo[i] != -1) return memo[i];
        if (i == 0) return memo[i] = 0;
        long a = solve(i-1,h,memo)+Math.abs(h[i]-h[i-1]);
        long b = i>=2 ? solve(i-2,h,memo)+Math.abs(h[i]-h[i-2]) : Long.MAX_VALUE;
        return memo[i] = Math.min(a,b);
    }
    static long memoized(long[] h) {
        long[] memo = new long[h.length];
        Arrays.fill(memo,-1);
        return solve(h.length-1,h,memo);
    }
    static long tabulated(long[] h) {
        long[] dp = new long[h.length];
        for (int i=1;i<h.length;i++) {
            long a = dp[i-1]+Math.abs(h[i]-h[i-1]);
            long b = i>=2 ? dp[i-2]+Math.abs(h[i]-h[i-2]) : Long.MAX_VALUE;
            dp[i] = Math.min(a,b);
        }
        return dp[h.length-1];
    }
    static long rolling(long[] h) {
        if (h.length==1) return 0;
        long prev2=0, prev1=Math.abs(h[1]-h[0]);
        for (int i=2;i<h.length;i++) {
            long curr=Math.min(prev1+Math.abs(h[i]-h[i-1]),
                               prev2+Math.abs(h[i]-h[i-2]));
            prev2=prev1; prev1=curr;
        }
        return prev1;
    }
    public static void main(String[] args) {
        long[] h={10,30,40,20,25,15};
        System.out.println(memoized(h)+" "+tabulated(h)+" "+rolling(h)); // 35 35 35
    }
}

Run locally: all three methods return 35 for the same input. One stone returns 0; equal heights can also return 0. The examples assume a nonempty array. The bounded numeric inputs fit signed 64-bit costs; do not add to the impossible sentinel. Top-down recursion is appropriate for modest n only; recursion depth can exceed a language/runtime stack limit. Prefer iterative code for very large n. The site displays and copies code; it does not execute it.

Debugging habit: first test n=1, n=2, repeated heights, then compare all methods on the same small inputs. If they disagree, inspect the first state where their answers diverge.

Section 08

Practice and transfer

Q1 · State meaning

Explain why the dp for minimum jump energy needs a stone index, not all previous jumps, under the given rules.

Solution

Legal predecessors and the energy cost depend only on the indices/heights. The best prefix to a given index can replace any worse prefix; no extra constraint depends on the route.

Q2 · Boundary case

Heights [7]. What do all three methods return? Why must the rolling implementation check n=1 before initializing the second value?

Solution

0. There is no jump; h[1] does not exist.

Q3 · Tie

For [5,9,4,8,3,7], find the table and one optimal route.

Solution

dp=[0,4,1,5,2,6]. One optimum is 0→2→4→5, cost 1+1+4=6. Another is 0→2→3→5 (there are ties). A deterministic tie rule chooses one without changing the value.

Q4 · Safe compression

A recurrence reads dp[i−1] and dp[i−3]. Can a two-value rolling buffer implement it as written?

Solution

No; retain three recent values (or an equivalent representation justified by the recurrence). Never overwrite a value before its last use.

Section 09

Exam practice

Practice formats, not official question predictions. Write state meaning, recurrence, boundary cases, dependency order, answer and complexity before revealing model answers.

Short answers 2 marks each

A1 · Define a DP state and transition. 2 marks

Reveal model answer
A state identifies the information needed to determine a subproblem answer; a transition relates that answer to smaller states.

State 1; transition 1.

A2 · Differentiate memoization and tabulation. 2 marks

Reveal model answer
Memoization is top-down recursive evaluation with saved answers; tabulation evaluates states iteratively in an order where prerequisites are known.

One correct description each.

A3 · Why is a separate visited flag sometimes needed? 2 marks

Reveal model answer
A valid result may equal the chosen initial value. For example, zero energy is valid; using zero to mean not computed causes repeat work. Use a distinct sentinel or visited flag.

Conflict 1; remedy 1.

A4 · What is a valid dependency order for the jump recurrence? 2 marks

Reveal model answer
Increasing index, 0 to n−1, because each state reads only i−1 and i−2.

Order 1; justification 1.

A5 · State the condition for rolling space reduction. 2 marks

Reveal model answer
Only a bounded number of previous state values are needed in later transitions, and discarded values are not required for reconstruction or other queries.

Bounded live dependencies 1; limitation 1.

Medium answers 5 marks each

B1 · Trace memoized jumps on [10,30,40,20]. 5 marks

Reveal model answer
dp[0]=0, dp[1]=20, dp[2]=30, dp[3]=30. With recursive order i−1 then i−2, calls: 3,2,1,0,0(hit),1(hit). Four misses, two hits, six total calls; best route 0→1→3.

State/base 1; recurrence 1; values 2; call/hit count 1.

B2 · Fill a bottom-up table for [8,3,10,6,7]. 5 marks

Reveal model answer
dp=[0,5,2,6,5]. At 2 compare 5+7=12 and 0+2=2; at 3 compare 2+4=6 and 5+3=8; at 4 compare 6+1=7 and 2+3=5. Answer 5, path 0→2→4.

Base 1; comparisons 3; final answer 1.

B3 · Compare time and auxiliary space of four methods. 5 marks

Reveal model answer
Plain recursion O(2ⁿ) upper bound, O(n) stack. Memoization O(n) time and O(n) extra (cache + stack); table O(n) each; rolling O(n) time, O(1) extra. Counts are for constant-time transitions and fixed-size arithmetic.

Recursion 1; memo 1; tab 1; rolling 1; assumptions 1.

Lecture summary and further reading
