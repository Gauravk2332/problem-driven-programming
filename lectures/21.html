Section 01

The problem: select the best subset

Imagine you are packing field equipment into a bag with a weight limit. Every item has a weight and usefulness score. You cannot cut an item into pieces, and you have only one of each. Maximize total usefulness.

Pack your bag · capacity 7

Each item is indivisible and can be selected at most once. Try to maximize total value without exceeding capacity.

Reveal the optimum

A+D has weight 7 and value 11. B+C has weight 7 and value 9. Any other feasible subset has value at most 11. The bag need not be full, although this example's optimum fills it.

Formal objective

maximize Σvᵢxᵢ subject to Σwᵢxᵢ ≤ W; xᵢ ∈ {0,1}

Weights are positive integers; values are nonnegative integers; W is a nonnegative integer. We seek an optimal subset, not an ordering of items. Today: derive a two-dimensional state, solve using recursion/memoization/tabulation, recover items and compress space.

Section 02

Why brute force and greedy are insufficient

Each item has two choices, select or skip. There are 2ⁿ possible subsets before checking capacity. Exploring all branches by carrying weight and value incrementally costs O(2ⁿ) in the worst case (pruning may help); enumerating masks and rescanning n items costs O(n·2ⁿ).

Capacity 50. Ratio-first greedy selects A and B (weight 30, value 160), then cannot fit C. B+C exactly fits 50 and gives 220, the optimum. Highest-value-first or lightest-first also lack a general correctness guarantee. In fractional knapsack, taking two thirds of C after A+B gives 240; that is a different problem with divisible items.

Key distinction: fractional knapsack permits pieces and admits a ratio-first proof; 0/1 knapsack does not. Do not transfer that rule without proof.

Section 03

Design the state and recurrence

Lecture 20's jumping problem needed one index. Here the optimal answer depends on both the available items and remaining capacity. Define dp[i][c] = maximum value using any subset of the first i items, total weight at most c. Rows count items; columns are limits, not exact weights. To use item i, its weight must fit.

dp[0][c] = 0; dp[i][0] = 0 (positive weights)
if wᵢ > c: dp[i][c] = dp[i−1][c]
otherwise: dp[i][c] = max(dp[i−1][c], vᵢ + dp[i−1][c−wᵢ])
Answer = dp[n][W]

Every feasible subset of the first i items either excludes item i or includes it. Excluding it leaves exactly the first i−1 items with capacity c. Including it consumes wᵢ and adds vᵢ, leaving capacity c−wᵢ and only earlier items. By induction, the previous row gives optimal answers to these smaller problems. Both candidate solutions are feasible, and every optimal subset belongs to one case, so taking their maximum is correct.

With n items and W+1 capacities, there are (n+1)(W+1) states. Both dependencies refer to row i−1, so the state graph is acyclic. The same (i,c) can be reached through different earlier choices. Example: four weights all 1 and W=3 — after processing two items, taking exactly one gives the same remaining capacity 2 and two items remaining, regardless of which item was taken.

Section 04

Top-down recursion and memoization

Start with K(n,W). Without caching, repeatedly branch into K(i−1,c) and K(i−1,c−wᵢ) when feasible. Recursion ends when no items remain or capacity is zero. Use a cache keyed by both i and c; use −1 for uncomputed (all valid values ≥0), or a dictionary/visited array.

solve(i,c):
if i=0 or c=0: return 0
if cached(i,c): return cache[i][c]
ans=solve(i−1,c)
if wᵢ ≤ c: ans=max(ans,vᵢ+solve(i−1,c−wᵢ))
cache[i][c]=ans; return ans

Every non-base state expands once and does constant local work. Dense storage and initialization cost O(n(W+1)); recursion stack adds O(n). A dictionary can evaluate/store fewer states, with expected constant-time lookups. Recursion may overflow for large n.

Build row 0 first. For each item fill every capacity from 0 through W. No dependency in the same row, so any column order is valid for the full 2D table.

Trace the decisive cell

At dp[4][7], skip D → dp[3][7]=9. Take D (weight 5,value 8) → 8+dp[3][2]=8+3=11. Choose 11. At dp[4][4] D does not fit; copy dp[3][4]=5. Notice dp[4][6]=8 and need not fill all 6 units.

Section 06

Recover the selected items

Start at (i,c)=(4,7). Compare dp[4][7]=11 against dp[3][7]=9: D must be taken in this optimum. Move to (3,2). C is skipped (3=3), then B is skipped (3=3), then A is taken (3>0). Selected A+D, weight 2+5=7, value 3+8=11. Stop at row 0. When equal, skip is itself an optimal choice; other optimal selections may exist.

Backtracking inspects one item per step, O(n) additional time after building the table, plus output storage. Do not compare against a cell from the same row. If multiple choices tie, we return one valid optimal subset.

Section 07

Reduce space and understand loop direction

Before processing item i, a[c] equals dp[i−1][c]. Update c from W down to wᵢ. Both a[c] and a[c−wᵢ] still hold previous-row values because the latter index is strictly smaller. After all updates, the array represents row i. Capacities below wᵢ remain unchanged. Ascending updates can read values already updated by the same item, effectively allowing multiple copies; that belongs to another problem (Lecture 22).

Minimal counterexample

One item (w=2,v=3), W=6. Descending: 3 at capacity 6. Ascending: dp[2]=3, dp[4]=6, dp[6]=9, which illegally uses the item three times. Try the example in the lab.

MethodTimeAuxiliary spaceWhat is retained
Subset enumeration (scan n items per subset)O(n·2ⁿ)O(n) if recursive / subset storedAll candidates explored

Memoization with dense cacheO(nW) for W≥1O(n(W+1)) cache + O(n) stackComputed states; dense allocation

1D descending updateO(nW) for W≥1O(W+1)Value only

Precise bound O(n(W+1)+(W+1)) for initializing and filling dense arrays; usual O(nW) shorthand assumes n,W≥1. W is numeric capacity; input encodes it in roughly log₂(W+1) bits, so the algorithm is pseudo-polynomial, not polynomial in binary input length in general.

Positive weights are an explicit assumption. W=0 or n=0 gives zero. An oversized item is always skipped; a zero-value item is optional and our tie rule skips it. Identical items remain distinct instances. An 'exactly W' problem is different: initialize unreachable capacities to −∞, not zero. Zero-weight items require revisiting the zero-capacity base and implementation; they are excluded here.

Section 08

From recurrence to code

knapsack.py

# items = (positive weight, nonnegative value); W >= 0
def memoized(items, W):
    n = len(items)
    memo = {}
    def solve(i, c):
        if i == 0 or c == 0:
            return 0
        if (i, c) in memo:
            return memo[i, c]
        w, v = items[i-1]
        ans = solve(i-1, c)
        if w <= c:
            ans = max(ans, v + solve(i-1, c-w))
        memo[i, c] = ans
        return ans
    return solve(n, W)

def tabulated(items, W):
    dp = [[0]*(W+1) for _ in range(len(items)+1)]
    for i, (w, v) in enumerate(items, 1):
        for c in range(W+1):
            dp[i][c] = dp[i-1][c]
            if w <= c:
                dp[i][c] = max(dp[i][c], v+dp[i-1][c-w])
    return dp[-1][W]

def compressed(items, W):
    dp = [0]*(W+1)
    for w, v in items:
        for c in range(W, w-1, -1):
            dp[c] = max(dp[c], v+dp[c-w])
    return dp[W]

if __name__ == "__main__":
    items = [(2,3),(3,4),(4,5),(5,8)]
    print(memoized(items,7), tabulated(items,7), compressed(items,7))

knapsack.cpp · C++17

#include <iostream>
#include <vector>
#include <utility>
#include <algorithm>
#include <functional>
using namespace std;
using ll = long long;
using Items = vector<pair<int,ll>>;
// Positive weights, nonnegative values, W >= 0.
ll memoized(const Items& a, int W) {
    vector<vector<ll>> memo(a.size()+1, vector<ll>(W+1,-1));
    function<ll(int,int)> solve = [&](int i,int c)->ll {
        if (i==0 || c==0) return 0;
        ll& r=memo[i][c];
        if (r!=-1) return r;
        auto [w,v]=a[i-1];
        r=solve(i-1,c);
        if (w<=c) r=max(r,v+solve(i-1,c-w));
        return r;
    };
    return solve(int(a.size()),W);
}
ll tabulated(const Items& a,int W) {
    vector<vector<ll>> dp(a.size()+1,vector<ll>(W+1));
    for (int i=1;i<=int(a.size());++i) {
        auto [w,v]=a[i-1];
        for (int c=0;c<=W;++c) {
            dp[i][c]=dp[i-1][c];
            if (w<=c) dp[i][c]=max(dp[i][c],v+dp[i-1][c-w]);
        }
    }
    return dp.back()[W];
}
ll compressed(const Items& a,int W) {
    vector<ll> dp(W+1);
    for (auto [w,v]:a)
        for (int c=W;c>=w;--c)
            dp[c]=max(dp[c],v+dp[c-w]);
    return dp[W];
}
int main() {
    Items a={{2,3},{3,4},{4,5},{5,8}};
    cout<<memoized(a,7)<<" "<<tabulated(a,7)<<" "<<compressed(a,7)<<"\n";
}

KnapsackDP.java

import java.util.Arrays;
public class KnapsackDP {
    // Each row is {positive weight, nonnegative value}.
    static long solve(int i,int c,int[][] a,long[][] memo) {
        if(i==0 || c==0) return 0;
        if(memo[i][c]!=-1) return memo[i][c];
        int w=a[i-1][0], v=a[i-1][1];
        long r=solve(i-1,c,a,memo);
        if(w<=c) r=Math.max(r,v+solve(i-1,c-w,a,memo));
        return memo[i][c]=r;
    }
    static long memoized(int[][] a,int W) {
        long[][] memo=new long[a.length+1][W+1];
        for(long[] row:memo) Arrays.fill(row,-1);
        return solve(a.length,W,a,memo);
    }
    static long tabulated(int[][] a,int W) {
        long[][] dp=new long[a.length+1][W+1];
        for(int i=1;i<=a.length;i++) {
            int w=a[i-1][0],v=a[i-1][1];
            for(int c=0;c<=W;c++) {
                dp[i][c]=dp[i-1][c];
                if(w<=c) dp[i][c]=Math.max(dp[i][c],v+dp[i-1][c-w]);
            }
        }
        return dp[a.length][W];
    }
    static long compressed(int[][] a,int W) {
        long[] dp=new long[W+1];
        for(int[] x:a)
            for(int c=W;c>=x[0];c--)
                dp[c]=Math.max(dp[c],x[1]+dp[c-x[0]]);
        return dp[W];
    }
    public static void main(String[] args) {
        int[][] a={{2,3},{3,4},{4,5},{5,8}};
        System.out.println(memoized(a,7)+" "+tabulated(a,7)+" "+compressed(a,7));
    }
}

Expected output: 11 11 11. Arrays are zero-indexed, while the state i counts how many items may be used. For these programs assume integer weights ≥1, nonnegative values, W≥0, weights and capacity within signed 32-bit range (with W+1 representable), and sum of values fits signed 64-bit (C++/Java). Use modest n,W for full tables and recursion; for large n use iteration, and for large nW use the 1D version if W is manageable. Python dictionary memoization stores only requested non-base states but recursion depth still grows with n. The website displays/copies code; run it locally or adapt the input to a judge.

Choose implementation deliberately: 2D for explanation and reconstruction; 1D for memory-sensitive value-only tasks; memoization for demand-driven states and modest recursion depth.

Challenge · exact weight versus capacity

One item (3,7), W=4. At-most optimum is 7; exact-weight solution does not exist. To solve exact filling, set dp[0][0]=0 and all other capacities in row 0 to −∞, then use the same skip/take recurrence with unreachable guards.

C2 · Develop a 1D solution and explain its correctness and limitations. 10 marks

Reveal model answer
a[0..W]=0
for each (w,v):
  for c=W down to w:
   a[c]=max(a[c],v+a[c−w])

Invariant: before a capacity is updated, its entry and smaller entries still equal the previous row. Since w>0, c−w is smaller, so no repeat selection occurs. After the row every capacity is correct.
