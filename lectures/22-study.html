Chapter 04 / 13

Why direction must change

Imagine the array as a notebook. During a type's iteration, a smaller capacity is updated first. When we read it for a larger capacity, it may already include the current type. Here that is desirable. Ascending lets us build repeated copies one at a time.

for each (w,v): for c=w..W: d[c]=max(d[c],v+d[c−w])

With item (2,3), W=6, start zeros; capacity 2 gives 3, capacity 4 uses that 3 plus 3, capacity 6 uses 6 plus 3. Earlier lecture's bug is now the intended behavior.

Chapter 05 / 13

Find the smallest number of coins

Suppose a machine accepts coins 1,3,4 and needs exactly 6. You want the fewest physical coins. Choosing the largest first looks smart until you need two extra ones. Two threes do better.

To find a minimum for amount a, pretend you have already chosen one final coin. The rest is exactly a−coin. Try each possible final coin, add one to its best answer, then select the smallest.

Chapter 06 / 13

Distinguish an impossible answer from zero

Imagine coins {3,4} and target 5. Failing to make 5 does not mean it takes zero coins. Zero coins make only amount zero. Mark amounts 1,2,5 as unreachable; amounts 3 and 4 cost one coin, and 6 costs two. Infinity is a placeholder which never wins against a finite minimum.

Why does every valid smaller state have a chance to win? The last coin of any optimal solution determines one recurrence candidate. Ignore unreachable candidates, and if no candidate is finite report impossible.

Chapter 07 / 13

Count bags of coins, not arrangements

Imagine putting coins into a bag without recording when each coin entered. A bag with two ones and a two is the same bag however you inserted them. A combination is a multiset. For {1,2} and amount 4, there are three multisets: four ones, two ones and a two, or two twos.

B[0][0]=1; B[0][a>0]=0
B[i][a]=B[i−1][a]+B[i][a−cᵢ] if cᵢ≤a
otherwise B[i][a]=B[i−1][a]
1D: for coin c: for a=c..A: ways[a]+=ways[a−c]

Process one denomination at a time, increasing amount. When processing 2, we may reuse 2 from smaller amounts, but cannot recreate a combination by adding the earlier type last in a separate round. Each quantity vector is counted once.

Chapter 09 / 13

Why do the base cases and operators differ?

The objective determines the operation. Maximum uses max; minimum uses min with an impossible marker; counting uses addition over disjoint cases. For exact-amount counting the empty solution must contribute one, or no ways can ever be created. For at-most capacity profit, choosing nothing is feasible at all capacities.

Chapter 10 / 13

Read the four algorithms in code

Read each state sentence first. Compare the loops across all four functions. Unbounded and combinations have coin/item outside and rising capacity, but one maximizes and the other adds. The minimum recurrence can compare last coins; ordered counting sums last-coin choices. A minimum of two identical arrangements is unchanged, while counting both increases the answer.

repeat_dp.py

# Positive integer weights and distinct positive coins.
def unbounded(items, W):
    dp = [0]*(W+1)
    for w,v in items:
        for a in range(w,W+1):
            dp[a] = max(dp[a], v+dp[a-w])
    return dp[W]

def minimum(coins,A):
    d = [0]+[A+1]*A   # at most A coins in a finite optimum
    for a in range(1,A+1):
        for c in coins:
            if c<=a and d[a-c]!=A+1:
                d[a]=min(d[a],1+d[a-c])
    return -1 if d[A]==A+1 else d[A]

def combinations(coins,A):
    d=[1]+[0]*A
    for c in coins:
        for a in range(c,A+1):
            d[a]+=d[a-c]
    return d[A]

def ordered(coins,A):
    d=[1]+[0]*A
    for a in range(1,A+1):
        for c in coins:
            if c<=a: d[a]+=d[a-c]
    return d[A]

if __name__=="__main__":
    print(unbounded([(2,3),(3,5),(5,7)],7))
    print(minimum([1,3,4],6), combinations([1,3,4],6), ordered([1,3,4],6))

ll unbounded(const vector<pair<int,int>>& items,int W){
    vector<ll> d(W+1);
    for(auto [w,v]:items)
        for(int a=w;a<=W;++a)

    return d[W];
}
int minimum(const vector<int>& coins,int A){
    vector<int> d(A+1,A+1); d[0]=0;
    for(int a=1;a<=A;++a)
        for(int c:coins)
            if(c<=a && d[a-c]!=A+1)
                d[a]=min(d[a],1+d[a-c]);
    return d[A]==A+1?-1:d[A];
}

    vector<ll> d(A+1); d[0]=1;

        for(int a=c;a<=A;++a) d[a]+=d[a-c];

RepeatDP.java

import java.util.Arrays;
public class RepeatDP {
    static long unbounded(int[][] items,int W){
        long[] d=new long[W+1];
        for(int[] x:items)
            for(int a=x[0];a<=W;a++)
                d[a]=Math.max(d[a],x[1]+d[a-x[0]]);
        return d[W];
    }
    static int minimum(int[] coins,int A){
        int[] d=new int[A+1]; Arrays.fill(d,A+1); d[0]=0;
        for(int a=1;a<=A;a++)
            for(int c:coins)
                if(c<=a && d[a-c]!=A+1)
                    d[a]=Math.min(d[a],1+d[a-c]);
        return d[A]==A+1?-1:d[A];
    }
    static long combinations(int[] coins,int A){
        long[] d=new long[A+1]; d[0]=1;
        for(int c:coins)
            for(int a=c;a<=A;a++) d[a]+=d[a-c];
        return d[A];
    }
    static long ordered(int[] coins,int A){
        long[] d=new long[A+1]; d[0]=1;
        for(int a=1;a<=A;a++)
            for(int c:coins) if(c<=a) d[a]+=d[a-c];
        return d[A];
    }
    public static void main(String[] args){
        int[][] items={{2,3},{3,5},{5,7}};
        int[] c={1,3,4};
        System.out.println(unbounded(items,7));
        System.out.println(minimum(c,6)+" "+combinations(c,6)+" "+ordered(c,6));
    }
}

Common mistakes

Can I use zero as a denomination?

No: it fails to reduce the amount and may make counting infinite.

Can I apply modulo to minimum coin counts?

No. Modulo changes their ordering. Use it only for count problems that explicitly request it.

Positive weights and denominations are essential: capacity strictly decreases after a take. A zero-weight item with positive value would make unbounded profit infinite; a zero denomination can generate infinitely many ordered/exact-target representations when a solution exists. Reject these inputs. Duplicate denominations should be deduplicated when coin values define types. W/A=0: max profit and min coins are 0; both counts are 1 (empty selection). An empty list cannot make a positive exact target: minimum is impossible, counts zero. Unused capacity is allowed only for the at-most knapsack formulation.

Every optimum skips type i or contains at least one copy. Removing a copy leaves the same type available at capacity c−w. Positive weights make a smaller state. Fill rows in increasing i and capacity in increasing c. Compress into a[c]=max(a[c],v+a[c−w]) with c ascending; the source already contains the current type. For reconstruction compare against previous row; on take reduce capacity without decreasing i.
