Module 05 · Lecture 22

Unbounded Knapsack and Coin Change

Repeated selection · Minimum coins · Unordered combinations · Ordered sequences

Section 01

One change, several new problems

Last lecture allowed each item once. Now imagine a warehouse with unlimited copies of every product type. Choose quantities, not just a subset. With (weight,value)=(2,3),(3,5),(5,7), capacity 7, what is the most valuable load?

Think first

Try two copies of weight 2 and one weight 3. Compare against taking each type at most once.

Reveal the contrast

Unlimited: 2+2+3 weight, value 3+3+5=11. 0/1: types 1+3 weigh 7, value 10. The new legal choices change the answer and the recurrence.

Today we connect unbounded maximization, minimum exact-target coin change, and counting exact-target ways. They share dependencies but solve different questions.

Section 02

Unbounded knapsack · same-row recurrence

Define K[i][c] as maximum value using unlimited copies of the first i types at total weight at most c. Positive integer weights, nonnegative values. If skip, use previous row; if take, remove one copy and retain type i at smaller capacity.

K[0][c]=0; K[i][0]=0
if wᵢ > c: K[i][c]=K[i−1][c]
otherwise K[i][c]=max(K[i−1][c], vᵢ+K[i][c−wᵢ])

Proof by exhaustive cases: any optimum either excludes i or uses it at least once. Removing one copy leaves a feasible smaller-capacity solution of the same prefix; an optimal one is sufficient by replacement. Both candidates feasible. Positive weight ensures acyclic dependencies.

Section 03

From descending to ascending capacity

For 0/1, both predecessors are previous-row values; descend to preserve them. Unbounded take needs the already-updated same-row value; ascend. With one (2,3), W=6, ascending gives [0,0,3,3,6,6,9]. This was a bug for 0/1; now it is correct.

d[0..W]=0
for (w,v) in item types:
  for c=w..W: d[c]=max(d[c],v+d[c−w])

Invariant: after processing type i, every capacity equals K[i][c]. Before updating c, smaller capacities already include type i; the current entry still represents skip. For two separate arrays, the same-row take still requires smaller current-row answers.

Section 04

Minimum coins · exact amount

Now a coin is a denomination, not a profit. Given unlimited {1,3,4}, make exactly 6 using fewest coins. Largest-first chooses 4+1+1, but 3+3 wins. State M[a] is fewest coins forming exactly a, not a maximum under a weight limit.

M[0]=0; M[a]=∞ initially for a>0
M[a]=min over fitting c of (1+M[a−c])
Answer: M[A] if finite; otherwise −1

Every nonempty solution has a final coin. Remove it and replace the remaining multiset by an optimal one. Compare all fitting coins. Infinity means unreachable, not zero coins. Store a winning denomination to recover a solution; decrease amount until 0.

Try {3,4}, target 5: impossible. Try {3,4}, target 6: 2. Empty target uses zero coins. For positive denominations a finite solution has at most A coins, so A+1 is a safe finite sentinel when guarded.

Section 05

Count unordered coin combinations

Same coins, different question: how many distinct multisets have sum A? The order of coins is irrelevant. For {1,2}, target 4: 1111, 112, 22 (three combinations).

Define B[i][a] as count of multisets of sum a using first i distinct types. Partition by whether type i appears. The take case removes one copy, leaving same type available. The cases are disjoint, so add rather than maximize.

B[0][0]=1; B[0][a>0]=0
B[i][a]=B[i−1][a]+B[i][a−cᵢ] if cᵢ≤a
otherwise B[i][a]=B[i−1][a]
1D: for coin c: for a=c..A: ways[a]+=ways[a−c]

Coin order need not be sorted; each type must be processed once as an outer iteration. At target zero the empty multiset contributes one way.

Section 06

Count ordered sequences

When order matters, 112, 121 and 211 are different. Define S[a] as the number of sequences summing exactly to a. Partition by last coin. Each smaller sequence followed by c is unique, and every nonempty sequence has one final coin. Sum all sources.

S[0]=1
S[a]=Σ S[a−c] over c≤a
for a=1..A: for coin c≤a: ways[a]+=ways[a−c]

For {1,2}, A=4, sequences: 1111,112,121,211,22. Five versus three. The loop order is dictated by state semantics, not a syntactic trick.

For n item types and capacity W, dense unbounded table: O(nW) time and O(nW) extra space; ascending 1D: O(nW) time, O(W) extra. For m coin types and target A, the three coin algorithms take O(mA) time and O(A) extra. These shorthands assume positive dimensions; arrays include index 0 and initialization costs O(W+1) or O(A+1). Bounds count constant-time arithmetic operations (or fixed-size modular arithmetic); numeric capacities/targets make them pseudo-polynomial. Exact counting integers may grow beyond machine word size.

Positive weights and denominations are essential: capacity strictly decreases after a take. A zero-weight item with positive value would make unbounded profit infinite; a zero denomination can generate infinitely many ordered/exact-target representations when a solution exists. Reject these inputs. Duplicate denominations should be deduplicated when coin values define types. W/A=0: max profit and min coins are 0; both counts are 1 (empty selection). An empty list cannot make a positive exact target: minimum is impossible, counts zero. Unused capacity is allowed only for the at-most knapsack formulation.

Section 08

From recurrence to code

repeat_dp.py

# Positive integer weights and distinct positive coins.
def unbounded(items, W):
    dp = [0]*(W+1)
    for w,v in items:
        for a in range(w,W+1):
            dp[a] = max(dp[a], v+dp[a-w])
    return dp[W]

def minimum(coins,A):
    d = [0]+[A+1]*A   # at most A coins in a finite optimum
    for a in range(1,A+1):
        for c in coins:
            if c<=a and d[a-c]!=A+1:
                d[a]=min(d[a],1+d[a-c])
    return -1 if d[A]==A+1 else d[A]

def combinations(coins,A):
    d=[1]+[0]*A
    for c in coins:
        for a in range(c,A+1):
            d[a]+=d[a-c]
    return d[A]

def ordered(coins,A):
    d=[1]+[0]*A
    for a in range(1,A+1):
        for c in coins:
            if c<=a: d[a]+=d[a-c]
    return d[A]

if __name__=="__main__":
    print(unbounded([(2,3),(3,5),(5,7)],7))
    print(minimum([1,3,4],6), combinations([1,3,4],6), ordered([1,3,4],6))

ll unbounded(const vector<pair<int,int>>& items,int W){
    vector<ll> d(W+1);
    for(auto [w,v]:items)
        for(int a=w;a<=W;++a)
            d[a]=max(d[a],v+d[a-w]);
    return d[W];
}
int minimum(const vector<int>& coins,int A){
    vector<int> d(A+1,A+1); d[0]=0;
    for(int a=1;a<=A;++a)
        for(int c:coins)
            if(c<=a && d[a-c]!=A+1)
                d[a]=min(d[a],1+d[a-c]);
    return d[A]==A+1?-1:d[A];
}
ll combinations(const vector<int>& coins,int A){
    vector<ll> d(A+1); d[0]=1;
    for(int c:coins)
        for(int a=c;a<=A;++a) d[a]+=d[a-c];
    return d[A];
}
ll ordered(const vector<int>& coins,int A){
    vector<ll> d(A+1); d[0]=1;
    for(int a=1;a<=A;++a)
        for(int c:coins) if(c<=a) d[a]+=d[a-c];
    return d[A];
}

}

RepeatDP.java

import java.util.Arrays;
public class RepeatDP {
    static long unbounded(int[][] items,int W){
        long[] d=new long[W+1];
        for(int[] x:items)
            for(int a=x[0];a<=W;a++)
                d[a]=Math.max(d[a],x[1]+d[a-x[0]]);
        return d[W];
    }
    static int minimum(int[] coins,int A){
        int[] d=new int[A+1]; Arrays.fill(d,A+1); d[0]=0;
        for(int a=1;a<=A;a++)
            for(int c:coins)
                if(c<=a && d[a-c]!=A+1)
                    d[a]=Math.min(d[a],1+d[a-c]);
        return d[A]==A+1?-1:d[A];
    }
    static long combinations(int[] coins,int A){
        long[] d=new long[A+1]; d[0]=1;
        for(int c:coins)
            for(int a=c;a<=A;a++) d[a]+=d[a-c];
        return d[A];
    }
    static long ordered(int[] coins,int A){
        long[] d=new long[A+1]; d[0]=1;
        for(int a=1;a<=A;a++)
            for(int c:coins) if(c<=a) d[a]+=d[a-c];
        return d[A];
    }
    public static void main(String[] args){
        int[][] items={{2,3},{3,5},{5,7}};
        int[] c={1,3,4};
        System.out.println(unbounded(items,7));
        System.out.println(minimum(c,6)+" "+combinations(c,6)+" "+ordered(c,6));
    }
}

Expected output: 11, then 2 4 9 on the next line. Assumptions: positive integer weights/coins, nonnegative integer values, distinct coin denominations, nonnegative capacity/target with A+1 and W+1 representable as int. For C++/Java assume all intermediate counts and values fit signed 64-bit. For count problems requiring modulo M, apply it at every addition using sufficiently wide arithmetic. Do not apply modulo to minimum or maximum costs. Python integers are exact but arithmetic cost grows with bit length. The site displays/copies code; run locally or adapt judge input.

C1 · Derive and optimize unbounded knapsack. 10 marks

Reveal model answer
K[0][c]=0; K[i][0]=0
if wᵢ > c: K[i][c]=K[i−1][c]
otherwise K[i][c]=max(K[i−1][c], vᵢ+K[i][c−wᵢ])

Every optimum skips type i or contains at least one copy. Removing a copy leaves the same type available at capacity c−w. Positive weights make a smaller state. Fill rows in increasing i and capacity in increasing c. Compress into a[c]=max(a[c],v+a[c−w]) with c ascending; the source already contains the current type. For reconstruction compare against previous row; on take reduce capacity without decreasing i.

Section 10

Summary and academic references

Repeated selection means same-row dependencies. Maximize at-most profit with zero bases, minimize exact coin count with infinity, or count exact-target solutions with the empty object as one. Distinguish multisets from sequences before deciding loop order.
