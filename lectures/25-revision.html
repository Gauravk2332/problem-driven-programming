Problem Driven Programming · R1UC544B
Lecture 25

Definition and state

Unit-cost Levenshtein: minimum insertions, deletions and replacements to convert A into B. Match costs 0. D[i][j] = distance of first i source characters to first j target characters.

D[i][0]=i; D[0][j]=j
c=0 if A[i−1]=B[j−1], else 1
D[i][j]=min(above+1,
left+1, diagonal+c)
Answer D[m][n]

Final alignment column is delete (above), insert (left), or pair (diagonal). Removing it gives a smaller optimal prefix. Fill row-major.

Worked example

horse → ros

∅ros
∅0123
h1123
o2212
r3222
s4332
e5443

Distance 3. horse → rorse → rose → ros. Match o and s for free.

Reconstruction

Start at (m,n). Choose neighbour whose cost plus its operation equals current cost. Diagonal pairs, above deletes, left inserts. Reach (0,0), reverse alignment. Execute using cursor; delete does not advance, others advance. Ties allowed.

Rolling rows

prev[j]=j
for i=1..m: cur[0]=i
for j=1..n:
cur[j]=min(prev[j]+1,
cur[j−1]+1,prev[j−1]+c)
swap(prev,cur)
return prev[n]

Choose shorter string as columns for symmetric unit costs. Distance only; full reconstruction needs history.

Complexity

Recursion O(3^(m+n)) upper, O(m+n) stack. Memo/table O(mn) time/space for positive lengths, memo adds stack. Rolling O(mn) time, O(min(m,n)) extra. Include +1 dimensions for empty strings. Backtracking O(m+n) steps.

Common mistakes

  • Index i−1, not i, for final prefix character.
  • Initialize both borders.
  • Match costs zero; diagonal mismatch costs one.
  • Do not allow transposition as one edit.
  • Hamming only equal lengths; insert/delete distance = m+n−2LCS, not general Levenshtein.

Exam: state, bases, recurrence/proof, order, trace, result, complexity.

Top-down vs bottom-up

Top-down: cache keyed by (i, j); recursion depth up to m + n. Bottom-up: fill row by row, left to right; two rows suffice for the distance.
