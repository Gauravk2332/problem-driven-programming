Problem-solving routine

Read objective, legal choices, constraints and output. Generate a tiny example. Choose state/greedy rule and prove it. Estimate time/space. Implement, trace, compare tests, submit.

Capstone: weighted scheduling

Inclusive days, maximize reward; earlier end < current start. Sort by finish. p(i) = number of earlier compatible jobs.

dp[0]=0
dp[i]=max(dp[i−1],w[i]+dp[p(i)])
p = lower_bound(earlier ends,start)
answer dp[n]

Skip or take exhausts all choices. Sort O(n log n), each search O(log n), O(n) storage. Follow p when take, i−1 when skip. Reverse witness.

Pattern recall

  • Static range sums: prefix sums.
  • Pair target: hashing / two pointers.
  • Unweighted intervals: earliest finish.
  • 0/1 DP: previous row, descend.
  • Unlimited: same row, ascend; count variants distinguish order.
  • Subset Sum: OR, exact reachability.
  • LIS: endpoint / lower_bound tails.
  • Edit Distance: two prefixes.
  • Partition DP: shorter intervals first.
  • Mask: used subset; digit: tight prefix.

Constraints and practical implementation

At n=200000, n²≈4×10¹⁰; n log₂n≈3.52×10⁶. Counts are not timings. Check memory, language and judge. Reward sums up to 2×10¹⁴: use 64-bit. Buffered token input, newline output, no prompts; avoid unnecessary flushes. I/O cannot repair wrong complexity.

Testing and debugging

WA: objective, bases, ties, boundaries, overflow. TLE: complexity, then constants. MLE: cells/bytes, stack. RE: bounds, allocation, recursion. Stress tiny cases against an independent brute oracle; save seed and failing input. Tests are not proof.

Inclusive endpoint trap: [1,2,5] and [2,3,6] → 6, not 11.

Full-marks answer

State, base, recurrence/choice, proof, order, trace, final answer and time/space. If requested, witness. For contest submissions also verify types, input and exact output.
