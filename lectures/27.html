Section 02

Select an algorithm from constraints

Extract objective, legal decisions, input range, time/memory limits and required output. Compare worst-case complexity before coding. A large n is a clue to avoid quadratic/exponential work, not a proof that any O(n log n) solution will pass.

Section 04

Capstone: derive weighted interval DP

Sort by nondecreasing end day.
p(i) = number of earlier jobs with end < start[i].
dp[0]=0
dp[i]=max(dp[i−1], reward[i]+dp[p(i)])
Answer dp[n]

Every optimum for the first i jobs either excludes job i or includes it. If excluded, the best reward is dp[i−1]. If included, all other jobs must finish strictly before its start: they form a subset of the compatible prefix of length p(i). Conversely any optimal compatible-prefix schedule can append job i. Both cases are feasible and exhaust the choices. Sorting makes compatible ends a prefix; binary search finds its length, not an arbitrary compatible job. Positive-length or same-day closed intervals use end < start; for half-open intervals use end ≤ start instead. Save p(i) and trace backwards: skip on equality with dp[i−1], otherwise take i and jump to p(i). Empty schedule is legal.

Without search, scanning backwards for p(i) costs O(n²). Since ends are sorted, binary search for the first end ≥ start among earlier jobs. Its zero-based index equals the number of compatible earlier jobs. Store dp indexed by prefix length.

Section 06

From recurrence to a submission

Top-down and bottom-up

Weighted interval scheduling can also be written either way.

Top-down (memoization)Bottom-up (tabulation)
Starts fromAll jobs: best(n)No jobs: dp[0] = 0
Stored byA memo keyed by prefix length iAn array dp[0…n], filled in increasing i
How it runsRecursion. A state is solved the first time it is asked for, then read from the cacheLoops. Every state is filled once, after the states it depends on
Which statesOnly the states the final answer actually needsUsually every state in the table
Extra costA call stack as deep as the longest chain of calls; very deep inputs can overflow itNo recursion; the table can often be shrunk to one or two rows
Choose it whenThe fill order is awkward, or many states are never neededThe fill order is clear and most states are needed; this is the safer default for large inputs

With n = 200,000 the top-down recursion would be 200,000 calls deep, which overflows the default stack in most languages. That is why the judge-ready program below is bottom-up; top-down is still a good way to check the recurrence on small inputs.

Python · projects_two_ways.py

from bisect import bisect_left


def prepare(jobs):
    # Sort by end day; p[i] = how many earlier jobs end strictly before job i starts
    jobs = sorted(jobs, key=lambda job: job[1])
    ends = [end for _, end, _ in jobs]
    p = [bisect_left(ends, start, 0, i) for i, (start, _, _) in enumerate(jobs)]
    return jobs, p


def best_top_down(jobs):
    # Top-down: best(i) = most reward using only the first i jobs
    jobs, p = prepare(jobs)
    memo = {0: 0}

    def best(i):
        if i not in memo:
            reward = jobs[i - 1][2]
            memo[i] = max(best(i - 1), reward + best(p[i - 1]))
        return memo[i]

    return best(len(jobs))


def best_bottom_up(jobs):
    # Bottom-up: fill dp[0], dp[1], ..., dp[n] in increasing order
    jobs, p = prepare(jobs)
    dp = [0] * (len(jobs) + 1)
    for i in range(1, len(jobs) + 1):
        dp[i] = max(dp[i - 1], jobs[i - 1][2] + dp[p[i - 1]])
    return dp[-1]


jobs = [(1, 2, 2), (3, 4, 2), (1, 4, 10), (5, 6, 3)]  # (start, end, reward), inclusive days
print(best_top_down(jobs), best_bottom_up(jobs))       # 13 13
print(best_top_down([(1, 2, 5), (2, 3, 6)]), best_bottom_up([(1, 2, 5), (2, 3, 6)]))  # 6 6

#include <algorithm>
#include <array>
#include <iostream>
#include <vector>
using namespace std;

using Job = array<long long, 3>;  // start, end, reward (inclusive days)
vector<Job> jobs;
vector<int> p;                    // p[i] = earlier jobs that end before job i starts
vector<long long> memo;           // -1 means "not computed yet"

void prepare(vector<Job> input) {
    sort(input.begin(), input.end(), [](const Job& x, const Job& y) { return x[1] < y[1]; });
    jobs = input;
    vector<long long> ends;
    for (auto& job : jobs) ends.push_back(job[1]);
    p.assign(jobs.size(), 0);
    for (int i = 0; i < (int)jobs.size(); i++)
        p[i] = lower_bound(ends.begin(), ends.begin() + i, jobs[i][0]) - ends.begin();
}

// Top-down: best(i) = most reward using only the first i jobs
long long best(int i) {
    if (i == 0) return 0;
    if (memo[i] != -1) return memo[i];
    return memo[i] = max(best(i - 1), jobs[i - 1][2] + best(p[i - 1]));
}

long long bestTopDown(const vector<Job>& input) {
    prepare(input);
    memo.assign(jobs.size() + 1, -1);
    return best(jobs.size());
}

// Bottom-up: fill dp[0], dp[1], ..., dp[n] in increasing order
long long bestBottomUp(const vector<Job>& input) {
    prepare(input);
    vector<long long> dp(jobs.size() + 1, 0);
    for (int i = 1; i <= (int)jobs.size(); i++)
        dp[i] = max(dp[i - 1], jobs[i - 1][2] + dp[p[i - 1]]);
    return dp[jobs.size()];
}

int main() {
    vector<Job> demo = {{1, 2, 2}, {3, 4, 2}, {1, 4, 10}, {5, 6, 3}};
    cout << bestTopDown(demo) << " " << bestBottomUp(demo) << "\n";  // 13 13
    vector<Job> overlap = {{1, 2, 5}, {2, 3, 6}};
    cout << bestTopDown(overlap) << " " << bestBottomUp(overlap) << "\n";  // 6 6
}

Java · ProjectsTwoWays.java

import java.util.Arrays;

public class ProjectsTwoWays {
    static long[][] jobs;  // each job: {start, end, reward}, inclusive days
    static int[] p;        // p[i] = earlier jobs that end before job i starts
    static long[] memo;    // -1 means "not computed yet"

    static void prepare(long[][] input) {
        jobs = input.clone();
        Arrays.sort(jobs, (x, y) -> Long.compare(x[1], y[1]));
        p = new int[jobs.length];
        for (int i = 0; i < jobs.length; i++) {
            int lo = 0, hi = i;  // first earlier index whose end >= start
            while (lo < hi) {
                int mid = (lo + hi) / 2;
                if (jobs[mid][1] < jobs[i][0]) lo = mid + 1; else hi = mid;
            }
            p[i] = lo;
        }
    }

    // Top-down: best(i) = most reward using only the first i jobs
    static long best(int i) {
        if (i == 0) return 0;
        if (memo[i] != -1) return memo[i];
        return memo[i] = Math.max(best(i - 1), jobs[i - 1][2] + best(p[i - 1]));
    }

    static long bestTopDown(long[][] input) {
        prepare(input);
        memo = new long[jobs.length + 1];
        Arrays.fill(memo, -1);
        return best(jobs.length);
    }

    // Bottom-up: fill dp[0], dp[1], ..., dp[n] in increasing order
    static long bestBottomUp(long[][] input) {
        prepare(input);
        long[] dp = new long[jobs.length + 1];
        for (int i = 1; i <= jobs.length; i++)
            dp[i] = Math.max(dp[i - 1], jobs[i - 1][2] + dp[p[i - 1]]);
        return dp[jobs.length];
    }

    public static void main(String[] args) {
        long[][] demo = {{1, 2, 2}, {3, 4, 2}, {1, 4, 10}, {5, 6, 3}};
        System.out.println(bestTopDown(demo) + " " + bestBottomUp(demo));  // 13 13
        long[][] overlap = {{1, 2, 5}, {2, 3, 6}};
        System.out.println(bestTopDown(overlap) + " " + bestBottomUp(overlap));  // 6 6
    }
}

Both functions give 13 for the four projects and 6 when the two jobs overlap on day 2.

Python · projects.py

# Input: n, followed by n triples (start, end, reward).
# Inclusive days, compatible iff previous end < next start.
import sys
from bisect import bisect_left

def solve(jobs):
    jobs = sorted(jobs, key=lambda x: x[1])
    ends = [e for s,e,w in jobs]
    dp = [0]*(len(jobs)+1)
    for i,(s,e,w) in enumerate(jobs):
        p = bisect_left(ends,s,0,i)
        dp[i+1] = max(dp[i],w+dp[p])
    return dp[-1]

def main():
    data = list(map(int,sys.stdin.buffer.read().split()))
    if not data: return
    n = data[0]
    jobs = [tuple(data[k:k+3]) for k in range(1,1+3*n,3)]
    print(solve(jobs))

if __name__ == "__main__":
    main()

Assumes valid nonnegative integral input, n fits int, start ≤ end, total rewards fit signed 64-bit, and allocation is feasible. Java scanner accepts nonnegative integers. Python reads all tokens (O(n) storage). Sort/search: O(n log n) for n≥2, O(n) auxiliary storage including arrays and sorting. Python/C++/Java return value only; lab also reconstructs jobs. Rename Java class to Main if required by judge. Website displays and copies code; runs occur locally or on a judge.

Read whitespace-separated tokens; avoid interactive prompts and confusing sample input with test-case count. In C++, disable iostream synchronization and untie cin before any I/O; don't mix C stdio with unsynchronized C++ streams. Use '\n' rather than flushing each line. Java: buffered byte/token reads; build large output with StringBuilder. Python: sys.stdin.buffer.read().split() is convenient but allocates all tokens; use buffered readline for very large input. Faster I/O reduces constants, not asymptotic algorithm cost. 200,000 rewards up to 10⁹ may sum to 2×10¹⁴, beyond signed 32-bit. In fixed-width languages widen before multiplying. Respect contest rules about allowed code and references.

Section 07

Debug systematically

Wrong Answer: confirm specification, indexing, base cases, compatible endpoints, duplicate values, ties, zero/empty cases, sentinel arithmetic and overflow. Time Limit Exceeded: bound work from worst-case constraints, remove repeated searches or unnecessary states, then profile I/O. Memory Limit Exceeded: count cells × bytes plus object/stack overhead; use rolling arrays only if dependencies permit. Runtime Error: check bounds, recursion depth, allocation and valid input handling. Output only the required answer; trace to stderr locally, disable expensive diagnostics for submissions.

Example: [1,2,5] and [2,3,6] must not be scheduled together; output 6. If 11 appears, the likely bug is the compatibility comparison. Solve a minimal failing case before changing code.

Section 08

Validate with an independent oracle

Brute force enumerates all subsets and rejects pairs that overlap, O(n²2ⁿ) worst case. That is impractical for large n but useful for tiny tests. Use reproducible seeds, retain the failure, minimize it, and rerun after repair. A test cannot replace the induction proof.
