Chapter 01 / 12

Start with a problem

Algorithm A takes 100n steps; algorithm B takes n² steps. Which is faster?

Think first

Try n = 10, n = 100 and n = 1000. Is there one answer for every n?

It depends on n — until it doesn’t
For n = 10, B is faster (100 vs 1000). At n = 100 they tie. From n = 101 onwards A is faster, and the gap keeps widening: at n = 10⁶, A needs 10⁸ steps and B 10¹².

For large inputs, what matters is how fast the cost grows, not the constant 100. Asymptotic analysis compares algorithms by their growth rate as n → ∞, ignoring constant factors and small inputs. This is why a Θ(n) algorithm beats a Θ(n²) one for all sufficiently large n, whatever the constants.

Chapter 03 / 12

Big-O: an upper bound

Definition. f(n) = O(g(n)) if there exist positive constants c and n₀ such that

0 ≤ f(n) ≤ c · g(n)   for all n ≥ n₀

Read it as: “beyond some point, f never exceeds a constant multiple of g”. The pair (c, n₀) is a witness. To prove a Big-O claim you exhibit a witness; to disprove it you show no witness can exist.

Example: 3n² + 5n + 2 = O(n²)

Witness 1: c = 10, n₀ = 1. For n ≥ 1, 5n ≤ 5n² and 2 ≤ 2n², so 3n² + 5n + 2 ≤ 10n².

Witness 2: c = 4, n₀ = 6. We need 5n + 2 ≤ n², true for n ≥ 6 (36 ≥ 32) and onwards; at n = 5 it fails (102 > 100).

Both witnesses prove the same claim. Witnesses are not unique.

Non-example: n² ≠ O(n)

Suppose n² ≤ c·n for all n ≥ n₀. Dividing by n gives n ≤ c for all large n, which is impossible because n grows without bound. No witness exists.

Which pair is a valid witness for 2n + 3 = O(n)?

Chapter 04 / 12

Explore: find a witness

Enter f(n) = p·n² + q·n + r as three coefficients, a constant c and a starting point n₀. The lab checks f(n) ≤ c·n² for each n and tells you whether your witness works.

Think first

Keep c = 4 and try n₀ = 3. Then try c = 2. What goes wrong in each case?

What you should see
With n₀ = 3 the rows n = 3, 4, 5 fail, so (4, 3) is not a witness. With c = 2 < 3 it fails for every large n: no n₀ can rescue a c below the leading coefficient.

Chapter 05 / 12

Omega and Theta

NotationDefinition (for all n ≥ n₀)Meaning
f = O(g)f(n) ≤ c·g(n)f grows no faster than g (upper bound)
f = Ω(g)f(n) ≥ c·g(n)f grows at least as fast as g (lower bound)
f = Θ(g)c₁·g(n) ≤ f(n) ≤ c₂·g(n)same growth rate (tight bound)

f = Θ(g) exactly when f = O(g) and f = Ω(g). For 3n² + 5n + 2: it is ≥ 3n² for n ≥ 1 (Ω with c = 3) and ≤ 4n² for n ≥ 6 (O with c = 4), so it is Θ(n²) with c₁ = 3, c₂ = 4, n₀ = 6.

Important: O, Ω and Θ describe functions, not cases. “The worst case of insertion sort is Θ(n²)” and “the best case is Θ(n)” are both precise statements. Saying “insertion sort is O(n²)” is true (it never exceeds that) but “insertion sort is Θ(n²)” without naming the case is false, because sorted inputs take only Θ(n).

Little-o and little-omega (optional)

f = o(g) means f grows strictly slower: f(n)/g(n) → 0. For example n = o(n²) but n² ≠ o(n²). Little-ω is the strict lower bound.

Chapter 06 / 12

Rules that save you from proofs

  • Constants: c·f = Θ(f) for any constant c > 0.
  • Sum rule: f + g = Θ(max(f, g)). Keep the dominant term: n³ + 1000n² = Θ(n³).
  • Product rule: O(f)·O(g) = O(f·g). A loop of n iterations doing O(log n) work is O(n log n).
  • Polynomials: a polynomial of degree k with positive leading coefficient is Θ(nᵏ).
  • Logarithm bases: log_a n = log_b n / log_b a, so all log bases differ by a constant: just write log n.
  • Transitivity: f = O(g) and g = O(h) imply f = O(h).

Chapter 07 / 12

Comparing functions with limits

When the rules are not enough, compute L = lim (n → ∞) f(n)/g(n):

Limit LConclusion
0f = O(g) but not Θ (f grows slower)
a constant 0 < L < ∞f = Θ(g)
∞f = Ω(g) but not Θ (f grows faster)

Example: n³ versus 2ⁿ. The ratio n³/2ⁿ → 0 (exponentials beat polynomials; apply L’Hôpital three times), so n³ = O(2ⁿ). Concretely 2ⁿ overtakes n³ for good at n = 10 (1024 > 1000); for n = 2 … 9 the cube is larger.

Chapter 08 / 12

Checking growth numerically

The program prints the growth table, finds the smallest n₀ for c = 4, and the two crossover points. Numerical checks like this are evidence, not proofs; use them to find or test a witness, then prove it algebraically.

Python · growth.py

"""Lecture 3: growth rates and checking a Big-O witness (c, n0)."""
import math

print(f"{'n':>4} {'log2 n':>7} {'n log2 n':>9} {'n^2':>6} {'n^3':>7} {'2^n':>22}")
for n in [1, 2, 4, 8, 16, 32, 64]:
    print(f"{n:>4} {math.log2(n):>7.0f} {n * math.log2(n):>9.0f} {n * n:>6} {n ** 3:>7} {2 ** n:>22}")


def f(n):
    return 3 * n * n + 5 * n + 2


def holds(c, n0, limit=10000):
    """Check f(n) <= c*n^2 for n0 <= n <= limit."""
    return all(f(n) <= c * n * n for n in range(n0, limit + 1))


smallest = next(n for n in range(1, 100) if holds(4, n))
print(f"f(n) = 3n^2+5n+2 <= 4n^2 holds for all n >= {smallest}; fails at n = {smallest - 1}: {f(smallest - 1)} > {4 * (smallest - 1) ** 2}")
print("first n with n^2 > 100n:", next(n for n in range(1, 1000) if n * n > 100 * n))
print("first n >= 2 with 2^n > n^3:", next(n for n in range(2, 100) if 2 ** n > n ** 3))

C++ · growth.cpp

// Lecture 3: growth rates and checking a Big-O witness (c, n0).
#include <cmath>
#include <cstdio>
#include <string>
using namespace std;

long long f(long long n) { return 3 * n * n + 5 * n + 2; }

bool holds(long long c, long long n0, long long limit = 10000) {   // f(n) <= c n^2 on [n0, limit]
    for (long long n = n0; n <= limit; n++) if (f(n) > c * n * n) return false;
    return true;
}

string pow2(int n) {                      // exact 2^n for n <= 64, as a decimal string
    unsigned __int128 v = 1; v <<= n;
    string s;
    while (v > 0) { s = char('0' + (int)(v % 10)) + s; v /= 10; }
    return s;
}

int main() {
    printf("%4s %7s %9s %6s %7s %22s\n", "n", "log2 n", "n log2 n", "n^2", "n^3", "2^n");
    for (int n : {1, 2, 4, 8, 16, 32, 64}) {
        double lg = log2((double)n);
        printf("%4d %7.0f %9.0f %6d %7lld %22s\n", n, lg, n * lg, n * n, (long long)n * n * n, pow2(n).c_str());
    }
    int smallest = 1;
    while (!holds(4, smallest)) smallest++;
    long long m = smallest - 1;
    printf("f(n) = 3n^2+5n+2 <= 4n^2 holds for all n >= %d; fails at n = %lld: %lld > %lld\n", smallest, m, f(m), 4 * m * m);
    int n = 1; while (!((long long)n * n > 100LL * n)) n++;
    printf("first n with n^2 > 100n: %d\n", n);
    n = 2; while (!(pow(2.0, n) > (double)n * n * n)) n++;
    printf("first n >= 2 with 2^n > n^3: %d\n", n);
}

Java · Growth.java

// Lecture 3: growth rates and checking a Big-O witness (c, n0).
import java.math.BigInteger;

public class Growth {
    static long f(long n) { return 3 * n * n + 5 * n + 2; }

    static boolean holds(long c, long n0, long limit) {   // f(n) <= c n^2 on [n0, limit]
        for (long n = n0; n <= limit; n++) if (f(n) > c * n * n) return false;
        return true;
    }

    public static void main(String[] args) {
        System.out.printf("%4s %7s %9s %6s %7s %22s%n", "n", "log2 n", "n log2 n", "n^2", "n^3", "2^n");
        for (int n : new int[]{1, 2, 4, 8, 16, 32, 64}) {
            double lg = Math.log(n) / Math.log(2);
            System.out.printf("%4d %7.0f %9.0f %6d %7d %22s%n", n, lg, n * lg, n * n, (long) n * n * n, BigInteger.TWO.pow(n));
        }
        int smallest = 1;
        while (!holds(4, smallest, 10000)) smallest++;
        long m = smallest - 1;
        System.out.printf("f(n) = 3n^2+5n+2 <= 4n^2 holds for all n >= %d; fails at n = %d: %d > %d%n", smallest, m, f(m), 4 * m * m);
        int n = 1; while (!((long) n * n > 100L * n)) n++;
        System.out.println("first n with n^2 > 100n: " + n);
        n = 2; while (!(Math.pow(2, n) > (double) n * n * n)) n++;
        System.out.println("first n >= 2 with 2^n > n^3: " + n);
    }
}

Chapter 09 / 12

Common confusions

ConfusionCorrection
“Big-O means worst case.”Big-O is an upper bound on a function. Any case (best, worst, average) can be bounded with O, Ω or Θ.
“O(n²) means it takes n² steps.”It means at most c·n² for large n; 5n is also O(n²).
“A smaller Big-O is always faster.”Only for large enough n: 100n beats n² only from n = 101.
“f = O(g) means g = O(f).”No: n = O(n²) but n² ≠ O(n).
“log₂ n and log₁₀ n are different classes.”They differ by a constant factor, so Θ(log n) covers both.

Practise

  1. Basic. Prove 7n − 2 = Θ(n) with explicit c₁, c₂, n₀.
  2. Core. Arrange in increasing order of growth: n², 2ⁿ, n log n, log n, n!, √n, 100.
    Answer
    100, log n, √n, n log n, n², 2ⁿ, n!.
  3. Core. Is n³ = O(n² log n)? Use a limit.
    Answer
    n³ / (n² log n) = n / log n → ∞, so no.
  4. Challenge. Prove that log(n!) = Θ(n log n).
    Hint
    Upper: n! ≤ nⁿ. Lower: the largest n/2 factors are each ≥ n/2, so n! ≥ (n/2)^(n/2).

Examination practice and revision

For full marks: state the definition with quantifiers (there exist c, n₀; for all n ≥ n₀), give explicit witnesses with the algebra that justifies them, and keep notation (bound) separate from case (input).

Exam-style practice, not a prediction of the examination paper. Write your answer before revealing the model answer.

Short answers 2 marks each

A1 · Define Big-O notation. 2 marks

Reveal model answer
f(n) = O(g(n)) if there exist constants c > 0 and n₀ ≥ 1 such that 0 ≤ f(n) ≤ c·g(n) for all n ≥ n₀.

Constants 1; inequality for n ≥ n₀ 1.

A2 · Define Θ notation. 2 marks

Reveal model answer
f = Θ(g) if there exist c₁, c₂ > 0 and n₀ with c₁g(n) ≤ f(n) ≤ c₂g(n) for all n ≥ n₀.

Both bounds 1; quantifiers 1.

A3 · Show 2n + 3 = O(n). 2 marks

Reveal model answer
2n + 3 ≤ 3n for n ≥ 3, so c = 3, n₀ = 3 (or 2n + 3 ≤ 5n for n ≥ 1).

Witness 1; justification 1.

A4 · Arrange: n log n, 2ⁿ, log n, n². 2 marks

Reveal model answer
log n < n log n < n² < 2ⁿ.

Correct order 2.

A5 · Is n² = O(n)? Justify. 2 marks

Reveal model answer
No. n² ≤ cn would require n ≤ c for all large n, impossible.

Answer 1; reason 1.

Medium answers 5 marks each

B1 · Prove 3n² + 5n + 2 = Θ(n²) with explicit constants. 5 marks

Reveal model answer
Lower: f ≥ 3n² for n ≥ 1. Upper: 5n + 2 ≤ n² for n ≥ 6, so f ≤ 4n². Hence c₁ = 3, c₂ = 4, n₀ = 6.

Lower bound 2; upper bound with algebra 2; conclusion 1.

B2 · Explain O, Ω and Θ with a graph and one example each. 5 marks

Reveal model answer
Graph: f between c₁g and c₂g beyond n₀. O: upper envelope; Ω: lower; Θ: both. Examples: 5n = O(n²), n² = Ω(n), 3n² + 5n + 2 = Θ(n²).

Definitions 3; examples 2.

B3 · Using limits, compare (i) n³ and 2ⁿ, (ii) n log n and n^1.5. 5 marks

Reveal model answer
(i) n³/2ⁿ → 0 ⇒ n³ = O(2ⁿ), not Θ. (ii) (n log n)/n^1.5 = log n/√n → 0 ⇒ n log n = O(n^1.5).

Rule 1; (i) 2; (ii) 2.

Long answers 10 marks each

C1 · Define O, Ω and Θ; state and justify the sum, product and polynomial rules; and use them to find Θ of the running time of a nested loop of n × n iterations followed by a loop of n log n work. 10 marks

Reveal model answer
Definitions with quantifiers. Sum rule from max(f, g) ≤ f + g ≤ 2max(f, g). Product rule by multiplying the inequalities. Polynomial: divide by nᵏ, terms vanish. Running time n² + n log n = Θ(n²).

Definitions 3; rule justifications 4; application 3.

C2 · Explain why asymptotic analysis ignores constants and small n, with a numerical example, and discuss when constants do matter in practice. 10 marks

Reveal model answer
100n vs n²: crossover at n = 101; for n = 10⁶, 10⁸ vs 10¹² steps. Growth rate determines scalability. Constants matter for small inputs, for algorithms in the same class (e.g. quicksort vs heap sort), and with memory/caching effects; hybrid algorithms switch to insertion sort for small arrays.
