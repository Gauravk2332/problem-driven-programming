Problem Driven Programming · R1UC544B
Lecture 5

Divide and conquer

DAndC(P): if small → solve; divide into a parts of size n/b; combine

T(n) = aT(n/b) + D(n) + C(n). Needs independent subproblems.

Binary search (sorted A)

mid = lo + (hi − lo)/2; discard half each step. T(n) = T(n/2) + 1 = Θ(log n); ≤ ⌊log₂ n⌋ + 1 iterations (10⁶ → 20). [3,9,10,27,38,43,82]: 43 in 2 steps, 5 absent after 3.

Merge sort

Split, sort halves, merge (take smaller front; ties from left ⇒ stable). [38,27,43,3,9,82,10] → sorted with 13 comparisons. T = 2T(n/2) + n = Θ(n log n) always; Θ(n) extra space.

Greedy (Lectures 12–18)

Best-looking choice, never undone. ₹289 → 8 pieces (optimal). {1,3,4}, 6: greedy 3 coins, optimum 2.

Dynamic programming (19–27)

Overlapping subproblems + optimal substructure; store answers. fib(20): naive 21,891 calls, memoised 39 (2n − 1).

Common mistakes · full marks

  • Binary search needs sorted input.
  • (lo + hi)/2 can overflow.
  • Recursion ≠ efficient D&C.

Full marks: method, recurrence + solution, trace, conditions for correctness.

Two-mark self-test

  1. What is the divide-and-conquer strategy?
    Divide the problem into smaller independent instances of the same problem, solve them recursively, and combine their solutions.
  2. Write the recurrence of binary search and its solution.
    T(n) = T(n/2) + c, T(1) = c ⇒ Θ(log n).
  3. Is merge sort stable? Why?
    Yes: when two front elements are equal the merge takes the left one first, preserving order.
  4. Name one problem each for greedy and dynamic programming.
    Greedy: activity selection / fractional knapsack. DP: 0/1 knapsack / LCS.
  5. Why is naive recursive Fibonacci slow?
    Its subproblems overlap; the same values are recomputed exponentially many times (21,891 calls for n = 20).
