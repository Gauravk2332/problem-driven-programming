Chapter 01 / 13

Start with a problem

A class register lists 1,000 names in alphabetical order. You want to find “Meera”.

Think first

Reading from the top could take 1,000 looks. Can you guarantee far fewer? How many?

Halve the problem
Open the middle. If Meera comes later alphabetically, ignore the first half; otherwise ignore the second. Each look halves what remains: 1000 → 500 → 250 → … → 1. At most 10 looks, because 2¹⁰ = 1024 ≥ 1000.

Halving the problem is an instance of a design strategy: a general idea that works for many problems. This lecture covers divide and conquer in detail and introduces the two strategies that fill the second half of the course, greedy (Lectures 12–18) and dynamic programming (Lectures 19–27).

Chapter 02 / 13

Divide and conquer

Divide and conquer solves a problem in three steps:

  1. Divide the instance into smaller instances of the same problem.
  2. Conquer them recursively; very small instances are solved directly.
  3. Combine the sub-answers into an answer for the original.
DAndC(P):
  if P is small: return Solve(P)
  divide P into P₁, …, P_a, each of size n/b
  return Combine(DAndC(P₁), …, DAndC(P_a))

Its cost is the recurrence from Lecture 4: T(n) = a·T(n/b) + D(n) + C(n), where D and C are the divide and combine costs. The subproblems must be independent: no subproblem is shared between branches. When they overlap, dynamic programming is the better tool.

Chapter 03 / 13

Binary search

Binary search finds a key in a sorted array. It is divide and conquer with a = 1 (only one half is searched) and a trivial combine step.

lo ← 0; hi ← n − 1
while lo ≤ hi:
  mid ← lo + (hi − lo) div 2
  if A[mid] = key: return mid
  if A[mid] < key: lo ← mid + 1 else hi ← mid − 1
return −1

In [3, 9, 10, 27, 38, 43, 82], searching 43 looks at index 3 (27, too small), then index 5 (43): found in 2 steps. Searching 5 looks at 27, 9, 3 and stops after 3 steps with lo > hi.

  • Recurrence T(n) = T(n/2) + 1 ⇒ Θ(log n); at most ⌊log₂ n⌋ + 1 iterations.
  • Writing mid = lo + (hi − lo)/2 avoids the integer overflow of (lo + hi)/2 for large indices.
  • Precondition: the array is sorted. On unsorted data the answer is meaningless.

Chapter 04 / 13

Explore: merge sort

Merge sort splits the array in half, sorts each half recursively and merges the two sorted halves. Step through the splits and merges and watch the comparison count.

Think first

How many comparisons do you expect for an array that is already sorted? Try 1 2 3 4 5 6 7 8.

What happens
Sorted input still takes n log₂ n / 2 = 12 comparisons for n = 8: merge sort does not get much faster on sorted data, unlike insertion sort. Its worst case, though, is far better than insertion sort’s.

  • Recurrence: T(n) = 2T(n/2) + Θ(n) ⇒ Θ(n log n) in every case (Lecture 4, case 2).
  • Space: Θ(n) auxiliary for the temporary arrays, plus Θ(log n) stack.
  • Stable: equal keys keep their relative order, because ties take from the left.

Chapter 06 / 13

First look: the greedy method

A greedy algorithm builds a solution one choice at a time, always taking the choice that looks best now, and never undoing it. To pay ₹289 with Indian denominations, take the largest note that fits: 100 + 100 + 50 + 20 + 10 + 5 + 2 + 2 = 8 pieces, which is optimal.

Greedy is fast (usually a sort plus one pass) but it is only correct when the problem has the greedy-choice property. With coins {1, 3, 4} and amount 6, largest-first gives 4 + 1 + 1 (3 coins) but 3 + 3 uses 2. Lectures 12–18 show how to prove a greedy rule or break it.

Chapter 07 / 13

First look: dynamic programming

Naive recursive Fibonacci, fib(n) = fib(n − 1) + fib(n − 2), splits into two subproblems, but they overlap: fib(n − 2) is computed again inside fib(n − 1). The program in Chapter 9 counts the calls for n = 20:

MethodCalls for fib(20)Growth
Naive recursion21,891Θ(φⁿ), exponential
Memoised (store each answer)39Θ(n)

Dynamic programming solves each distinct subproblem once and stores the answer, either top-down (memoisation) or bottom-up (tabulation). It applies when a problem has overlapping subproblems and optimal substructure. Lecture 19 starts this properly.

Why is divide and conquer a poor choice for naive Fibonacci?

A useful order of questions: can the input be split into independent parts? (divide and conquer). Is there a provably safe choice? (greedy). Do the same subproblems recur? (dynamic programming). If none fits and the input is small, brute force or backtracking.

The strategies in code

Python · strategies.py

"""Lecture 5: divide and conquer (merge sort) and why DP stores answers."""
comparisons = 0


def merge_sort(a):
    global comparisons
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left, right = merge_sort(a[:mid]), merge_sort(a[mid:])
    out, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        comparisons += 1
        if left[i] <= right[j]:
            out.append(left[i]); i += 1
        else:
            out.append(right[j]); j += 1
    return out + left[i:] + right[j:]


def binary_search(a, key):
    lo, hi, steps = 0, len(a) - 1, 0
    while lo <= hi:
        steps += 1
        mid = (lo + hi) // 2
        if a[mid] == key:
            return mid, steps
        if a[mid] < key:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1, steps


calls = 0


def fib_naive(n):
    global calls
    calls += 1
    return n if n < 2 else fib_naive(n - 1) + fib_naive(n - 2)


def fib_memo(n, memo):
    global calls
    calls += 1
    if n < 2:
        return n
    if n not in memo:
        memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]


data = [38, 27, 43, 3, 9, 82, 10]
s = merge_sort(data)
print("merge sort", data, "->", s, f"({comparisons} comparisons)")
print("binary search 43 ->", binary_search(s, 43))
print("binary search 5  ->", binary_search(s, 5))
calls = 0; v = fib_naive(20); print(f"fib(20) = {v}, naive calls = {calls}")
calls = 0; v = fib_memo(20, {}); print(f"fib(20) = {v}, memoised calls = {calls}")

C++ · strategies.cpp

// Lecture 5: divide and conquer (merge sort) and why DP stores answers.
#include <cstdio>
#include <string>
#include <unordered_map>
#include <utility>
#include <vector>
using namespace std;

long long comparisons = 0, calls = 0;

vector<int> mergeSort(const vector<int>& a) {
    if (a.size() <= 1) return a;
    size_t mid = a.size() / 2;
    vector<int> left = mergeSort(vector<int>(a.begin(), a.begin() + mid));
    vector<int> right = mergeSort(vector<int>(a.begin() + mid, a.end()));
    vector<int> out;
    size_t i = 0, j = 0;
    while (i < left.size() && j < right.size()) {
        comparisons++;
        if (left[i] <= right[j]) out.push_back(left[i++]); else out.push_back(right[j++]);
    }
    while (i < left.size()) out.push_back(left[i++]);
    while (j < right.size()) out.push_back(right[j++]);
    return out;
}

pair<int, int> binarySearch(const vector<int>& a, int key) {
    int lo = 0, hi = (int)a.size() - 1, steps = 0;
    while (lo <= hi) {
        steps++;
        int mid = lo + (hi - lo) / 2;
        if (a[mid] == key) return {mid, steps};
        if (a[mid] < key) lo = mid + 1; else hi = mid - 1;
    }
    return {-1, steps};
}

long long fibNaive(int n) { calls++; return n < 2 ? n : fibNaive(n - 1) + fibNaive(n - 2); }

long long fibMemo(int n, unordered_map<int, long long>& memo) {
    calls++;
    if (n < 2) return n;
    if (!memo.count(n)) memo[n] = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
    return memo[n];
}

string show(const vector<int>& a) {
    string s = "[";
    for (size_t i = 0; i < a.size(); i++) s += (i ? ", " : "") + to_string(a[i]);
    return s + "]";
}

int main() {
    vector<int> data = {38, 27, 43, 3, 9, 82, 10};
    vector<int> s = mergeSort(data);
    printf("merge sort %s -> %s (%lld comparisons)\n", show(data).c_str(), show(s).c_str(), comparisons);
    auto r = binarySearch(s, 43); printf("binary search 43 -> (%d, %d)\n", r.first, r.second);
    r = binarySearch(s, 5);       printf("binary search 5  -> (%d, %d)\n", r.first, r.second);
    calls = 0; long long v = fibNaive(20); printf("fib(20) = %lld, naive calls = %lld\n", v, calls);
    unordered_map<int, long long> memo;
    calls = 0; v = fibMemo(20, memo); printf("fib(20) = %lld, memoised calls = %lld\n", v, calls);
}

Java · Strategies.java

// Lecture 5: divide and conquer (merge sort) and why DP stores answers.
import java.util.Arrays;
import java.util.HashMap;
import java.util.Map;

public class Strategies {
    static long comparisons = 0, calls = 0;

    static int[] mergeSort(int[] a) {
        if (a.length <= 1) return a;
        int mid = a.length / 2;
        int[] left = mergeSort(Arrays.copyOfRange(a, 0, mid));
        int[] right = mergeSort(Arrays.copyOfRange(a, mid, a.length));
        int[] out = new int[a.length];
        int i = 0, j = 0, k = 0;
        while (i < left.length && j < right.length) {
            comparisons++;
            out[k++] = left[i] <= right[j] ? left[i++] : right[j++];
        }
        while (i < left.length) out[k++] = left[i++];
        while (j < right.length) out[k++] = right[j++];
        return out;
    }

    static int[] binarySearch(int[] a, int key) {
        int lo = 0, hi = a.length - 1, steps = 0;
        while (lo <= hi) {
            steps++;
            int mid = lo + (hi - lo) / 2;
            if (a[mid] == key) return new int[]{mid, steps};
            if (a[mid] < key) lo = mid + 1; else hi = mid - 1;
        }
        return new int[]{-1, steps};
    }

    static long fibNaive(int n) { calls++; return n < 2 ? n : fibNaive(n - 1) + fibNaive(n - 2); }

    static long fibMemo(int n, Map<Integer, Long> memo) {
        calls++;
        if (n < 2) return n;
        if (!memo.containsKey(n)) memo.put(n, fibMemo(n - 1, memo) + fibMemo(n - 2, memo));
        return memo.get(n);
    }

    public static void main(String[] args) {
        int[] data = {38, 27, 43, 3, 9, 82, 10};
        int[] s = mergeSort(data);
        System.out.println("merge sort " + Arrays.toString(data) + " -> " + Arrays.toString(s) + " (" + comparisons + " comparisons)");
        int[] r = binarySearch(s, 43); System.out.println("binary search 43 -> (" + r[0] + ", " + r[1] + ")");
        r = binarySearch(s, 5);        System.out.println("binary search 5  -> (" + r[0] + ", " + r[1] + ")");
        calls = 0; long v = fibNaive(20); System.out.println("fib(20) = " + v + ", naive calls = " + calls);
        calls = 0; v = fibMemo(20, new HashMap<>()); System.out.println("fib(20) = " + v + ", memoised calls = " + calls);
    }
}

Output (identical in all three languages):

merge sort [38, 27, 43, 3, 9, 82, 10] -> [3, 9, 10, 27, 38, 43, 82] (13 comparisons)
binary search 43 -> (5, 2)
binary search 5  -> (-1, 3)
fib(20) = 6765, naive calls = 21891
fib(20) = 6765, memoised calls = 39

Merge sort Θ(n log n) time, Θ(n) space. Binary search Θ(log n). Naive Fibonacci exponential; memoised Θ(n) time and space. Copy and run it locally; this website shows code but does not execute it.

  • The memoised calls for fib(n) are 2n − 1: each fib(k) with k ≥ 2 is expanded once and makes two calls.

Common confusions

ConfusionCorrection
“Recursion means divide and conquer.”D&C needs independent subproblems and a combine step; naive Fibonacci is recursive but not efficient D&C.
“Binary search works on any array.”Only on sorted data (or a monotone condition).
“Greedy is always faster, so prefer it.”Faster but possibly wrong; prove the greedy choice first.
“DP is just recursion.”DP stores subproblem answers so each is computed once.
“Merge sort is in place.”The standard version needs Θ(n) extra memory.
