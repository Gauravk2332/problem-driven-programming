Chapter 01 / 13

Start with a problem

A hall floor measures 252 cm × 105 cm. You want to tile it with identical square tiles, as large as possible, with no cutting.

Think first

The tile side must divide both 252 and 105. How would you find the largest such side without listing all divisors?

The greatest common divisor
The side is gcd(252, 105) = 21 cm: 12 tiles by 5 tiles. Euclid’s method finds it in three divisions: 252 = 2 × 105 + 42, 105 = 2 × 42 + 21, 42 = 2 × 21 + 0.

The greatest common divisor (GCD, also called HCF) appears everywhere: simplifying fractions, lowest common multiples, modular inverses (Lecture 8), cryptography. This lecture computes it efficiently.

Chapter 02 / 13

GCD, LCM and the slow ways

gcd(a, b) is the largest positive integer dividing both a and b; by convention gcd(a, 0) = a. lcm(a, b) is the smallest positive integer divisible by both. For positive a, b:

gcd(a, b) × lcm(a, b) = a × b
MethodIdeaCost
Check downwardtry d = min(a, b), min − 1, … until d divides bothup to min(a, b) divisions
Prime factorisation252 = 2²·3²·7, 105 = 3·5·7 ⇒ gcd = 3·7 = 21factorising is slow for large numbers
Euclidreplace (a, b) by (b, a mod b)O(log min(a, b)) divisions

From the factorisations, lcm(252, 105) = 2²·3²·5·7 = 1260, and 21 × 1260 = 26,460 = 252 × 105.

Chapter 03 / 13

Why Euclid works

Lemma: gcd(a, b) = gcd(b, a mod b) for b > 0

Write a = qb + r with r = a mod b. If d divides a and b, it divides a − qb = r; so every common divisor of (a, b) is a common divisor of (b, r). Conversely, if d divides b and r, it divides qb + r = a. The two pairs have exactly the same common divisors, hence the same greatest one.

gcd(a, b):
  while b ≠ 0:
    (a, b) ← (b, a mod b)
  return a

Termination: the second number strictly decreases (0 ≤ a mod b < b) and stays non-negative, so it reaches 0. Then gcd(a, 0) = a. The recursive form is one line: gcd(a, b) = a if b = 0, else gcd(b, a mod b).

If a < b the first step just swaps them: gcd(46, 240) → gcd(240, 46).

Consecutive Fibonacci numbers are the worst case
89 and 55 need 9 divisions (every quotient is 1); 100 and 55 need only 4. Small quotients mean slow shrinking, and consecutive Fibonacci numbers give quotient 1 at every step.

Chapter 06 / 13

How fast is it?

The remainder at least halves every two steps

Consider (a, b) with a ≥ b. If b ≤ a/2 then a mod b < b ≤ a/2. If b > a/2 then a mod b = a − b < a/2. Either way, after two steps the first number is below half its value.

So the number of divisions is at most about 2 log₂ min(a, b): O(log min(a, b)), i.e. linear in the number of digits. Lamé’s theorem sharpens this: the worst inputs are consecutive Fibonacci numbers, and the number of steps is at most about 5 times the number of decimal digits of the smaller number.

Chapter 07 / 13

Extended Euclid and Bézout’s identity

Bézout’s identity: for any a, b not both 0 there are integers x, y with a·x + b·y = gcd(a, b). The extended algorithm finds them by working the divisions backwards.

Back substitution for 240 and 46

From the trace: 2 = 6 − 1·4, 4 = 10 − 1·6, 6 = 46 − 4·10, 10 = 240 − 5·46.

2 = 6 − (10 − 6) = 2·6 − 10 = 2·(46 − 4·10) − 10 = 2·46 − 9·10 = 2·46 − 9·(240 − 5·46) = 240·(−9) + 46·47. Check: −2160 + 2162 = 2.

extGcd(a, b):
  if b = 0: return (a, 1, 0)
  (g, x₁, y₁) ← extGcd(b, a mod b)
  return (g, y₁, x₁ − (a div b)·y₁)
  • Modular inverse: if gcd(a, m) = 1 then a·x ≡ 1 (mod m): x is the inverse of a mod m (Lecture 8).
  • Linear Diophantine equations: ax + by = c has integer solutions exactly when gcd(a, b) divides c.

Chapter 08 / 13

LCM, many numbers and edge cases

  • LCM without overflow: compute lcm(a, b) = a / gcd(a, b) × b, dividing first; a × b / gcd may overflow even when the LCM fits.
  • Many numbers: gcd(a, b, c) = gcd(gcd(a, b), c); likewise for LCM.
  • Zero: gcd(a, 0) = a; gcd(0, 0) is undefined (every integer divides 0).
  • Negatives: use absolute values; the GCD is positive by definition.
  • Fractions: 252/105 reduces to 12/5 by dividing both by 21.

Chapter 09 / 13

Euclid in code

The program prints the division steps for (252, 105), runs extended Euclid on (240, 46), and compares the number of divisions for a Fibonacci pair and a non-Fibonacci pair.

Python · euclid.py

"""Lecture 7: Euclidean algorithm, extended Euclid, LCM."""


def gcd_steps(a, b):
    steps = []
    while b:
        steps.append(f"{a} = {a // b} x {b} + {a % b}")
        a, b = b, a % b
    return a, steps


def gcd(a, b):
    return a if b == 0 else gcd(b, a % b)


def ext_gcd(a, b):
    """Returns (g, x, y) with a*x + b*y = g = gcd(a, b)."""
    if b == 0:
        return a, 1, 0
    g, x1, y1 = ext_gcd(b, a % b)
    return g, y1, x1 - (a // b) * y1


def lcm(a, b):
    return a // gcd(a, b) * b


g, steps = gcd_steps(252, 105)
for s in steps:
    print(s)
print("gcd(252, 105) =", g)
g, x, y = ext_gcd(240, 46)
print(f"ext_gcd(240, 46): g = {g}, x = {x}, y = {y}, check {240 * x + 46 * y}")
print("lcm(12, 18) =", lcm(12, 18), "| gcd(0, 7) =", gcd(0, 7))
print("divisions for gcd(89, 55):", len(gcd_steps(89, 55)[1]), "| for gcd(100, 55):", len(gcd_steps(100, 55)[1]))

C++ · euclid.cpp

// Lecture 7: Euclidean algorithm, extended Euclid, LCM.
#include <cstdio>
#include <string>
#include <tuple>
#include <vector>
using namespace std;

long long gcdSteps(long long a, long long b, vector<string>& steps) {
    while (b) {
        steps.push_back(to_string(a) + " = " + to_string(a / b) + " x " + to_string(b) + " + " + to_string(a % b));
        long long r = a % b; a = b; b = r;
    }
    return a;
}

long long gcd(long long a, long long b) { return b == 0 ? a : gcd(b, a % b); }

// Returns (g, x, y) with a*x + b*y = g = gcd(a, b).
tuple<long long, long long, long long> extGcd(long long a, long long b) {
    if (b == 0) return {a, 1, 0};
    auto [g, x1, y1] = extGcd(b, a % b);
    return {g, y1, x1 - (a / b) * y1};
}

long long lcm(long long a, long long b) { return a / gcd(a, b) * b; }   // divide first: avoids overflow

int main() {
    vector<string> steps;
    long long g = gcdSteps(252, 105, steps);
    for (auto& s : steps) printf("%s\n", s.c_str());
    printf("gcd(252, 105) = %lld\n", g);
    auto [g2, x, y] = extGcd(240, 46);
    printf("ext_gcd(240, 46): g = %lld, x = %lld, y = %lld, check %lld\n", g2, x, y, 240 * x + 46 * y);
    printf("lcm(12, 18) = %lld | gcd(0, 7) = %lld\n", lcm(12, 18), gcd(0, 7));
    vector<string> s1, s2;
    gcdSteps(89, 55, s1); gcdSteps(100, 55, s2);
    printf("divisions for gcd(89, 55): %zu | for gcd(100, 55): %zu\n", s1.size(), s2.size());
}

Java · Euclid.java

// Lecture 7: Euclidean algorithm, extended Euclid, LCM.
import java.util.ArrayList;
import java.util.List;

public class Euclid {
    static long gcdSteps(long a, long b, List<String> steps) {
        while (b != 0) {
            steps.add(a + " = " + (a / b) + " x " + b + " + " + (a % b));
            long r = a % b; a = b; b = r;
        }
        return a;
    }

    static long gcd(long a, long b) { return b == 0 ? a : gcd(b, a % b); }

    // Returns {g, x, y} with a*x + b*y = g = gcd(a, b).
    static long[] extGcd(long a, long b) {
        if (b == 0) return new long[]{a, 1, 0};
        long[] r = extGcd(b, a % b);
        return new long[]{r[0], r[2], r[1] - (a / b) * r[2]};
    }

    static long lcm(long a, long b) { return a / gcd(a, b) * b; }   // divide first: avoids overflow

    public static void main(String[] args) {
        List<String> steps = new ArrayList<>();
        long g = gcdSteps(252, 105, steps);
        steps.forEach(System.out::println);
        System.out.println("gcd(252, 105) = " + g);
        long[] e = extGcd(240, 46);
        System.out.println("ext_gcd(240, 46): g = " + e[0] + ", x = " + e[1] + ", y = " + e[2] + ", check " + (240 * e[1] + 46 * e[2]));
        System.out.println("lcm(12, 18) = " + lcm(12, 18) + " | gcd(0, 7) = " + gcd(0, 7));
        List<String> s1 = new ArrayList<>(), s2 = new ArrayList<>();
        gcdSteps(89, 55, s1); gcdSteps(100, 55, s2);
        System.out.println("divisions for gcd(89, 55): " + s1.size() + " | for gcd(100, 55): " + s2.size());
    }
}

Common confusions

ConfusionCorrection
“GCD needs prime factorisation.”Euclid never factorises and is far faster.
“The answer is the last remainder.”It is the last non-zero remainder (the divisor when the remainder becomes 0).
“Euclid needs a ≥ b.”If a < b, the first step swaps them automatically.
“lcm = a × b / gcd is always safe.”a × b can overflow; divide first.
“Bézout coefficients are unique.”If (x, y) works, so does (x + kb/g, y − ka/g).
