Congruence

a ≡ b (mod m) ⇔ m | (a − b). a mod m ∈ [0, m). −7 mod 3 = 2; C++/Java −7 % 3 = −1 → ((a % m) + m) % m.

Rules

(a+b) mod m · (a−b+m) mod m · (a·b) mod m — reduce every step

Division only via inverse. m = 10⁹+7: products need 64 bits.

Binary exponentiation

r=1; while e>0: if e odd: r=r·b; b=b·b; e/=2 (all mod m)

Θ(log e). 3¹³ mod 7: bases 3,2,4,2; r 3,3,5,3 ⇒ 3. 3²⁰⁰ mod 13 = 9; 2^(10¹⁸) mod p = 719,476,260.

Fermat (p prime, p ∤ a)

a^(p−1) ≡ 1 ⇒ a⁻¹ ≡ a^(p−2). Shrink exponents mod p − 1.

Common mistakes · full marks

  • Negative % in C++/Java.
  • Reduce after each operation.
  • Fermat needs a prime modulus.

Full marks: rules, algorithm + trace, Θ(log e), inverse with condition and check.

Two-mark self-test

  1. Define a ≡ b (mod m).
    m divides a − b; equivalently a and b leave the same remainder when divided by m.
  2. Compute (−7) mod 3 and explain the C++ result.
    2 (since −7 = −3·3 + 2). C++ gives −1 because % keeps the sign of the dividend; fix with ((a % m) + m) % m.
  3. State Fermat’s little theorem.
    If p is prime and p ∤ a, then a^(p−1) ≡ 1 (mod p).
  4. When does a modular inverse exist?
    a has an inverse modulo m iff gcd(a, m) = 1.
  5. Complexity of binary exponentiation?
    Θ(log e) modular multiplications.
